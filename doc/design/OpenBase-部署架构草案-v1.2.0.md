## 1. 部署拓扑（Dev）

```
用户浏览器
    │ https
    ▼
nginx（统一前端静态资源 /ui + 反向代理）
    ├── /ui/*         → dist 静态资源（版本目录 v1.2.0）
    └── /api/*        → openbase 后端（uvicorn :8000）
                            │ 代理
                            ├── OpenLLM / OpenRAG / OpenMemory / DPS（Dev 实例）
                            │
                            └── PostgreSQL(192.168.0.151:5432 openbase schema)
                                 Redis(192.168.0.151:6380)
```

| 项 | 设计 |
|----|------|
| 前端 | Vite build → dist（静态资源），nginx 托管 /ui，版本目录 `ui-v1.2.0` |
| 后端 | 沿用 v1.1.0 部署（uvicorn + 共享基础设施 PG/Redis），本版本仅增量 API（ai-apps/proxy） |
| 域名/路径 | 同域部署（/api 反代），规避跨域与 Cookie 问题 |
| 四系统 | Dev 实例地址在 config 模块路由表配置（system→base_url） |

## 2. 环境划分

| 环境 | 前端 | 后端 | 四系统 | 说明 |
|------|------|------|--------|------|
| Dev | dist 当前版本 | Dev 库 | Dev 实例 | 联调验证（本版本目标） |
| Test | 同 Dev | Test 库 | Test 实例 | Step 4 测试 |
| Pro | 灰度 10%→50%→100% | Pro 库 | Pro 实例 | 后续版本推进 |

## 3. 发布流程

| 步骤 | 内容 |
|------|------|
| 1 | 质量门禁：Lint 0 + 测试 100% + 覆盖率 ≥80% |
| 2 | 构建：vite build --mode dev，产物入版本目录 |
| 3 | 部署：nginx 指向新版本目录 + 缓存刷新 |
| 4 | 联调验收：登录/模块挂载/核心操作/响应式三端/错误契约（对齐上线检查清单） |
| 5 | 契约校验：openapi.json diff 0 缺口 |

## 4. 上线检查清单（草案）

| # | 检查项 | 通过标准 |
|---|--------|---------|
| 1 | 登录 | admin/admin123 登录成功，错误密码 401 |
| 2 | 模块挂载 | 4 模块菜单可见，路由可达 |
| 3 | 核心操作 | 对话查询/知识库检索/记忆列表/画像列表 0 阻塞 |
| 4 | 响应式 | 1440/1024/375 三端无横向溢出 |
| 5 | 错误契约 | 触发错误返回 ErrorResponse 统一格式 |
| 6 | 代理 | 四系统代理端点连通（health） |
| 7 | SSE | 对话流式正常 |
| 8 | 性能 | 首屏 <3s |

## 5. 回滚方案

| 项 | 设计 |
|----|------|
| 前端 | 保留上一版本 dist 目录（ui-v1.1.x 占位），nginx 切换回退 <1min |
| 后端增量 | ai-apps/proxy 表可安全 drop；代理配置回退 git revert |
| 四系统 | 无侵入（只读代理），无回滚风险 |
