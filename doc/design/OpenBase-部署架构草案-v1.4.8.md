## 1. 部署定位

本版本（v1.4.8）**本仓 OpenBase 不实施任何 OpenLLM 侧代码改动**（VC-014）；本仓仅产出 BL-148-08 文档整合与 BL-148-07 报告框架。因此 **OpenBase 仓的部署面零代码部署改动**，仅涉及文档与报告框架的存放（属仓库内文件，随既有发布流程）。

OpenLLM 与 openbase-ui 仓的部署由其各自发布流程独立管控（派选 §8.2；接收仓独立评审/提交/发布）。

---

## 2. 部署矩阵

| 环境 | OpenBase（本仓） | OpenLLM（主体施工） | openbase-ui（配合） |
|------|:----------------:|:-------------------:|:-------------------:|
| Dev | 文档/报告框架随仓库 | 工装/收敛/接线（按段独立提交） | 会话标识提交 |
| Test | 回归验证 | 集成/两路径一致性/F-08 回归 | 接口配合验证 |
| Pro | 无代码改动（VC-014） | 按段验收后发布 | 随前端发版 |

**本仓在 Pro 环境无新增部署构件**（无新服务 / 无新端口 / 无新配置项）。

---

## 3. 端口 / 配置 / 依赖（本仓）

| 项 | 结论 |
|----|------|
| 端口 | 无新增（本仓无新服务） |
| 配置 | 无新增配置项（会话标识/回写等均在 OpenLLM 仓） |
| 依赖 | 无新增第三方依赖（派选：不新增依赖） |
| 回滚 | 本仓无代码改动，无回滚面；OpenLLM 侧按段提交，必要时按段回退（第零段开关默认关闭的思路同样用于裁剪回退） |

---

## 4. 数据/存储部署

* `routing_trace` 计量表 / `WritebackStore` / `ConversationMessage`：属 OpenLLM 仓数据面，部署在 OpenLLM 侧；迁移幂等（`create_all` / `WHERE NOT EXISTS`）。
* 既有 `backend/data/writeback.db`（26 行/8 会话）保留 + 迁移说明（不做破坏性删除）。
