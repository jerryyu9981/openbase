## 1. 安全设计范围

本版本**无新增权限面**（会话编排为既有能力的修正与接线，不新增权限码；需求 §7）。安全设计重点为**数据脱敏红线**、**输入校验**、**审计留痕**与**跨仓契约安全**。

---

## 2. 敏感数据脱敏（红线）

### 2.1 禁令

* **禁止**记录：令牌（`Bearer <token>`）、密码、密钥（`sk-*`、`AKIA*`）、完整请求体、个人隐私（AGENTS.md §3；需求 §7）。
* 计量回执字段（`routing_trace`）、回写回执（`WritebackStore`）**不得含**敏感内容（AC-148-01-5）。

### 2.2 脱敏机制

* 自由文本 / 回执内容必须经 `core/mask.py` 处理，覆盖模式：`Bearer <token>` / `sk-*` / `AKIA*` / `key=value` / `authorization:` 等（项目记忆 Hard Constraint）。
* `session_id` 字段**不携带凭据类信息**（需求 §7；API §2.1）。
* 跨仓契约沿用 v1.4.6 四仓契约口径，**禁记敏感字段**（需求 §7；AC-148-01-5）。

### 2.3 验收断言

| 判定 | 方法 |
|------|------|
| 计量与回执字段不含令牌/密码/密钥/完整请求体 | 证据（红线断言扫描 `mask` 覆盖；AC-148-01-5） |
| 第零段工装无裁剪/改写/截断逻辑 | 静态审查 0 命中（AC-148-01-3） |

---

## 3. 输入校验

* `OpenLLMChatRequest.session_id`（可选）做**类型与长度校验**（字符串、合理长度上限），防超长/畸形输入；拒绝则 400 `PARAM_400`（AGENTS.md §2；错误码规范）。
* 计量/回写字段写入前经 schema 约束（Pydantic），杜绝注入类载荷。
* 沿用既有输入校验（`ComponentUnavailableError` 降级语义，不因校验引入新错误面）。

---

## 4. 审计与留痕

| 项 | 设计 |
|----|------|
| 回写留痕 | `WritebackStore.status`（accepted/duplicated/failed）+ `seq` + 被丢弃项标识，可查可核对（AC-148-05-2） |
| 计量留痕 | `routing_trace` 计量回执按 `request_id` + `session_id` 批量导出（AC-148-01-1） |
| 降级留痕 | 组件不可用/回写失败降级路径留 degraded 标记，不静默（非功能） |
| 日志 | 结构化日志（logging + extra），禁 print；不含敏感字段（AGENTS.md §3） |

## 5. 威胁面快速核对

| 威胁 | 缓解 | 状态 |
|------|------|:----:|
| 计量/回执记录泄露凭据 | `mask` 脱敏 + 字段白名单 | ✅ 已覆盖 |
| 回写幂等键被 user 顶替致数据串扰 | AC-148-06-1 强制真实会话标识 | ✅ 已覆盖 |
| 会话标识注入畸形输入 | Pydantic 校验 + `PARAM_400` | ✅ 已覆盖 |
| 回写通道失败影响主链路（加入类 DoS） | 异步队列 + 退避 ≤3 次隔离（AC-148-05-3） | ✅ 已覆盖 |
| 前端提交会话标识越权访问他会话 | 会话标识缺省按用户；访问控制沿用既有鉴权口径（本版对接口层配合，越权治理归既有认证面） | ✅ 既有能力 |
