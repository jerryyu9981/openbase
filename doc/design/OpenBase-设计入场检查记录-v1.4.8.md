## 3. 设计轨道选择确认

依据项目实际与 `design-stage-execution` 矩阵，确认本版本设计轨道及适用性：

| 设计轨道 | 是否覆盖 | 适用范围 / 理由 |
|----------|:--------:|------------------|
| 系统架构设计 | ✅ | 会话编排前置与回写闭环整体架构、模块归属、跨仓边界 |
| Agent 架构设计 | ⛔ **不适用** | 本版本无新增 Agent 角色 / 工具 / 工作流；编排层已存在（`edgerouter/orchestration/`），本次仅接线与修正 |
| 前端架构设计 | ⛔ **部分适用（接口层）** | 仅 openbase-ui 发消息提交会话标识（接口层配合），**无界面交互改造**；详见 API 接口设计文档 §4.8 |
| UI/UX 与原型 | ⛔ **不适用** | 需求文档 §8 声明「不含前端会话界面交互设计」；无界面新增/改造 |
| API 接口设计 | ✅ | `OpenLLMChatRequest` 新增会话标识字段；回写回执查询契约 |
| 数据模型 / 数据库设计 | ✅ | `routing_trace` 计量表扩展（或独立表）；回写幂等键改会话维度 + 迁移 |
| 缓存与消息设计 | ✅（并入架构） | 回写异步队列与退避机制沿用；语义缓存语义补齐（流式路径） |
| 安全设计 | ✅ | 计量/回执字段脱敏红线；无新权限码；跨仓契约敏感字段禁写 |
| 性能与容量设计 | ✅（并入非功能） | 回写不阻塞主链路；第零段不改输出；两路径行为一致 |
| 可观测性设计 | ✅ | `routing_trace` 计量回执 + 回写回执可查可导出 |
| 部署与环境设计 | ✅ | 本仓无代码改动（VC-014）；跨仓部署边界在派单；报告框架为本仓 |
| 设计评审 | ✅ | 本记录 + 《设计评审记录-v1.4.8》 |
| 需求架构对比审计 | ✅ | 《需求架构对比审计-v1.4.8》 + 阶段审计 Stage2 |

**不适用轨道说明**：Agent 架构、UI/UX 与原型（含前端架构界面层、Figma、设计系统）本版均不适用，理由已在上表声明，将在《设计评审记录-v1.4.8》再次记录，不构成设计缺口。
