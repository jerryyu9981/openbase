## 1. 性能设计

| 指标 | 设计 | 判定方式 | 追溯 |
|------|------|----------|:----:|
| 回写对主链路时延影响 = 0 | 回写走**异步队列 + 指数退避 ≤3**，不阻塞请求；同步/流式两路径均异步派发 | 两路径各跑一次会话对比时延 | G1 / AC-148-05-3 |
| 第零段不改变对话输出 | 工装仅观测，无裁剪/改写；计量埋点零语义干预 | 同一输入第零段前/后对比 | G5 / AC-148-01-2 |
| 归因 A 零额外模型调用 | n-gram/关键词引用检测随调用计算 | 每次调用成本核验 | AC-148-01-4 |
| 历史窗口不超窗 | `get_context_window` 按 max_tokens 截取 | 集成断言 | AC-148-04-3 |
| 两路径一致 | 共用步骤单实现 | 集成对比 | AC-148-03-1 |

### 1.1 性能量化目标（v1.1.0 新增，Step 4 性能批次前置）

**背景与必要性**：需求 §5 对性能仅给出定性要求（「回写对主链路时延影响 = 0」「第零段不改变对话输出」），**无数值门禁**；而 `TT-v1.4.8-038` 的通过标准写明「P99 < **目标值**（目标值须在执行前确定）」→ 该目标值缺失即性能批次**不可执行、不可判定**。本节补齐可执行、可验证的量化目标，作为 `TT-038`/`TT-039` 的通过标准。

**边界声明**：本节**不新增产品需求**，仅将需求 §5 的定性项**操作化**；数值取自本仓既有基线先例（《非功能设计说明-v1.4.3/v1.4.4/v1.4.5/v1.4.6》、《系统架构设计文档-v1.3.0》代理透传额外延迟 <100ms、告警规则 `P99>500ms → P1`、《人工端到端测试日志记录方案》§6「P99 增量 <5ms」）。

#### 1.1.1 口径声明（关键，决定判定是否有效）

| 项 | 口径 |
|----|------|
| **为何不用端到端绝对值判定** | LLM 生成与外部检索（OpenRAG / OpenMemory / DPS）耗时**不由本仓决定**，端到端时延随上游模型/数据量漂移，**不可作为本仓性能门禁** |
| **判定对象** | **本仓可控部分** ＝ 网关 / 编排的**步骤耗时**（`auth` / `memory` / `rag` / `llm` 等），可由 `routing_trace` 与 `traces.spans` 的**步骤计时形态** `[{"step":"auth","ms":0}, …]` 直接取数；**扣除 `llm` 步骤即得本仓额外开销** |
| **端到端的处置** | **只观测、不判定**：记录 P50/P95/P99 作为纵向基线（供 B0/B1 与后续版本对比），不设通过标准 |
| **测量噪声约束** | 本机（开发机）**端到端差分噪声 8~16 ms**（S7 审计 §9.7.1 既有结论）→ 端到端数字在中小样本下**不可判**；判定须用**路径内步骤计时**，或足量采样后取分位数 |
| **失败定性** | 未达标即记 FAIL 并登记缺陷/技术债；**不得**以「上游慢」为由静默通过 |

#### 1.1.2 量化目标（分级）

| # | 端点 / 场景 | 指标 | 目标值 | 口径与依据 |
|:-:|------------|------|--------|------------|
| P-1 | `POST /openllm/v1/chat`（同步，非流式） | **本仓步骤耗时**（不含 `llm` 步骤） | P50 ≤ **50ms** / P95 ≤ **100ms** / P99 ≤ **200ms** | 依据《系统架构 v1.3.0》「代理透传额外延迟 <100ms」（P95 取同值），P99 放宽 2×；且须显著低于告警阈值 500ms |
| P-2 | `POST /openllm/v1/chat`（同上） | 端到端（含上游） | **只观测，不判定** | 上游模型耗时不可控 |
| P-3 | `POST /openllm/v1/chat/stream`（SSE） | **`routing` 首包（首事件）** | P95 ≤ **1s** / P99 ≤ **2s** | 依据 v1.4.3 / v1.4.4「SSE 首包 P95 ≤ 1s」；须 < 网关整体超时 **5000ms** |
| P-4 | `POST /openllm/v1/chat/stream`（同上） | 首包**本仓额外开销** | P95 ≤ **100ms** | 同 P-1（扣除上游连接与首 token 时间） |
| P-5 | `POST /openllm/v1/chat/stream`（同上） | 流式总时长 | **只观测，不判定** | 由模型输出长度决定 |
| P-6 | `GET /openllm/v1/writeback/receipts`（回执查询，默认窗口 + 缺省 `limit`） | 响应时间 | P50 ≤ **100ms** / P95 ≤ **300ms** / P99 ≤ **500ms**；**5xx = 0** | 依据 v1.4.4 / v1.4.5 本地列表 `P95 ≤ 300ms`；P99 对齐告警阈值 500ms（等于阈值即告警，故门禁取 ≤） |
| P-7 | 回执查询 @ **1e4 行**（`TT-039` 专项） | 响应时间 | P95 ≤ **1s** / P99 ≤ **1.5s**；**不达标登记技术债，不判版本失败** | `payload_json` 表达式过滤**未建索引**为已知项（`TT-039` 用例文字即允许技债登记）；该档以「可用性可接受」为口径 |
| P-8 | `GET /openllm/v1/trace/metrics/export`（计量导出，默认 24h 窗 / `page_size=20` / 单源） | 响应时间 | P95 ≤ **500ms** / P99 ≤ **2s** | 依据 v1.4.6「检索响应 P99 < 2s」（同为文件/日志扫描类） |
| P-9 | `GET /api/v1/conversations/{id}/messages`（消息查询，缺省 `limit`；带/不带会话标识） | 响应时间 | P50 ≤ **100ms** / P95 ≤ **300ms** / P99 ≤ **500ms** | 同 P-6 |
| P-10 | 回写对主链路时延影响（操作化「= 0」） | 请求路径内**同步新增耗时** | P99 ≤ **5ms**，且回写经**异步队列**派发（无同步等待） | 依据《人工端到端测试日志记录方案》§6「P99 增量 <5ms」；与需求 §5「时延影响 = 0」等价操作化 |
| P-11 | 吞吐 | 相对首个可复现基线 | ≥ **基线 80%** | `TT-v1.4.8-038` 既有通过标准 |
| P-12 | 错误率 | 全部压测端点 | **< 0.1%**；读类端点 **5xx = 0** | 通用指标（`performance-engineering` §1.1） |

#### 1.1.3 测试方法与判定规则

| 项 | 定义 |
|----|------|
| 负载模型 | 基准（单用户，5min）→ **负载（并发 8**，对齐聚合信号量并发 8）→ 压力（至拐点） |
| **判定口径（v1.2.0 新增）** | **双口径，任一结论必须注明口径，不得混用**：**(a) 单飞档**（任意时刻仅 1 请求在飞；用于功能可用性与基线时延判定）；**(b) 并发 8 档**（并发 8、不限客户端节流；用于吞吐与尾延迟判定，须同时报告 `achieved_rps` 与 `peak_in_flight` 以自证并发确实生效）。**依据**：`TT-038` v1.3.0 实测同一端点两口径结论相反——单飞 P99 **128~484 ms 达标** / 并发 8 P99 **21,901 ms 不达标**；该差异已归集为技术债 **TD-新增-027**（并发下服务端串行化，P1），**P-11 吞吐须以并发 8 档判定**（实测 1.578 req/s 不达标） |
| 样本量 | 每档 **≥ 200 次请求**；P50/P95/P99 取全档分位数（非单次采样） |
| 数据规模 | `TT-039` 以**回执 1e4 行**为档位；其余端点用当前库内真实规模并**记录行数** |
| 判定 | 对 P-1/P-3/P-4/P-6/P-8/P-9 取**路径内步骤计时**；P-10 取请求路径内计时差分；**端到端数字仅登记为基线观测量** |
| 通过标准 | 全部适用项目标值达标 → `TT-038` 通过；P-7 例外（不达标登记技债）；未达标项须逐条给出定性（缺陷 / 技术债 / 环境限制） |
| 复现要求 | 记录：实例（端口 / 是否加载 `.pylib` / 是否带编排器 `Env`）、模型与后端、并发、样本量、库行数、执行命令与时间 |

#### 1.1.4 本版本不适用项（显式声明）

| 项 | 不适用原因 |
|----|-----------|
| 容量规划（CPU/内存/磁盘/网络峰值、扩容策略） | 本机为**开发机**，无生产容量与流量模型；容量数据须在生产或专用压测环境取得 |
| 可用性 SLO（≥99.9%）与错误预算 | 无生产长周期运行数据；本版本不设可用性门禁 |
| 前端性能（Core Web Vitals / 首屏） | 本工作区**无 OpenBase/OpenLLM 前端工程**（同 `TT-025`/`TT-026` 不适用声明） |

## 2. 可用性设计

| 项 | 设计 |
|----|------|
| 回写通道失败不影响主链路 | 异步 + 退避隔离；注入故障主链路仍 200（AC-148-05-3） |
| 组件不可用降级不报错 | `ComponentUnavailableError` + degraded 标记（沿用） |
| 流式回写不可行 | 显式声明并写入契约，不得静默缺失（AC-148-03-3；R3） |

## 4. 可靠性设计

| 项 | 设计 |
|----|------|
| 幂等且不丢（F-08） | 幂等键会话维度 + `seq=max_seq+1`（持久化来源）；重启后续接 DB 最大序号 |
| 硬判据 | 重启后回写丢失数 = 0（复用 F-08 复现用例形态） |
| 迁移幂等 | `WHERE NOT EXISTS` / `create_all` 兜底（AGENTS.md §5） |

## 5. 可维护性设计（含观测/裁剪口径区分）

* **观测模式 vs 裁剪模式严格区分**（AGENTS.md / 需求 §5）：本版本仅观测（第零段），裁剪属 v1.4.9 且开关默认关闭，二者不得混用——避免「观察到的变化」与「被观察对象变了」混淆（Phase 1/2 并行不合并交付的同一原则）。
* 计量与裁剪共用 `count_tokens` / 窗口查询时，通过显式模式开关隔离。

## 6. 可观测性设计

### 6.1 计量回执（`routing_trace`，DT-148-C1）

| 字段组 | 必需字段 |
|--------|----------|
| Prompt 组成 | `prompt_total_tokens`、六段分项 `segment_tokens`（system/profile/memory/rag/history/query） |
| 检索快照 | `memory_items`、`rag_items`（条目数、score、实际进入 prompt 条目与 token） |
| 维度字段 | `request_id`、会话标识、模型、时间戳 |
| 导出 | 按 `request_id` + `session_id` **批量导出**（AC-148-01-1） |

### 6.2 回写回执（第一批起，AC-148-05-2）

* 三路各自 `accepted` / `duplicated` / `failed`、投递 `seq`、被丢弃项标识，覆盖率 **100%**，可查。
* 回写静默失败是 F-08/F-09 暴露的问题，回执是其唯一可见性来源。

### 6.3 预算回执（v1.4.9 第二批起）

* `model_window`、`output_reserve`、`budget`、`tokens_before_trim`、`tokens_after_trim`、`dropped_fragments`（含原因）、`hard_truncated` —— **本版本不产出**（裁剪不在本版范围），字段设计预留（数据库 §3.1 预留 `output_reserve`）。

### 6.4 日志

* 结构化日志（logging + extra 字段），级别 DEBUG/INFO/WARN/ERROR，禁 print（AGENTS.md §3）；敏感字段不落（`mask`）。
