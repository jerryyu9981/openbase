## 0. 基线更正（v1.1.0，2026-09-28）

> 既有 `routing_trace.context_metrics` 已含 `segment_tokens`/`attribution_a`/`budget`/`truncated`/`refine`（CR-149 §3.3 v1.13.0）
> ⇒ 本版本回执为**扩展既有字段组**，**非新建**；§2 表中标注 **【新增】**者仅 I-2/I-3 三类（逐条丢弃原因／`hard_truncated`／`degraded`／`enabled`）。

## 1. 对外接口影响（IF-149-01/03）

| 项 | 设计 |
|----|------|
| 路径/方法 | **不变**（不新增端点、不新增必填参数） |
| 请求体 | **不变**（不新增必填字段） |
| 响应 | 在既有**只读观测**字段组内**新增子字段**（向后兼容，调用方可忽略） |
| 错误码 | 沿用既有体系；本版本**不新增**对外错误码 |

## 2. 预算与回写回执（FR-149-06 / AC-149-05）

落点：既有 `routing_trace` 的观测字段组内（字段名以实现为准，语义如下）。

| 字段 | 类型 | 语义 | 必填 |
|------|------|------|:----:|
| `model` | str | 使用的模型标识 | ✅ |
| `model_window` | int | 模型窗口（token） | ✅ |
| `output_reserve` | int | 输出预留 | ✅ |
| `safety_margin` | int | 安全余量 | ✅ |
| `available_budget` | int | 实际可用预算 | ✅ |
| `prompt_tokens_before` | int | 裁剪前 token | ✅ |
| `prompt_tokens_after` | int | 裁剪后 token | ✅ |
| `dropped` | list | 被丢弃片段及原因 `[{source,id,reason}]` | ✅（可为空数组） |
| `hard_truncated` | bool | 是否发生文本级硬截断 | ✅ |
| `degraded` | str\|null | 降级标记（如 `empty_guard`） | ✅（可为 null） |
| ~~`enabled`~~ | — | **更正（Step 3 批次 1 实测）**：**不新增该字段** —— 既有 `budget` 段落的**出现与否**已等价表达开关状态（`budget` 非空 ⇔ 预算/裁剪生效）。新增同义字段属重复造字段，故取消 | — |

- **齐备率 100%** 为验收项；字段缺失即判失败（该请求不计入通过）。
- **齐备率的论域（v1.3.0 澄清，与架构 §3.16／§3.19 对齐）**：统计对象为**预算生效的请求**（即回执含计量组 `budget` 的请求）。**预算总开关关闭 ⇒ 上表扩展字段一律不出现**（回执与 v1.4.8 逐字一致，满足 NFR-149-02／AC-149-09）；因此「齐备率 100%」与「关闭即零新增字段」**不矛盾**。
- **取值齐备（非仅键存在）**：上表 ✅ 字段须**键在且取值有语义**（`model` 不得为 null；`degraded` 允许 null 表示无降级）。
- **禁止**写入片段正文、回答正文、令牌或密钥（SEC-149-01；沿用 AC-148-01-5）。

## 3. 跨仓回写 payload 契约（FR-149-08 / IF-149-02，依赖 D4）

```json
{
  "writeback": {
    "targets": ["memory", "rag", "profile"],
    "save_if_valuable": true,
    "used_fragments": [
      {"source": "rag", "id": "chunk-0001", "score": 0.82},
      {"source": "memory", "id": "mem-0042", "score": 0.71}
    ]
  }
}
```

| 约定 | 内容 |
|------|------|
| `used_fragments` | **本轮实际进入最终 Prompt 的片段**（含标识与得分） |
| 缺省 | 字段缺省 ⇒ 视为未提供使用反馈（不报错） |
| 跨仓落点 | 由 **OpenLLM** 仓实现消费；本仓负责定义与产出（D4 随派单分发） |
| 兼容 | 不改四系统（DPS/OpenRAG/OpenMemory）既有接口 |

## 4. 契约对齐检查（2.9）

前端轨道**不激活** ⇒ 本版本**不做**前后端契约对齐（`[N/A]`）；仅做**跨仓**（OpenLLM）契约对齐，见 §3。
