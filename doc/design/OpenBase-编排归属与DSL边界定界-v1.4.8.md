## 1. 边界条款（AC-148-08-1）

### 1.1 两层编排的定义

| 层 | 定义 | 承载能力 | 落位 |
|----|------|----------|------|
| **网关「聚合编排（BFF）」** | OpenBase 网关作为**薄策略层**：面向客户端的聚合入口，负责请求归一、路由策略、鉴权透传与响应聚合 | ①请求转发（`llm_chat(payload)` 原样透传）；②鉴权/身份透传（四维身份透传契约）；③路径级归属（路径归属矩阵） | 本仓网关 `llm_proxy` |
| **OpenLLM「pipeline 编排」** | OpenLLM 编排层：负责上下文素材的**选择、组装、预算、回写**，是真实的语义编排面 | ①素材四类+历史组装（Jinja2）；②模型路由（5 因子）/ `ComponentRouter` 决策；③预算与裁剪；④三路回写；⑤计量回执 | OpenLLM 仓 `edgerouter/orchestration/` |

### 1.2 归属原则

1. **pipeline 编排归 OpenLLM**：素材选择、组装、预算、回写、模型路由——全部落在 OpenLLM 仓。
2. **网关保持薄策略层**：网关侧**不新增任何编排组件**、不新增编排 DSL、不做素材选择/预算/回写逻辑。
3. **主题按「会话」归集，实现按模块落位**：一个迭代主题（会话编排）下挂 R-395/R-396/R-397/R-398 与 F-01…F-11，但不把模型路由、组件适配器、配额中间件、语义缓存硬塞进「会话模块」——编排还依赖这些非会话域能力（《系统架构设计文档》§1.3）。
4. **网关零改动**：`llm_chat(payload: dict[str, Any])` 原样转发请求体，新增字段（如 `session_id`）直接透传（`llm_proxy/__init__.py:355-366` 实测）。

## 2. 边界判定用例（消除残留歧义）

| 场景 | 归属 | 判定依据 |
|------|------|----------|
| 新增上报字段透传 | 网关（透传）｜OpenLLM（消费） | 网关不解析、pipeline 消费 |
| 素材历史/画像/记忆/知识库投入上下文 | OpenLLM | 属素材选择与组装 |
| prompt token 预算计算与超窗处理 | OpenLLM | 属预算能力 |
| 多轮会话标识记账口径 | OpenLLM | 属会话域 |
| 请求鉴权与身份透传 | 网关 | 属 BFF 薄策略层 |
| 具体模型路由（auto 5 因子 / fallback） | OpenLLM | 属模型路由 |
| 语义缓存命中判定 | OpenLLM | 属编排域（两路径一致） |

**命名防歧义**：术语「编排」在网关句保留限定语「聚合编排（BFF）」，在 OpenLLM 句用「pipeline 编排」，二者**不混用**。

---

## 3. 结论

* 本版本（v1.4.8）编排 DSL 边界定界为：**网关 = 薄策略聚合层（BFF，零编辑能力）；OpenLLM = 语义 pipeline 编排（选择/组装/预算/回写）**。无残留歧义（AC-148-08-1 满足）。
* 本仓本次**仅文档整合**，未实施任何 OpenLLM 侧代码改动（VC-014；AC-148-08-2，以 git 核查验证）。
