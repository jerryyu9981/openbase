## 2. 环境与端口（零变化）

| 项 | 设计 |
|----|------|
| 拓扑 | **不变**：统一前端（vite 5173）→ 网关（8000）→ 模块；四仓服务（DPS/OpenLLM/OpenMemory/OpenRAG）**不受影响** |
| 端口 | **不新增端口**（`logs` 模块随 OpenBase 8000 一并暴露） |
| 进程 | **不新增进程/服务**（`logs` 是 OpenBase 进程内的模块） |
| 数据库 | 复用既有 PG（`audit_logs` 零迁移） |
| 文件系统 | 复用既有日志目录 `logs/openbase/`（**只读访问**，不新增目录） |

---

## 3. 配置增量（4 项，均可回退为默认值）

| 配置项 | 默认 | 说明 |
|--------|:----:|------|
| `log_query_default_window_hours` | 24 | 前端未指定时间窗时的默认范围 |
| `log_query_max_days` | 2 | L1 单次最多扫描的日分片数（超出置 `truncated`） |
| `log_query_max_lines` | 200000 | L1 单次最多扫描行数（超出置 `truncated`） |
| `log_export_max_rows` | 10000 | 导出条数上限（超出 400） |

| 项 | 说明 |
|----|------|
| 生效方式 | 环境变量 / `.env`（沿用既有 settings 机制）；**不改既有配置项** |
| 生产建议 | 三环境使用**相同默认值**；如生产日志量显著更大，可在 Pro 收窄 `max_days`/`max_lines` 并观察 `truncated` 频率后再调整 |
| 敏感配置 | 无新增密钥/凭据 |

## 4. 授权数据变更（唯一的数据侧动作，幂等）

| 项 | 内容 |
|----|------|
| 变更内容 | **（v1.1.0 修订）新增两个权限码**：① **`log:read`**（日志中心，VC-012）；② **`module:manage`**（模块开关管理页，VC-013 决议 10）—— 均授予**管理员角色** |
| 变更性质 | **数据（授权）变更，非 schema 迁移**（`audit_logs` 与权限表结构均不变） |
| 落地方式 | ① 更新《OpenBase-K13-账号权限矩阵-v1.0.0》登记**两个**权限码；② 通过既有授权脚本（幂等，`WHERE NOT EXISTS` 语义）写入权限与角色映射 |
| 验证 | 授权后：无令牌 401；普通用户 403；管理员 200（AC-146-07-1）；**`module:manage` 同口径**（AC-146-15-2：无权限 → 接口 403 且页面/入口不可见） |
| 回滚 | 撤销授权即可（不删数据）；页面入口随权限消失（**最轻量回滚**，见 §6） |

## 6. 发布与回滚

| 项 | 设计 |
|----|------|
| 发布路径 | Dev → Test → Pro（沿用既有三环境门禁） |
| 发布内容 | **（v1.1.0 修订，四块）**① **后端（日志域）**：`openbase/modules/logs/` 新模块（含 **`RepoLogAdapter` 第四类源**）+ `demo_app` 挂载 + 4 项配置；② **后端（平台配置域）**：模块状态写端点 `PATCH /api/v1/modules/{id}` + 权限码 `module:manage` + `module.switch` 留痕；③ **前端（IA 重构 + 日志中心）**：`pages/platform/**` 四域 + `pages/personal/**` + 日志中心 + 模块开关页 + `core/api/{logs,modules}.ts` + **全量重定向映射表** + 三分菜单；④ **授权**：`log:read` + `module:manage` 授予管理员 |
| **采集侧改造（v1.1.0）** | 编排器输出由"启动时间戳"命名改为 **`{svc}-YYYYMMDD.jsonl`**（按日切分，BL-146-18）；**不删历史、重启不追加破坏**。此改造**属本仓发布内容** |
| **跨仓发布（v1.1.0，非本仓发布）** | **四仓改动（D-6 + JSONL 结构化）由各仓独立评审、提交与发布**，**不在本仓发布清单内**；本仓发布仅需保证 `RepoLogAdapter` 对"未就绪的四仓"**可降级**（纯文本回退/文件缺失返回空集） |
| 灰度/开关 | 无需开关：新增页面对无权限用户不可见，**天然灰度**（授权即上线）；IA 重构按域分批发布（需求评估报告 §6#4） |
| **回滚步骤** | ① **最轻量**：撤销 `log:read` / `module:manage` 授权（页面入口即时消失）；② 如需彻底回滚：还原前端路由（把 `legacyRedirects` 反向，旧路径指回原页）与后端模块卸载；③ 配置项回默认值；④ **采集侧命名改造**回滚为原命名（历史文件**不删除**，可并存） |
| 回滚风险 | **低**：无数据迁移、无既有契约变更；写入路径仅两处且均可降级（导出留痕失败不阻断导出；`module.switch` 留痕失败须在实现中明确为"变更失败并回滚"或"降级告警"，Step 3 定案） |
| 验证清单（发布后） | ① `checkall` 服务体检通过；② **四端点**鉴权三态（401/403/200）；③ **四源**各检索一次并核对 `total`（含 `repo_log`）；④ 导出 CSV/JSON + 留痕 1 行；⑤ 旧路径**抽样遍历全部可达**（无 404）；⑥ 无权限用户菜单不可见（双角色）；⑦ 模块开关页：启停生效 + `module.switch` 留痕 1 行；⑧ 深链直访不回退 + `console.warn = 0` |

## 7. 不适用项说明

| 项 | 原因 |
|----|------|
| 容器/编排变更 | 无新增进程与端口，沿用既有部署形态 |
| 数据库迁移 | `audit_logs` 零迁移（仅新增 `action` 取值，非结构变更） |
| 缓存/消息组件 | 本版本不引入（见《非功能设计说明-v1.4.6》§7） |
| 容量与扩缩容 | 零新增持久化结构，无扩缩容诉求 |
| CI/CD 流水线变更 | 沿用既有流水线，无新增阶段 |
