## 1. 架构定位与边界

### 1.1 本版本改动本质

v1.4.8 **不新建编排层**。编排引擎已存在且完整（OpenLLM 仓 `edgerouter/orchestration/`：`ComponentRouter`、`auto/explicit` 编排器、Jinja2 组装器、回写回调）。本版本补齐的是**接线、收敛与计量**：

| 补齐项 | 性质 | 落点 |
|--------|------|------|
| 会话轴接入 | 接线 | OpenLLM `openllm_gateway.py` / 编排链路 |
| 三路回写接齐 | 接线 | OpenLLM `_build_writeback_callback` / `_run_stream_components` |
| 回写幂等键修正 | 修正 | OpenLLM `edgerouter` 写回存储 |
| 双路径收敛 | 收敛 | OpenLLM 网关入口（同步 / 流式共用步骤） |
| 基线工装 / F-02 | 观测 / 修正 | OpenLLM 编排链路 + `context_manager.py` |
| DSL 边界定界 | 文档 | **本仓（OpenBase）** |
| B0/B1 报告框架 | 文档 | **本仓（OpenBase）** |

### 1.2 跨仓边界（三方触达）

| 触达方 | 改动 | 依据 | 本仓角色 |
|--------|------|------|----------|
| **OpenLLM（主体施工仓）** | 第零段 / 前置零 / 第一批全部落点 | 派单选 §4；需求 §3 结论 1 | 定义设计契约（本文档），经派单分发 |
| **openbase-ui（配合仓）** | 发消息提交会话标识 | 说明 D2；`llm.ts:101/113` | 定义契约（API §4.8），另行派单 |
| **本仓 OpenBase** | BL-148-08 文档整合 + BL-148-07 报告框架 | VC-014 | 设计文档 + 报告框架，**不实施代码改动** |
| **OpenBase 网关** | **零改动** | `llm_proxy/__init__.py:355-366` 原样透传 | 验证透传契约 |

### 1.3 主题归集与模块归属（R-394 核心口径）

```
主题按「会话」归集（一个迭代主题下挂 R-395/R-396/R-397/R-398 与 F-01…F-11）
实现按模块落位（会话域 / 编排域 / 网关入口）
```

| 模块域 | 承载能力 | 本次改动 |
|--------|----------|----------|
| 会话域（会话状态 / 序号 / 幂等） | 会话标识、消息落库、写回序号 | R-396（会话落库）、F-08（幂等键） |
| 编排域（`orchestration/`） | 组件路由、素材选择、组装、预算 | R-396（历史素材）、R-398（回写接线）、第零段工装 |
| 网关入口（`openllm_gateway.py`） | 请求归一、双路径分发 | R-397（双路径收敛）、R-398（流式回写）、第零段归因 A |

> **边界推论**：不得把模型路由、组件适配器、配额中间件与语义缓存硬塞进「会话模块」；预算裁剪落点 `orchestration/`、双路径收敛落点网关入口。

## 2. 目标架构（v1.4.8 后的会话编排形态）

```text
                                   openbase-ui（配合仓）
                                        │  提交 { model, messages, session_id? }
                                        ▼
                          OpenBase 网关 llm_proxy（零改动，原样透传）
                                        │
                                        ▼
                              OpenLLM 网关入口  openllm_gateway.py
                                        │   _normalize_request（会话标识归一）
                                        ▼
                    ┌────────────── 共用编排步骤（R-397 收敛）──────────────┐
                    │ 组件执行 → 上下文格式化 → 预算 → 组装 → 路由/缓存        │
                    │   ├─ 会话域：历史按窗口（get_context_window）截取       │
                    │   ├─ 编排域：四类素材 + 历史（第五类）组装，Jinja2       │
                    │   └─ 计量埋点：prompt 六段分项 / 检索快照 / 归因 A     │
                    └──────────────────────────────────────────────────────┘
                                        │
                    ┌───────────────────┴────────────────────┐
               /chat 同步响应                             /chat/stream 流式
                    │                                        │
                    └─────── 三路回写（memory/rag/profile）──┘  ← 两路径共用回写回调
                                        │
                             WritebackStore（会话维度幂等键）
                                        │
                             routing_trace（计量回执，可批量导出）
```

## 4. 各段架构设计

### 4.1 DT-148-01 基线工装（第零段，仅观测）

| 工装 | 设计要点 | 落点 |
|------|----------|------|
| 工装 1 Prompt 组成计量 | 记录 `prompt_total_tokens` 与六段分项 `segment_tokens`（system/profile/memory/rag/history/query）；分母口径 = 四类素材注入片段 token 之和，不含 query 与输出 max_tokens 预留 | 编排链路计量埋点 |
| 工装 2 检索快照 | 记录 memory/rag 返回条目数、各条 `score`、实际进入 prompt 的条目与 token | 编排链路 |
| 工装 3 回执落库 | `request_id`/会话标识/模型/时间戳 + 工装 1/2 写入 `routing_trace`，可批量导出 | 数据库 §3.1 |
| 工装 4 归因 A | 由片段抽关键 n-gram/关键词集合，回答命中即视为使用；随调用计算，零额外模型调用 | `openllm_gateway.py` |
| 工装 5 归因 B 工具 | 抽样每轮 ≥30 条，固定判定 prompt/模型/版本；片段去标识打乱序；判定模型不与被评同源 | 独立脚本 + 固定集 |
| 工装 6 固定集与评分表 | 7 场景矩阵 × ≥5 条 ≥35 条（含 2 负例）+ 四维 1~5 分 + 记录模板 | B0B1 报告框架文档 |
| 工装 7 汇总脚本 | 从回执导出指标，生成基线报告（含方法/样本量/漏检率区间） | 本仓报告框架 |

**硬约束**：工装 1~7 一律不得含裁剪/改写/截断逻辑；禁止记录令牌/密码/密钥/完整请求体（AC-148-01-5）。

### 4.2 DT-148-02 F-02 窗口匹配修正

* `MODEL_CONTEXT_LIMITS` 匹配由「插入顺序 `startswith`」改为**最长键优先**：精确匹配 → 命中失败则按**键长度降序**做前缀匹配，取最具体开窗。
* 预期：`gpt-4o-2024-08-06` → 128000/`o200k_base`；`gpt-4-turbo-2024-04-09`、`gpt-4-32k-0314` → 各自最具体窗口。
* 补 3 个日期化模型名单测（AC-148-02-1/2）。

### 4.3 DT-148-03 双路径收敛（前置零 R-397）

* 抽取共用步骤：**组件执行 → 上下文格式化 → 预算 → 组装 → 路由/缓存判定**，供 `/chat` 与 `/chat/stream` 共用。
* 消除流式路径自建 Prompt 组装副本。
* `model="auto"` 两路径均走 5 因子路由与 fallback；`mode="auto"` 两路径均经 `ComponentRouter`（AC-148-03-2）。
* 流式补齐回写与语义缓存语义，或按 R3 前置核实结论**显式声明不提供并写入契约**（AC-148-03-3）。

### 4.4 DT-148-04 会话轴接入（R-396）

* `_normalize_request` 停止只取最后一条 user 消息；历史按窗口纳入（`get_context_window` 按 max_tokens 截取，不超窗）。
* `OpenLLMChatRequest` 新增会话标识字段（可选）（API §4.8）。
* 历史作为第五类素材于 `assembler` 位置 **System+画像+记忆+知识库+[历史]+Query** 组装（AD-03）。
* `ConversationMessage` 会话消息落库与检索对齐新会话标识口径（数据库 §3.2）。

### 4.5 DT-148-05 三路回写接齐（R-398）

* `_build_writeback_callback` 由 2 路扩为 3 路（+profile）。
* `_run_stream_components` 补齐 memory/rag/profile 回写；触发点与聚合方式按 R3 前置核实结论。
* 回写回执：三路各自 `accepted/duplicated/failed`、投递 `seq`、被丢弃项标识，可查（可观测性 §4）。
* 失败隔离：沿用既有异步队列 + 指数退避 ≤3 次；组件不可用降级不报错、失败不影响主链路。

### 4.6 DT-148-06 回写幂等键修正（F-08）

* 键 `(session_id, seq, target)`，`session_id` 必须为真实会话标识（禁用 `identity.user_id` 顶替）。
* `seq` 取 `WritebackStore.max_seq(session_id) + 1`（持久化来源），禁止模块级进程内计数器。
* 复用 F-08 复现用例形态做跨进程重启回归（AC-148-06-3）。
* 既有 26 行/8 会话数据保留 + 迁移说明（数据库 §3.3）。

### 4.7 DT-148-07 B0/B1 基线测量与报告

* 无条件部分：工装就绪（随 DT-148-01）+ F-02 生效（DT-148-02）。
* 条件部分（D3 确认时）：B0（第零段后/前置零前，严格只观测）与 B1（第一批后）报告；以相邻点位差值为准、绝对值辅。
* 判定三层：A 引用检测（主指标，纵向对比）+ B LLM 归因（抽样≥30 条，校准漏检率）+ C 消融（一次性 10~15 条）。
* WCR 口径三分：硬浪费/软占用/必要占用，三者之和=1。
* 本仓产 B0/B1 报告框架（见《B0B1基线报告框架-v1.4.8》）；D3 未确认则挂起并留测量入口。

### 4.8 DT-148-08 编排归属与 DSL 边界定界（R-394）

见独立文档《OpenBase-编排归属与DSL边界定界-v1.4.8》：网关「聚合编排（BFF）」为**薄策略层**（路由、鉴权、聚合透传），**不承载编排组件**；OpenLLM「pipeline 编排」负责素材选择、组装、预算与回写；网关零新增编排能力（AD-14；AC-148-08-1）。

## 5. 技术选型与约束

| 项 | 选型 / 约束 | 说明 |
|----|-------------|------|
| 编排引擎 | 沿用 `edgerouter/orchestration/` | 不新建 |
| 组装 | Jinja2 组装器（沿用） | 历史第五类素材复用同一机制 |
| token 计量 | `count_tokens(model, text)` + 修正后 `get_model_context_limit` | F-02 修正后计量可信 |
| 回写存储 | WritebackStore（SQLite `writeback.db`） | `seq=max_seq+1`；会话维度 |
| 计量存储 | `routing_trace` 表扩展（或独立表，本设计定稿 `routing_trace` 增列） | 可批量导出 |
| 异步回写 | 既有异步队列 + 指数退避 ≤3 | 不阻塞主链路 |
| 语义缓存 | 两路径检出一致（沿用） | 前置零对齐 |
| 语言安全 | SQLAlchemy 参数化（禁止字符串拼接） | AGENTS.md §5 |
| 日志/脱敏 | 结构化日志；计量回执脱敏（`core/mask.py` 覆盖凭据模式） | AGENTS.md §3；需求 §7 |

## 6. 约束与排除项（对齐需求 §10）

1. 第零段工装一律不得含裁剪/改写/截断逻辑；裁剪属 v1.4.9 且开关默认关闭。
2. 新增字段一律可选，缺省保持既有行为。
3. 本仓不实施 OpenLLM 侧代码改动（VC-014）。
4. 开工前回填派选 §2 五项前置核实；与指令不一致须先更正落点。
5. D3 未确认期间不得以「无基线数据」规避硬判据（重启后回写丢失数=0、两路径行为一致）。

**排除项**：预算裁剪与配额竞争、回写质量与反馈闭环、v1.5 治理、前端会话界面交互、模型选型（见需求 §10.2）。
