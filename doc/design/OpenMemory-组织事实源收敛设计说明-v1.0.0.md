## 1. 背景与问题

### 1.1 现状取证（三源，非双源）

| # | 组织状态载体 | 位置 | 数据结构 |
|:-:|---|---|---|
| 1 | `_org_registry`（多租户 API A） | `src/openmemory/multitenancy/api/organization_routes.py:44` | `dict[str, dict[str, Any]]` |
| 2 | `_org_registry`（多租户 API B） | `src/openmemory/multitenancy/api/org_routes.py:78` | `dict[str, OrganizationConfig]` |
| 3 | 组织策略映射 | `src/openmemory/auth/permission.py:46`（经 `_load_org_policies`，`permission.py:107-120`） | `dict[str, OrganizationRolePolicy]`；配置源 `src/openmemory/utils/config.py:176` |

### 1.2 漂移链路（三处互相不可见）

1. **同名不同物**：两个 `_org_registry` 是两个独立模块级变量，分别由 `organization_routes.py:114` 与 `org_routes.py:153` 写入，**互不可见**；
2. **不回写授权层**：两者均**不更新** `permission.py::_org_policies`，而 RBAC 判定**只读**该映射（`permission.py:173` / `:223` / `:269` / `:295` 均为 `self._org_policies.get(org_id)`）；
3. **后果**：经 API 新建的组织在授权层**无策略**，仅靠 `src/openmemory/auth/middleware.py:64` 的 `{"default": {"enabled": True, "default_role": "user"}}` 兜底 → 「组织已存在」与「其策略」两个事实不一致；
4. **进程内易失**：三源均为内存态，进程重启即丢失，与「组织是持久治理实体」的语义不符。

### 1.3 问题定性

- 属**架构性缺陷**（缺唯一事实源 + 缺缓存失效策略），非单点 bug；
- 影响面：组织生命周期（建/改/停/删）× 授权判定（策略装载/查询）× 多租户隔离；
- 现状无自动化护栏（三源漂移不会被任何用例捕获）。

## 2. 目标与非目标

### 2.1 目标

| 编号 | 目标 |
|---|---|
| G1 | 组织与其策略**以 DB 为唯一事实源**；内存层降级为**可失效缓存** |
| G2 | 组织写操作（建/改/停/删）**同步**影响授权判定，消除「建了组织却无策略」 |
| G3 | 两个 `_org_registry` **注销**，改由统一读取入口提供 |
| G4 | 漂移可被**自动化用例**捕获（回归护栏） |
| G5 | 变更**可回滚**（保留内存态回退开关至过渡期结束） |

### 2.2 非目标

- 不改变组织 API 的**对外契约**（路径、方法、响应体保持不变）；
- 不引入新的外部依赖；
- 不在本批调整角色/权限模型（沿用既有档位锚点与权限码）。

## 3. 设计

### 3.1 分层与职责

| 层 | 职责 | 禁止 |
|---|---|---|
| **事实源（DB）** | 组织实体与其策略的唯一持久化；事务边界内保证一致 | 禁止被内存层反向覆盖 |
| **缓存层（进程内）** | 加速读；可失效、可预热；**非事实源** | 禁止作为写入目标；禁止独立于 DB 演进 |
| **读取入口（单点）** | 对外唯一读取 API（`get_org` / `get_org_policy`） | 禁止各路由自行持有 registry |
| **授权判定** | 经读取入口取策略，缺失即 **fail-closed**（不静默降级到 default，见 §3.5） | 禁止绕过入口直读旧映射 |

### 3.2 读路径（Cache-Aside）

1. 查缓存 → 命中即返回；
2. 未命中 → 回源 DB（按 `id` 或 `code` 双形态解析，复用既有 `_looks_uuid` 语义）；
3. DB 命中 → 回填缓存并返回；DB 无记录 → 返回 `None`（授权侧 fail-closed）；
4. DB 不可达 → **不返回陈旧兜底**，按既有「数据源失败不静默降级」口径返回依赖不可用错误（建议 `SYS_SOURCE_UNAVAILABLE` 语义一致化）。

### 3.3 写路径（先库后缓存）

1. DB 事务内写入/更新/停用/删除组织及其策略；
2. **提交成功后**失效（或刷新）对应缓存键；提交失败不得改缓存；
3. 删除/停用须**同步**使授权判定失效（避免「已停用仍可授权」）。

### 3.4 收敛映射表（现状 → 目标）

| 现状 | 目标 |
|---|---|
| `organization_routes.py:44 _org_registry` | **注销**；读写改经统一读取入口（DB + 缓存） |
| `org_routes.py:78 _org_registry` | **注销**；同上 |
| `permission.py:46 _org_policies`（配置装载） | 保留为**缓存**；装载源由「静态配置」改为「DB 事实源 + 配置仅作**初始种子**」 |
| `middleware.py:64` 的 `{"default": …}` | 仅作**过渡期兼容**，须登记退出条件（见 §5） |

### 3.5 一致性语义（关键决策）

- **策略缺失**：组织存在但无策略时，**不得**静默套用 `default` 放行；应显式拒绝并留痕（fail-closed），避免「未配置即放宽」；
- **读一致性**：允许缓存延迟，但**同一进程内写后必失效**（read-after-write 一致性）；
- **并发**：缓存刷新须加锁或采用「写失效 + 读回填」的无锁安全模式，避免共享可变状态竞争。

## 4. 数据模型

### 4.1 组织表（沿用/对齐既有 `organization`）

| 字段 | 类型 | 约束 | 说明 |
|---|---|---|---|
| `id` | uuid | PK | canonical 标识 |
| `code` | text | **UNIQUE**（索引型唯一约束） | 组织码（对外码形态） |
| `status` | text | NOT NULL, CHECK(`active`/`suspended`/`disabled`) | 启停状态；授权判定须读取 |
| `created_at` | timestamptz | NOT NULL | — |
| `updated_at` | timestamptz | NOT NULL | 写路径维护 |

### 4.2 组织策略载荷

| 方案 | 说明 | 取用 |
|---|---|---|
| ① 同表 JSONB 列 `policy` | 策略与组织同生命周期、同事务 | **推荐**（避免第二次查询与二次漂移） |
| ② 独立 `organization_policy` 表 | 便于策略版本化与审计 | 备选（须与组织同事务写入） |

载荷至少含：`enabled`、`default_role`、`allowed_roles[]`、`row_scope` 相关项（与既有 `OrganizationRolePolicy` 字段对齐）。

### 4.3 约束与索引

- `organization.code` 唯一（索引型唯一约束，参考本项目既有教训：`pg_constraint` 不含索引型唯一约束，核查须用 `pg_indexes`）；
- 策略查询路径需 `org_id` 索引；
- 迁移脚本须**幂等**（`CREATE ... IF NOT EXISTS` / `ON CONFLICT DO NOTHING`）。

## 5. 迁移与过渡方案（结构先行、数据后行）

| 阶段 | 内容 | 退出条件 |
|---|---|---|
| **P0 结构** | 建表/加列/唯一约束（独立结构变更，由受控流程执行） | 结构就位且只读预检通过（无重复 `code`） |
| **P1 影子读比对** | 新读取入口与旧内存态**并行读**，比对差异并留痕；**放行仍走旧路径** | 影子期差异为 0（无遗漏组织/策略） |
| **P2 切换读** | 读取切至新入口；旧 registry 只读保留 | 切换后错误率与延迟不劣于基线 |
| **P3 切换写** | 写路径改为「先库后缓存」；旧 registry **注销** | 写后读一致，无 drift 用例全绿 |
| **P4 退役** | 移除 `middleware.py:64` 的 `default` 兜底与旧内存态 | 过渡期结束（建议**两个版本内**） |

**回滚**：每阶段均保留回退开关（读路径可切回旧实现）；结构变更回滚语句随迁移脚本一并交付。

## 6. 非功能要求

| 维度 | 指标 |
|---|---|
| 性能 | 读命中缓存 ≤ 1ms（进程内）；未命中回源 ≤ 50ms P95（同实例局域网库） |
| 一致性 | 写后读（同进程）必须一致；跨进程最终一致（TTL 建议 ≤ 60s） |
| 可观测 | 缓存命中率、回源次数、失效次数、策略缺失拒绝数（fail-closed 计数） |
| 安全 | 组织写操作须鉴权（沿用既有权限码，不新增端点级声明）；变更留痕（操作人/前后值/request_id） |
| 可靠性 | DB 不可达时**不静默降级**；按既有口径返回依赖不可用错误 |

## 7. 验收标准

| 编号 | 验收项 | 通过标准 |
|---|---|---|
| AC1 | 唯一事实源 | 三个旧载体注销或降级为缓存；代码检索无第二个组织事实源 |
| AC2 | 建组织即可授权 | 新建组织后**无需重启/改配置**，授权判定即可读到其策略 |
| AC3 | 停用即时生效 | 组织停用后，授权判定立即拒绝（read-after-write 一致） |
| AC4 | 漂移护栏 | 新增用例：三源漂移场景（旧实现）必须**失败**，新实现必须**通过**（反例自证） |
| AC5 | fail-closed | 策略缺失/DB 不可达不得放行；返回码与既有错误码口径一致 |
| AC6 | 回滚可用 | 按 §5 回滚脚本可恢复至前一阶段，且回滚后行为与基线一致 |

## 8. 风险、假设与约束

| 编号 | 风险/假设 | 应对 |
|---|---|---|
| R1 | 组织 API 存在**隐式内存语义**依赖（如测试依赖 registry 直读） | 先全量检索 `_org_registry` 使用点（当前已知：`organization_routes.py` 5 处、`org_routes.py` 5 处）逐点判定 |
| R2 | 「策略缺失 fail-closed」可能暴露既有未配置组织 | 以 P1 影子期先量化影响面，再决定是否设白名单过渡 |
| R3 | 缓存 TTL 与跨进程一致性 | 建议先不做跨进程缓存或设短 TTL；以 `request_id` 关联观测 |
| A1 | 假设 `organization` 表已存在且可加列 | 须在 P0 前只读预检确认（表存在性、`code` 唯一性、DDL 权限） |
| C1 | 本机无可用测试环境（Py3.13 + 旧 SQLAlchemy 阻断包导入） | 落地须在 OpenMemory 可执行环境完成，本设计不承诺本机验证 |

## 10. 附录

### 10.1 术语

| 术语 | 含义 |
|---|---|
| 事实源（SoT） | 唯一权威数据来源；其余均为派生/缓存 |
| Cache-Aside | 读时回源回填、写后失效的缓存模式 |
| fail-closed | 依赖不可用或必需信息缺失时拒绝，而非放行 |
