| 项 | 内容 |

## 2. 分层落点（本版本新增/改造）

```text
edgerouter/orchestration/
├── budget/             【新增】预算计算：可用预算 = 模型窗口 − 输出预留 − 安全余量
├── selector/           【新增】保底配额 + 相关性竞争（按 score）
├── segmenter/          【新增】条目级切分 + 文本级硬截断（标记是否硬截断）
├── verifier/           【新增】二次校验与显式降级（空/超窗拦截，禁止空上下文）
├── assembler.py        【复用不改契约】按既有段模板拼装
├── receipt/            【新增】预算与回写可观测回执
└── writeback/          【改造】写入治理（save_if_valuable 口径统一）+ 使用反馈字段
```

**依赖方向**：`budget → selector → segmenter → verifier → assembler`（单向），`receipt` 旁路采集，
`writeback` 在装配完成后触发；**不得**反向调用（避免 v1.4.8 双路径分叉问题复现）。

### 3.2 结构化片段契约

```text
Fragment = { source: "memory|rag|profile|history", id: str, text: str, score: float|None, tokens: int }
```
- `score` 缺失时按来源顺序退化（不参与竞争，但保留在保底配额内）；
- `id` 用于回写「使用反馈」（FR-149-08）。

### 3.3 预算计算（FR-149-02）

```text
available = model_window − output_reserve − safety_margin
```
- `model_window` 取自修正后的窗口查询（唯一数据源，避免两表分叉）；
- `output_reserve` / `safety_margin` 为**配置项**（默认值随实现给出，不在此硬编码）；
- **窗口未知** ⇒ 退回不裁剪行为并在回执标记原因（不静默）。

### 3.4 保底配额与相关性竞争（FR-149-03）

1. **保底**：每个来源至少 1 条（受剩余额度约束）；
2. **竞争**：剩余额度按 `score` 降序取用；
3. **确定性**：同输入必须同输出（`score` 相同时按 `(source, id)` 稳定排序）⇒ AC-149-02。

### 3.5 条目级切分与文本级硬截断（FR-149-04）

- 先**整条丢弃**低分片段（保底除外），再对最后一条做**文本级截断**；
- 截断必须置 `hard_truncated = true` 并在回执登记 ⇒ AC-149-03。

### 3.6 二次校验与显式降级（FR-149-05）

| 校验 | 触发 | 动作 |
|------|------|------|
| 空结果 | 裁剪后无任何片段 | **禁止返回空上下文** ⇒ 强制注入保底一条（取最高分）并标记 `degraded=empty_guard` |
| 仍超窗 | 校正后仍 > 窗口 | 触发**硬截断**至安全界；若仍失败 ⇒ 判失败并在回执标记（**不静默**） |

### 3.7 回执（FR-149-06 / NFR-149-03）

字段组见《API 接口设计文档》§2；**字段齐备率 100%** 为验收项（AC-149-05）。
**回执不含**片段正文与回答正文（SEC-149-01）。

### 3.8 写入治理（FR-149-07）

- `save_if_valuable=false` ⇒ **不写入**知识库（F-10 口径统一）；
- 价值判定拦截**计数可观测**（拦截率）；多租户过滤**保持生效**（SEC-149-03）；
- 防自引用污染：写入内容**不得**包含本轮装配生成的回执文本。

### 3.9 取数层逐组件通道路由（I-6，v1.1.1）

> **与既有能力的分工（不重复）**：§4.2 组件决策＝**选哪些组件**；W4 `describe_channel_report`＝**状态上报与建议**；本节＝**选定组件走哪条通道**（执行路由）。

```text
取数层（每组件）
  ├─ 读取该组件通道状态（既有 ChannelStateManager）
  ├─ 逐组件裁决：本次走 A 还是 B（默认＝整体 CHANNEL_PREFERENCE）
  ├─ 取数（走 A ⇒ OpenBase 直连；走 B ⇒ 经编排）
  └─ 该组件连续失败达阈值 ⇒ 仅该组件切换；成功 ⇒ 该组件计数归零
```

**ADR-149-06：路由粒度＝组件级**

| 项 | 内容 |
|----|------|
| 决策 | 通道路由粒度为**组件级**（profile／memory／rag 各自独立判定），整体偏好降为**默认兜底** |
| 备选 | ① 请求级（现状，全链路一次裁决）② 会话级 |
| 理由 | 三组件依赖不同的外部系统（DPS／OpenMemory／OpenRAG），**故障域不同**；请求级会把单组件故障放大为全链路切换 |
| 已知后果/风险 | ① 需逐组件状态与观测（本版新增轨迹字段）② 与整体偏好**必须兼容**：逐组件无判定时回落整体 ③ 裁决器不可用 ⇒ **fail-safe 回落整体偏好**（不把请求打挂） |

| 项 | 约定 |
|----|------|
| 开关 | **默认关闭**（关闭 ⇒ 语义与现状逐字一致） |
| 观测 | 轨迹／回执含**每组件通道**标签；与既有 `rag_source` 等口径**不冲突**（不改变其取值域） |
| 边界 | **不改**四系统接口；**不改变**既有归因 A 与 `degraded` 语义 |

### 3.13 设计补充 A：条目元数据最小契约（解 I-2，v1.2.0）

> **目的**：让段内裁剪能产出 `dropped[{source,id,reason}]`，**且不改变既有行为**。

| 项 | 约定 |
|----|------|
| 形态 | `build_prompt(..., segment_items={段: [{"source": str, "id": str, "score": float\|None}]})`（**可选**参数） |
| 对齐 | 与 `segments[段]` 的**单元行序一一对应**（单元＝`_parse_items` 还原的 `(编号前缀, 正文)`） |
| 缺省兼容 | `segment_items=None`（或不含该段）⇒ **不产出明细**，其余行为**逐字不变**；**长度不符同样按「无明细」处理**（不报错、不猜对齐） |
| 只读 | 元数据**不参与**排序、配额、去重与渲染 ⇒ 不改变任何取舍结果 |
| 安全 | 明细**只落身份与原因**（`source`/`id`/`reason`），**不落正文**（SEC-149-01；沿用 AC-148-01-5） |
| 提供方 | 由**网关侧（取数层）**在组装 `segments` 时并行提供；无身份组件（如历史段）可缺省 |

**冻结不变**：`dropped_items`/`dropped_tokens`/`truncated_items`/`merged_*`/`hard_truncated` 口径**不变**；新增明细为**增量**字段 `dropped`。

### 3.14 设计补充 B：跨段竞争池（解 I-1）＋ ADR-149-07（v1.2.0）

**ADR-149-07：跨段竞争池的算法与不变量**

| 项 | 内容 |
|----|------|
| 决策 | 在**既有分段落配额与保底之后**，引入**共享剩余额度池**，把「某段被丢掉的条目」按分数竞争回填 |
| 备选 | ① 保持各段独立（现状）② 取消分段配额改为全局单一池 ③ 跨段竞争但**不改段内单位**（**采用**） |
| 理由 | 现状下未用满的段额度被**浪费**（`dropped_items` 已发生的段本该可回填）；全局单池会破坏「**各段都有底**」的观测量与归因粒度 |
| 已知后果 | 观测需新增回填字段；必须显式守住 T1（Σ ≤ 可用预算）否则会**超窗** |

**算法（顺序固定，便于判据复现）**

```text
1) 各段先按既有配额裁剪（含保底一条，T2 语义不变）⇒ 得 used_i / dropped_tokens_i
2) 池上界：pool = min(available_budget − Σ used_i, Σ dropped_tokens_i)
   └─ **硬上界**：无论如何回填，Σ used 永不超 available ⇒ T1 结构性不破
3) 段序：按「被丢条目的最高 rank_score」降序；无 score 的段排最后（稳定序）
4) 段内：把被丢条目按 rank_score 降序回填，逐条检查「该段新 used ≤ 段配额 + 该段本次分得额度」，
   分得额度 = pool 中尚未耗尽的余量（先到先得，单段不得独占超过本次池）
5) 结果：回填条目数计入 `truncated.<段>.refilled_items`，回填 token 计入 `budget.<段>.competition_filled`
```

| 不变量 | 要求 |
|--------|------|
| T1（超窗率 0） | **Σ used ≤ available_budget ≤ 窗口 − 输出预留** —— 由池上界保证 |
| T2（保底一条） | 保底**先于**竞争；回填不得使任何段低于保底 |
| T10（段内单位） | 段内取舍单位**不变**（profile 维度/字段级、memory/rag/history 整条） |
| 逐字回退 | 开关 `CONTEXT_CROSS_SEGMENT_COMPETITION_ENABLED`（**默认 False**）关闭 ⇒ 与既有实现逐字一致 |
| fail-safe | 池计算或回填异常 ⇒ **视为未启用**（不改动既有结果），并在回执标记 `degraded="competition_skipped"` |
| 观测 | `budget.<段>.quota` **仍为静态配额**（语义不变）；新增 `competition_filled` 与 `refilled_items` |

**与 I-2 的关系**：池内的段序与段内序**都用 `rank_score`**；若缺条目身份（设计补充 A 未提供）⇒ **秩按既有呈现序**（fail-safe，不臆造分数）。

### 3.15 实现期澄清：池的语义边界与单一口径（I-1 落地，v1.4.0）

> 本节为 I-1 编码期发现的两处**语义空缺**所做的**收敛性澄清**：不改变 §3.14 的算法与不变量，仅补齐「池里到底装什么」与「回填用什么口径表达」，供 Step 4 判据直接引用。

**① 池只承载「预算闲置额度」，**不**承载内容质量规则的丢弃**
- 期望：竞争池的设计意图是让**静态分段配额**的闲置额度可按需再分配（配额是预算分配问题）。
- 约束：**段内去重 / 相邻同义合并 / 噪声剥离 / 单条截断**属于**内容质量规则**，与预算无关，其丢弃条目**不得**因池的存在而被回填（否则等价于「用预算换重复内容」，直接违背 FR-149-04 的意图）。
- 实现保证（结构性，非约定）：回填**复用同一** `_trim_segment`，而质量规则**先于**配额执行 ⇒ 即使放大配额，重复/噪声条目**仍会被丢掉** ⇒ 质量规则**不可被绕过**。
- 判据落点：`test_context_cross_segment_competition.py::TestQualityDropsAreNotReclaimed`（回归护栏）。
- 已知口径折中（如实登记）：池上界目前用**汇总** `Σ dropped_tokens`，其中**可能包含**质量规则丢弃的 token ⇒ 池**估值偏大**；但 T1 由 `available − Σ used` 一阶项守死，且回填实测 `gained > 0` 才落账 ⇒ **不产生超窗**。**I-2 落地后的状态**：逐条原因明细 `dropped` 已可用，但**明细不含 token 数** ⇒ 若要按「仅配额原因」收窄池上界，需再扩一个「**按原因分桶的 token 观测**」字段（属**再次契约扩展**）；本版本**不做**，登记为**后续可选项**（T1 已由一阶项守死，不构成风险）。

**② 回填一律用「放大该段比例」表达（单一口径，无旁路参数）**
- v1.2.0 算法第 4 条的措辞隐含了「额外配额参数」，落地时**取消**该旁路：段配额**只**取自策略（`policy.quota(segment)`），回填通过 `quota_ratios[段] = (静态配额 + 本次分得额度) / available` 表达。
- 理由：避免出现**两套配额表述**（策略配额 vs 旁路覆盖）而破坏 T1/T2 的**同源性**证明；也使「观测里的 `quota` 恒为静态配额」这一不变量无需例外。

**③ 回填后的观测描述「最终状态」**
- `truncated.<段>` 在回填后描述**放宽配额后的最终裁剪结果**，并追加 `refilled_items`（相对回填前少丢的条目数）。
- 放宽后**已无任何丢弃**时（`_trim_segment` 返回空报告）⇒ **不臆造零计数**，仅落 `refilled_items`；回填本身已由 `budget.<段>.competition_filled > 0` 独立证实。

### 3.16 设计补充 C：丢弃原因码取值域（解 I-2 的冻结项，v1.5.0）

> **目的**：设计补充 A（§3.13）已定 `dropped[{source,id,reason}]` 的**形态与对齐**，但未定 `reason` 的**取值域**。取值域属契约的一部分 ⇒ 先冻结后实施（Step 3 规则 2），避免用实现细节反向定义契约。

**原因码（冻结；与段内裁剪的处置点一一对应）**

| 原因码 | 处置点（`_trim_segment`） | 语义 | 计入 `dropped_items` |
|--------|--------------------------|------|:--------------------:|
| `dedup` | ① 段内去重 | 与段内**更早已保留**条目正文重复（键取正文，编号前缀不参与比较） | ✅ |
| `profile_field` | ②' 画像字段级预丢（A1） | 字段优先级低于保留者，整条目预丢 | ✅ |
| `quota` | ③ 配额整条裁剪 | 段配额已满，**整条**丢弃（不做半条截断） | ✅ |

**不进 `dropped` 的三种情形（冻结，含理由）**
- **单条截断（②）**：内容仍在（以截断形态保留），只计入 `truncated_items` ⇒ **不算丢弃**，其身份随正文保留。
- **相邻同义合并（①'，仅 memory）**：内容被**并入相邻条目**而非丢弃 ⇒ 由 `merged_items`/`merged_tokens` 独立观测；若同时进 `dropped` 会与同一处置点的**两种口径**（`merged_*` / `dropped_*`）混用，故**明确排除**（既有约定：两种口径不得混用）。
- **无身份条目**：`segment_items` 未提供该条 ⇒ **不臆造 `id`**，该条不出现于明细。

⇒ 由此得可验证关系：**`len(dropped) ≤ dropped_items`**。

**`dropped` 的落点与排序（冻结）**
- **落点（两级，语义一致）**：
  - **段级**：`truncated.<段>.dropped` —— **仅当为该段提供了身份**时出现；
  - **回执顶层**：`dropped` —— **恒有**（无身份或无丢弃 ⇒ `[]`），由段级明细按 **`QUOTA_SEGMENTS` 段序****展平**得到（元素自带 `source`，展平**无信息损失**），以满足 **AC-149-05 齐备率 100%**（API §2 `dropped` 必填）。
- 元素形态：`{"source": str, "id": str, "reason": <上表原因码>}`；**只落身份与原因，不落正文**（SEC-149-01 / AC-148-01-5）。
- 段内排序：按**处置阶段先后**（段内去重 → 画像字段级 → 配额整条），阶段内按**段内呈现序**（原下标升序）⇒ 判据可复现、**不依赖字典序**、回执可读。

**与 I-1 回填的关系（冻结）**
- `dropped` 与其余裁剪观测同守 **§3.15③「描述最终状态」**：被竞争池**回填恢复**的条目**从 `dropped` 中移除**（不保留「曾被丢过」的中间态）⇒ `dropped` 与 `dropped_items`、`refilled_items` 三者口径自洽。

**字段存在性（冻结）**
- 段级 `dropped`：`segment_items` **缺省、不含该段、或与该段单元行数不符** ⇒ **不产出**（整体缺席，而非空数组）；提供了身份且该段**确有裁剪但无条目被丢** ⇒ `[]`；该段**完全未发生裁剪** ⇒ **段级报告整体缺席**（沿用 I-3「无裁剪 ⇒ 报告缺失」不变量）。
- 顶层 `dropped`：**恒有**（回执含计量组时）；未提供身份 ⇒ `[]`；提供了身份且确无丢弃 ⇒ `[]`。

**不变量（冻结）**
- **只读**：明细**不得**影响排序、配额、去重、合并、渲染与竞争池的任何取舍结果；缺省时**逐字回退**（段级字段缺席、顶层 `[]`）。
- 口径冻结：`dropped_items`/`dropped_tokens`/`truncated_items`/`merged_items`/`merged_tokens`/`hard_truncated` **口径不变**，`dropped` 为**纯增量**字段。

### 3.17 设计补充 D：仍超窗的二次校验与显式失败标记（解 I-5，v1.6.0）

> **目的**：§3.6 已定「仍超窗 ⇒ 硬截断至安全界；若仍失败 ⇒ 判失败并在回执标记（**不静默**）」，但未定**判定口径**、**校正次数**与**失败表达方式**（是否新增错误码、落在哪个字段）。属契约的一部分 ⇒ 先冻结后实施。

| 项 | 冻结内容 |
|----|----------|
| 判定口径 | **最终 Prompt 总 token > 模型窗口**（`prompt_total_tokens > window_tokens`）⇒ 判为**超窗**；即 **AC-149-12「超窗发生率 = 0」的统计对象** |
| 为何仍可能超窗 | T1（Σ 素材 used ≤ 可用预算）已结构性保证**素材**不超窗；本校验实际拦截 **system / query / 段标记等非配额开销**把总长顶出窗口的情形 |
| 校正 | 把**溢出额度**并入输出预留（等价于**收紧素材可用预算**）后**重跑一次**预算裁剪并重组装 ⇒ **至多一次**、确定性、**无循环** |
| 判失败 | 校正后**仍超窗** ⇒ 置 `over_window=True`、`over_window_tokens=溢出额度`，并记 **ERROR 日志**（**不静默**） |
| 失败表达方式 | **不新增对外错误码**（API §1 约定）⇒ 失败以**回执标记**表达；该请求按 AC-149-12 **计入超窗率**（即「可判、可统计」，而非行为上的中断） |
| 观测 | `composition.over_window`（bool，**判失败**）、`composition.over_window_tokens`（int，判失败时的溢出额度）、`composition.over_window_recovered`（bool，**校正已发生且未判失败**）三者**恒有**；回执同步导出（含计量组时）。三字段齐备使「校正路径**即使成功也可见**」⇒ 二次校验不是黑盒 |
| 逐字回退 | `BudgetPolicy.enabled=False` ⇒ **不做二次校验、不改任何行为**（与 v1.4.8 逐字一致） |
| 不变量 | 校正**只**收紧素材预算，不得放宽任何段配额 ⇒ T1/T2 仍成立；校正后 `budget`/`truncated`/`dropped` 观测描述**校正后**的最终状态（与 §3.15③ 同口径） |

**与 I-3 `degraded` 的区别（冻结）**：`truncated.<段>.degraded` 是**段级**裁剪降级（`empty_guard`）；`over_window` 是**Prompt 级**的校验失败标记 —— 两者层级不同，**不合并**为同一字段，避免语义混淆。

### 3.18 设计补充 E：逐组件通道「执行路由」的落点语义（解 I-6，v1.6.1）

> **目的**：§3.9 已定「逐组件裁决 + 每组件通道标签 + 与整体偏好兼容」，但未定**在本仓（OpenLLM）里「切换」究竟切什么** —— 而这一点直接决定实现是否会在同一进程内伪造 A 拓扑身份。属契约的一部分 ⇒ 先冻结后实施。

| 项 | 冻结内容 |
|----|----------|
| 拓扑事实 | 本仓＝**编排/B 侧**；「走 A ⇒ **OpenBase 直连**」由**直连拓扑**（`openbase-llm-proxy` 来源）承担 —— 不在本仓调用链内 |
| 本仓 I-6 的实现边界 | **逐组件裁决 ＋ 标签发布 ＋ 结果回写**三件事：① 取数前按组件裁决 `channel`（默认＝整体 `CHANNEL_PREFERENCE`；**该组件**连续失败达阈值 ⇒ **仅该组件**切另一通道）；② 标签经 `result.channels.<组件>` 与 handler 参数 `_channel` **发布**给调用方/A 直连路径；③ 该组件成败**按组件**回写计数（成功清零） |
| **不做**的事 | **不在本仓切换出站拓扑** —— `X-Proxy-Source` 恒为 `openbase-orchestrator`（B 侧身份）；在同一进程内伪造 `openbase-llm-proxy` 会**破坏 K07 对账与 AB 等价断言**（违背 v1.4.8 已冻结的身份面契约） |
| 开关 | `COMPONENT_CHANNEL_ROUTING_ENABLED` **默认关闭**：关闭 ⇒ `channels` 为空、**不**注入 `_channel`、**不**按组件回写（与现状**逐字一致**） |
| fail-safe | 裁决器不可用 / 抛异常 ⇒ **回落整体 `CHANNEL_PREFERENCE`**（不把请求打挂），并（仅在开启时）以 `channel_source="overall_fallback"` 落痕 |
| 阈值与隔离 | 每组件**独立**计数与阈值（默认沿用 `_DEFAULT_CONSECUTIVE_FAILURE_THRESHOLD`）；**互不覆盖**、**不**影响整体 `_b_consecutive_failures`（后者仍服务请求级 B→A 链，语义不变） |
| 观测 | 轨迹/回执可见**每组件通道**（`channels: {组件: {channel, failures, threshold, switched, source}}`）；与既有 `rag_source` 口径**不冲突**（不改其取值域） |
| 与既有能力边界 | 不改 §4.2 组件决策（选哪些组件）；不改 W4 `describe_channel_report`（状态上报与建议）；不改四系统接口 |

## 4. 失败处理与降级总表

| 场景 | 行为 | 可观测性 |
|------|------|----------|
| 窗口未知 | 不裁剪（与 v1.4.8 一致） | 回执标记原因 |
| 裁剪后为空 | 保底注入（degraded=empty_guard） | 回执标记 |
| 仍超窗 | 硬截断 → 仍失败则判失败 | 回执 `hard_truncated`/失败标记 |
| 回执写入失败 | **fail-open**：不改变业务结果，仅 WARN | 日志告警 |
| 值判定服务不可用 | 保守**不写入**（防污染优先） | 拦截率指标 |
