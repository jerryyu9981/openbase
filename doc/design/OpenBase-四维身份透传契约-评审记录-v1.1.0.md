## 6. 评审发现问题清单（需修订后批准）

| # | 严重级 | 问题 | 位置 | 修订要求 |
|---|:------:|------|------|---------|
| F1 | 高 | 值域矛盾：正则允许 `_`，禁止列表又含 `_`；LIKE 中 `_` 为通配符，存在注入面 | §4.2 | 段值域改为 `^[a-zA-Z0-9]{1,64}$`（禁 `_`/`%`/`-`/`/`）；查询转义保留为双保险；同步 §3.2 术语表 |
| F2 | 高 | 安全缺口：上游端口若对外暴露，攻击者可绕过 OpenBase 直连上游并伪造三头，隔离失效 | §9/§7.4 边界 | 新增强制条款：四系统上游端口仅对 OpenBase 网关网络开放（防火墙/容器网络隔离），不对外暴露；OpenRAG 8010 在 M1 落地前必须网络隔离；TC 增加"直连上游被拒"断言 |
| F3 | 高 | 语义矛盾：§5.1 agent_id"当前上下文智能体"与 JWT 静态签发（登录时无"当前智能体"概念）冲突；多团队/多智能体切换机制未定义 | §5.1/§4.3 | 明确"JWT 承载静态身份（user/tenant/主团队），X-Scope 由网关基于请求上下文动态推导（团队/智能体切换经上下文请求，不重签 JWT）"；JWT 的 team_id/agent_id 语义改为"主团队/初始上下文（可为 `-`）"；TC-HDR-001 断言改为"X-Scope 与当前上下文一致，tenant 段 = JWT tenant_id" |
| F4 | 中 | 规则缺失：前缀匹配无层级边界规则（不完整段前缀如 `{t}/te` 可误匹配跨层数据） | §7.4 | 补充：前缀必须完整到某层级段并以 `/` 结尾（精确匹配除外）；禁止不完整段前缀 |
| F5 | 中 | 表达式缺失：存量无归属数据的"租户根节点"未给出定长 scope 表达式 | §11.3 | 明确无归属数据 scope = `{tenant}/-/-/-` |
| F6 | 中 | 断言歧义：TC-ISO-001 用户聚合视图未限定团队上下文（多团队用户跨团队聚合语义未定义） | §12.1 | 聚合视图限定当前团队上下文；多团队并集语义在 §4.3 明确定义（按 F3 上下文机制） |
| F7 | 低 | 冗余未说明：X-User-Id 与 X-Scope 第 3 段重复 | §6.1 | 契约注明保留理由（审计索引/快速解析），或评估合并 |
