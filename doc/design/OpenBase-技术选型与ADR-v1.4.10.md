## 2. ADR 记录

### ADR-1410-01（后端）：**在既有 `dps_proxy` 扩展路由，不新增代理服务**

| 项 | 内容 |
|----|------|
| **上下文** | 需向本仓暴露 DPS v2.11.0 新增 **10 端点**；本仓已存在 `dps_proxy`（12 路由，四头注入 ＋ 错误适配 ＋ 隔离口径均已就位） |
| **备选 A** | 新增独立代理服务（独立进程／端口） |
| **备选 B ✅** | **在既有 `dps_proxy` 扩展 10 条路由，复用 `_forward()` 与 `_build_identity_headers()`** |
| **决策** | 采 **B** |
| **理由** | ① 复用**已联调通过**的注入与适配链路（v1.4.5 基线），风险最低；② 零新增部署单元与运维面；③ 满足「前端零直连／零密钥」 |
| **已知后果** | `dps_proxy/__init__.py` 体积增大（现 ~600 行 → 约 900 行）⇒ 登记**可维护性观察项**（若超 1200 行需考虑拆分路由模块，留待后续版本） |
| **风险** | 单文件承载 22 条路由的可读性下降 ⇒ Step 3 须保持「一路由一函数 + 统一 `_forward` 调用」的既有风格 |

### ADR-1410-02（后端）：**4xx/5xx 语义原样透传，不做统一包装**

| 项 | 内容 |
|----|------|
| **上下文** | DPS 契约 §4 定义 **7 类错误码**（400／401／403／404／409／422／503），语义各不相同 |
| **备选 A** | 统一转换为本仓错误码／统一 500 |
| **备选 B ✅** | **原样透传（保 `code`／`message`／`data`）** |
| **决策** | 采 **B** |
| **理由** | ① 契约 §4 的语义（如 409 = 未复核门禁／code 冲突、503 = 适配器降级非阻塞）**前端业务判断依赖**；② 统一包装会丢失可判性，使前端无法区分「不可重试」与「可重试」；③ 复用既有 `_adapt_response()` 已具备该能力 |
| **已知后果** | 前端须**逐码处理**（`core/api/error.ts` 已支持）；测试须逐码构造用例 |
| **风险** | 若上游新增错误码而前端未覆盖 → 需兜底分支（UI 设计中已定义 5xx 兜底） |

### ADR-1410-03（集成）：**AI 复核的 LLM 能力经 `llm_proxy` 转发 OpenLLM**

| 项 | 内容 |
|----|------|
| **上下文** | AI 标注复核需 LLM 判定／建议能力；用户在 **A-1410-01** 裁定「复用 OpenLLM 通道的 LLM 能力」 |
| **备选 A** | 让 DPS 侧新增 LLM 复核端点 |
| **备选 B** | 前端直连 OpenLLM |
| **备选 C ✅** | **经本仓既有 `llm_proxy` 转发（`POST /openllm/v1/chat`）** |
| **决策** | 采 **C**（用户裁定） |
| **理由** | ① **`llm_proxy` 已是完整 OpenLLM 通道**（`/models`／`/chat`／`/chat/stream`／`prompt-assembly/*`／`conversations/*`）⇒ **后端零新增**；② 前端零密钥、身份统一由本仓注入；③ 不扩 DPS 范围（D-1410-02 边界下的最小动作） |
| **已知后果** | P-08 页面**跨两个上游**（DPS 生成候选 ＋ OpenLLM 复核辅助）⇒ UI 须明确标识数据来源与降级语义 |
| **风险** | `llm_proxy`→OpenLLM 链路**未实测** ⇒ 联调时验证（第三方集成设计 §7） |

### ADR-1410-04（集成）：**org 走别名值映射传真，禁用强模式**

| 项 | 内容 |
|----|------|
| **上下文** | DPS 要求 `X-Org-ID` 为**真实且存在的组织**（双头必填 ＋ 租户归属校验）；本仓 `X-Org-ID` 为 OB-8 退役别名（默认 = tenant 值）；实测 `.env` 未配任何映射 |
| **备选 A** | 开启 `enforce_org_alias=True`（强制 `org == tenant`） |
| **备选 B ✅** | **保持 `False`，经 `dps_org_map`／`dps_code_map` 传真真实 org** |
| **决策** | 采 **B** |
| **理由** | ① 强模式在 `inject.py:198-208` **要求 `org == tenant`**，与「传真 org」**互斥**；② DPS 侧 org／tenant 本就是**不同 code**（`dps-org-001` vs `dps-tenant-001`）⇒「org == tenant」不可行；③ 映射是基准 B5 的既有能力，零代码改动 |
| **已知后果** | **必须配 `dps_org_map`（P1 联调前置）**；且须**防止误开强模式**（否则联调直接 403） |
| **风险** | 配置缺失或误开是**本版最高频的两个联调失败点** ⇒ 已列入发布入场检查项 |

### ADR-1410-05（前端）：**不引入新技术栈与全局状态库**

| 项 | 内容 |
|----|------|
| **上下文** | 本版新增 8 类页面，涉及列表／对比／预检／导入导出等交互 |
| **备选 A** | 引入 Pinia 之外的额外状态库／组件库／表单库 |
| **备选 B ✅** | **沿用现有 Vue ＋ `core/stores`（auth／moduleRegistry／ui）＋ 组合式函数承载页面级状态** |
| **决策** | 采 **B** |
| **理由** | ① 本版为对接深化，页面间**无跨页共享状态**（除既有 auth／moduleRegistry）；② 新引入依赖会**扩大回归面与构建面**（与"不改视觉规范与设计系统"的边界一致）；③ 复用 `core/api/http.ts` ＋ `error.ts` 已满足数据与错误处理需求 |
| **已知后果** | 复用的加载／错误／空态逻辑以**组合式函数**抽取（Step 3 落地），避免逐页重复 |
| **风险** | 若后续版本出现跨页共享的 DPS 域状态，再评估引入专用 store（登记为演进点） |

### ADR-1410-06（前端）：**影响面 `basis` 采折叠/气泡呈现**

| 项 | 内容 |
|----|------|
| **上下文** | 契约 §3.7 要求预检／影响面的三项指标**必须随报告返回 `basis`** 且口径「**可复核、非隐式**」；`basis` 为「指标 → 口径说明」字典（技术性文本） |
| **备选 A** | 常显（直接列在指标下） |
| **备选 B ✅** | **折叠/气泡（默认收起，点「口径」展开）**（用户 **A-1410-03** 裁定） |
| **备选 C** | 不显示（❌ 违反契约「非隐式」） |
| **决策** | 采 **B** |
| **理由** | ① 满足契约可复核要求（信息可达）；② 技术性文本不干扰运营人员阅读主指标；③ **审计导出时提供完整原文**，兼顾审计取证 |
| **已知后果** | 组件需支持「可访问的展开控件」（键盘可达 ＋ `aria-expanded`） |
| **风险** | 若折叠过深导致复核者遗漏 ⇒ 在 `tag_count = 0` 等**易误判场景强制展开**提示（UI 设计已定义） |
