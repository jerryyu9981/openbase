## 3. 总体架构

```
┌─────────────────────────────────────────────────────────────┐
│                    统一前端（OpenBase UI v1.2.0）              │
│  ┌─────────────────────────────────────────────────────────┐ │
│  │ 公共底座：布局(侧边栏/顶栏/内容区) + 设计系统 + 路由 + 状态  │ │
│  │ 动态模块注册表（懒加载/权限）  │  统一鉴权(Axios 拦截器)    │ │
│  ├─────────────────────────────────────────────────────────┤ │
│  │ 特色动态模块                                             │ │
│  │  OpenLLM模块  │ OpenRAG知识库 │ OpenMemory记忆 │ DPS画像  │ │
│  └───────────────┴──────────────┴──────────────┴───────────┘ │
└─────────────────────────────────────────────────────────────┘
        │ JWT + ErrorResponse 契约（OpenAPI 客户端）
┌─────────────────────────────────────────────────────────────┐
│              OpenBase 后端（v1.1.0 稳定底座）                 │
│  auth(登录/刷新)  notifications  mcp  audit  tenant  config  │
│  [v1.2.0 增量] ai-apps(应用管理)  proxy(四系统特色API网关)     │
└─────────────────────────────────────────────────────────────┘
        │ 各系统原生 API（经 openbase 网关/代理）
┌───────────────┬───────────────┬───────────────┬──────────────┐
│    OpenLLM    │    OpenRAG    │   OpenMemory  │     DPS      │
│ (对话/模型/   │ (知识库/文档/ │ (记忆/衰减/   │ (画像/标签/   │
│  用量/监控)   │  检索/评估)   │  图谱/会话)   │  报表/批量)   │
└───────────────┴───────────────┴───────────────┴──────────────┘
```

架构分层原则：前端只与 openbase 后端通信（统一入口/统一鉴权/统一错误契约）；四系统特色 API 经 openbase 网关代理转发，前端不直连四系统，保证单点认证与契约收敛。

## 4. 技术选型 ADR

### ADR-12-01 前端框架选型

| 项 | 内容 |
|----|------|
| 决策 | 统一前端采用 **Vue 3 + TypeScript + Vite + Pinia + Vue Router + Element Plus** |
| 上下文 | 四系统前端技术栈盘点：OpenLLM（Vue3+Element Plus）、OpenRAG（Vue3 系）、OpenMemory（Vue 系原型）、DPS（无现成前端）。多数系统为 Vue3 生态，抽取复用成本最低 |
| 备选方案 | A. React 18 + Ant Design（组件生态强但抽取需重写）；B. 多框架微前端（qiankun，隔离强但复杂度高） |
| 决策理由 | ①四系统 3/4 为 Vue 生态，组件/布局抽取直接复用 ②统一技术栈降低学习与维护成本 ③Vite 构建快，符合前端质量门禁（Lint/覆盖率） |
| 后果与风险 | 风险 R-201 降低（抽取适配成本最小化）；Element Plus 定制统一风格需设计系统约束；微前端隔离能力缺失（本版本动态模块用注册表+懒加载替代，满足需求） |

### ADR-12-02 动态模块机制选型

| 项 | 内容 |
|----|------|
| 决策 | 采用 **模块注册表（manifest）+ 路由级懒加载（动态 import）+ 权限指令** 的轻量动态模块机制，不引入微前端框架 |
| 上下文 | 需求 FR-12-03：特色模块可注册/卸载、懒加载、按权限展示 |
| 备选方案 | A. 微前端（qiankun/module federation）强隔离；B. npm 包按需加载 |
| 决策理由 | ①四模块同仓库同技术栈，无需进程级隔离 ②注册表+懒加载满足"挂载/卸载/按权限"需求且复杂度低 ③避免微前端样式隔离与通信成本 |
| 后果与风险 | 模块间需遵守依赖规范（禁止跨模块直接引用内部状态）；模块升级走统一构建 |

### ADR-12-03 状态管理与契约生成

| 项 | 内容 |
|----|------|
| 决策 | Pinia（状态）+ Axios 拦截器（鉴权/错误统一）+ **openapi-typescript 由 openbase 后端 openapi.json 生成客户端类型** |
| 上下文 | 需求 FR-12-04：JWT 登录态管理、ErrorResponse 契约对齐 0 缺口 |
| 备选方案 | Redux Toolkit（React 生态）；手工手写 API 类型（易漂移） |
| 决策理由 | 契约以 OpenAPI 为唯一事实源，生成类型避免前后端契约漂移（对应债务 TD-新增-005 偿还） |
| 后果与风险 | openapi.json 变更需重新生成类型（纳入 CI 门禁） |

## 5. 公共底座设计（DT-12-01/02/11）

### 5.1 抽取清单（RT-201）

| 来源系统 | 可抽取资产 | 复用处 |
|---------|-----------|--------|
| OpenLLM（Vue3+Element Plus） | 布局骨架（侧边栏/顶栏）、表格组件（筛选/分页/多选）、图表封装（ECharts 趋势/分布）、监控指标卡、弹窗规范 | 底座布局/列表页/图表/监控模块 |
| OpenRAG | 上传组件（拖拽/进度/重试）、分块预览、卡片列表、空态组件 | 知识库模块/通用上传 |
| OpenMemory | 时间线组件（WaypointTimeline）、状态色规范、衰减权重着色 | 记忆模块/通用状态 |
| DPS | 无现成前端，按 API 全新设计（画像/标签/报表/批量） | 画像模块 |

抽取规则：组件级复制后按统一设计系统重构（token 替换），不允许直接引入原系统样式表；抽取清单 + ADR 作为 Phase 1 交付物。

### 5.2 布局与风格（RT-202）

- 布局：侧边栏（可折叠）+ 顶栏（用户/通知/主题）+ 内容区；三端断点见 §5.5
- 风格体系：色板（主色/功能色/状态色）、字体（系统字体栈+数字字体）、间距（8px 栅格）、圆角/阴影 token；设计系统 token 见 UI 设计文档
- 路由：vue-router 集中注册，公共路由（登录/仪表盘/系统管理）+ 动态模块路由（注册表注入）
- 状态：Pinia 分域（auth/user/moduleRegistry/ui），模块状态隔离命名空间

### 5.3 组件库

- 基于 Element Plus 封装统一业务组件：DataTable（筛选/分页/多选/导出）、Uploader（拖拽/批量/进度/重试）、ChartCard（ECharts 封装）、StatusTag、ConfirmModal、EmptyState、PageHeader 等
- 组件规范文档化（props/events/slots/样式 token），见 UI 设计文档设计系统章节

### 5.4 统一鉴权与契约（DT-12-04）

| 项 | 设计 |
|----|------|
| 登录 | POST /api/v1/auth/login（admin/admin123 基线）→ JWT access/refresh 存安全存储 |
| 刷新 | 401 时静默刷新（refresh token），失败跳登录 |
| 拦截器 | Axios 请求注入 Bearer；响应统一解包 data，错误映射 ErrorResponse{code,message,detail,request_id} |
| 契约 | openapi-typescript 由后端 openapi.json 生成客户端，CI 校验类型漂移 |
| 权限 | 前端路由守卫 + 模块权限（permission 指令）按 RBAC 角色控制 |

### 5.5 响应式设计（DT-12-11，RT-211）

| 断点 | 布局策略 |
|------|---------|
| ≥1280（桌面） | 侧边栏常驻，内容栅格 12 列，表格正常显示 |
| 768-1280（平板） | 侧边栏可折叠为抽屉，栅格 8 列，表格横向滚动 |
| <768（移动） | 侧边栏抽屉 + 汉堡按钮（≥44px），栅格 4 列，卡片化，图表自适应高度，触控目标 ≥44px |

通用：栅格系统（12/8/4）、表格横向滚动封装（DataTable 内置）、图表 resize 监听（ChartCard 内置）、弹窗宽度 ≤ 屏宽-32px。

## 6. 动态模块机制（DT-12-03）

```
module-manifest.json（注册表：模块ID/名称/图标/路由前缀/权限标识/入口文件）
        │ 启动时读取
        ▼
ModuleRegistry（Pinia store）
   ├─ 注册：动态 import('modules/{id}/index.vue') 懒加载
   ├─ 卸载：移除路由 + 清理 store 命名空间
   └─ 权限：permission 指令按 RBAC 角色过滤菜单与路由
```

| 模块 | 模块ID | 路由前缀 | 权限标识 |
|------|--------|---------|---------|
| OpenLLM | openllm | /openllm | openllm:view |
| 知识库 | openrag | /knowledge | openrag:view |
| 记忆 | openmemory | /memory | openmemory:view |
| 画像 | dps | /portrait | dps:view |

验收对应 AC-12-03：注册/卸载生效、懒加载验证（首屏不加载模块 chunk）、按权限展示。

## 7. 四系统集成架构（第三方集成轨道，DT-12-04/05~08）

### 7.1 代理模式

```
统一前端 ──► openbase 后端 /api/v1/proxy/{system}/{path}（JWT 校验后转发）
                  │
                  ├─► OpenLLM   （对话/模型/用量/监控 API）
                  ├─► OpenRAG   （知识库/文档/检索/评估 API）
                  ├─► OpenMemory（记忆/衰减/召回/图谱 API）
                  └─► DPS       （画像/标签/报表/批量 API）
```

- 代理转发：后端校验 JWT → 按 system 路由表转发 → 透传响应（统一 ErrorResponse 包装）
- 系统 API 版本：OpenLLM /openllm/v1 + /api/v1、OpenRAG /api/v1、OpenMemory /api/v1、DPS /api/v2
- 契约收敛：Step 2 按四系统 OpenAPI 逐一核对代理路径与参数（知识库 29 端点/记忆 50 端点/画像 52 端点），超出 v1.2.0 范围登记 backlog
- 鉴权传递：openbase JWT 与四系统会话映射（config 模块管理各系统 API Key 凭据，密钥不落前端）

### 7.2 AI 应用后端增量（全新补建）

| 项 | 设计 |
|----|------|
| 表 | openbase.ai_apps（应用）、openbase.ai_app_versions（版本）、openbase.ai_app_calls（调用记录） |
| API | /api/v1/ai-apps CRUD + /api/v1/ai-apps/{id}/publish + /api/v1/ai-apps/calls |
| 绑定 | 应用绑定模型（provider/model 配置串）+ Prompt 模板 + 参数（temperature/top_p 等） |
| 说明 | OpenLLM 无此模块，openbase 后端提供最小 API，前端全新设计页面（见前端架构文档） |

## 8. OpenLLM 板块重设计 ADR（DT-12-05，用户指示）

> 用户指示：OpenLLM 功能较多，按 OpenLLM 功能定位重新设计功能板块分类与布局。

### 8.1 板块重设计原则

OpenLLM 独立前端原 5 组菜单（工作台/模型中心/AI 工具/路由与监控/系统管理，52 路由页面）中，凡属于**统一前端公共能力**的（用户/角色/租户/审计/配置/Webhook/计费等）上移为底座级"系统管理"；凡属于 **OpenLLM 特色业务**的（模型接入/应用编排/对话监控/路由策略）保留为 OpenLLM 模块内板块。

### 8.2 重设计后的 OpenLLM 板块结构（布局方案）

| 板块 | 一级菜单 | 二级页面 | 来源 |
|------|---------|---------|------|
| 大模型接入 | 模型管理 | 模型列表/详情、本地模型（Ollama 拉取/启停/GPU 占用）、开源模型市场、模型分类/对比/下载/收藏 | OpenLLM 模型中心 9 页重排 |
| 大模型接入 | 提供商 | 提供商列表/详情、注册向导（多步）、API 密钥管理 | OpenLLM 提供商/API Key |
| 大模型接入 | 部署与资源 | 模型部署向导、GPU 资源监控、EdgeRouter 适配器 | OpenLLM 部署/GPU/适配器 |
| AI 应用 | 应用管理 | 应用列表/创建/详情、发布/下架/版本、调用记录 | 全新补建 |
| AI 应用 | 调试与 Prompt | Playground、Prompt 模板、Prompt 实验 | OpenLLM AI 工具页 |
| 对话监控 | 对话管理 | 对话列表/详情、流式对话（SSE）、导出/批量删除 | OpenLLM 对话管理 |
| 对话监控 | 监控中心 | 监控仪表盘、链路追踪、指标查询、成本分析、预算、告警 | OpenLLM 路由与监控页 |
| 平台联动 | 路由治理 | 路由策略、语义/级联路由、熔断器、A/B 测试 | OpenLLM 路由页（经动态模块挂载） |

布局决策：模型接入与提供商合并为"模型中心"一级菜单下的两个子分组，避免平铺 9 页；部署与资源独立成组（GPU/适配器/部署向导强关联）；"AI 应用"独立一级菜单（全新能力，突出产品定位）；对话监控收敛为"对话管理+监控中心"两分组；路由治理作为平台联动二级（深度对接部分登记 backlog）。菜单结构与页面布局以本设计为基准，Step 3 实现对照执行。

### 8.3 板块设计 ADR 记录

| 决策 | 备选 | 理由 |
|------|------|------|
| 板块按"模型接入/应用编排/对话监控/平台联动"四大域重组 | 保持 OpenLLM 原 5 菜单 | 原菜单混合公共与特色，重组后公共能力上移底座、特色按业务域聚类 |
| AI 应用独立一级菜单 | 并入工具页 | 全新产品能力需要独立入口与权限 |
| 路由治理降为二级挂载 | 保持一级 | 本版本深度对接部分登记 backlog，降低首版复杂度 |
