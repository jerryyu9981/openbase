## 4. 逐项评审意见（Q1~Q5）

### Q1 metrics token 下发方式

- **意见**：采用「**token 必选 + CIDR 可选叠加**」，token 经现有密钥管理/K8s Secret 下发，
  支持 CURRENT/PREVIOUS 双 token 轮换（重叠期 ≤7 天）。
- **理由**：五系统共用同一主机/网段，单纯 CIDR 无法区分服务；单纯 token 一旦泄露影响面过大。
  双因子成本低且可运维。
- **对方案的调整**：H3 的生产口径由「token 或 trusted-source」改为「token 为最低要求，
  CIDR 非空时作为 AND 条件」；配置表新增 `OPENLLM_METRICS_TOKEN_PREVIOUS`。
- **责任方**：OPS（下发）/ LL（实现）。

### Q2 `/openllm/v1/health` 是否纳入豁免登记

- **意见**：**不纳入**。豁免登记表保持 5 条，与 K07 矩阵一一对应；该端点在 K07 中标注为
  「受信管理面（非豁免）」；其限流豁免收紧为仅受信来源。
- **理由**：该端点返回 `components`、`channel`、`channel_report`，敏感度高于 `/health`；
  纳入豁免等于扩大 R4 暴露面，且会破坏登记表与 K07 的一致性。
- **对方案的调整**：H8 增加第 4 条；验收新增 AC-12。
- **责任方**：LL（实现）/ 评审组（分类确认）。

### Q3 网络层 ACL / NetworkPolicy 归属

- **意见**：**OPS 所有**。落地三层控制：监听地址收紧、主机防火墙/安全组、K8s `default-deny`；
  同宿主场景优先端口/进程级隔离；至少一项控制证据留档。
- **理由**：五系统同宿主，网段 ACL 区分度有限；应用层 token 是主控制，网络层用于缩小可达面。
- **对方案的调整**：§3 增加 Q3 落地口径；验收新增 AC-13。
- **责任方**：OPS（证据）/ LL（来源清单）。

### Q4 `client_ip` 审计留存与隐私

- **意见**：完整 IP 仅写入安全审计域，默认保留 **90 天**，仅安全/审计角色可查；提供
  `full|hashed|masked` 三种模式，默认 `full`；普通应用日志不重复记录。
- **理由**：完整 IP 对溯源不可替代；脱敏会削弱 R5 的审计价值。若合规要求更严，可使用带密钥的
  HMAC 哈希，兼顾可关联与不可逆。
- **对方案的调整**：H5 隐私说明改写；配置表新增 `OPENLLM_EXEMPT_AUDIT_IP_MODE` 与
  `OPENLLM_EXEMPT_AUDIT_RETENTION_DAYS`。
- **责任方**：安全/合规（口径）/ OPS（执行）。

### Q5 豁免机制长期替代方案

- **意见**：短期保留 5 行豁免并完成 H1~H8；中长期（两个版本内）改为**独立管理监听端口**
  （127.0.0.1:9xxx），承载 health/metrics，逐步退役路径豁免。
- **理由**：路径豁免是结构性风险，H1~H8 只能收敛不能消除；独立管理端口可从架构上消除 R1/R4/R6。
- **对方案的调整**：§11.3 增加三阶段路线与退出判据。
- **责任方**：LL 架构组；**不阻塞当前发布**。
