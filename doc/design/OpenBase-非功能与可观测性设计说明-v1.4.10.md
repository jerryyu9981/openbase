## 1. 非功能需求落地映射

| NFR | 要求 | 设计落地 | 验证（→ Step 4） |
|:---:|------|----------|------------------|
| **NFR-01** | 代理不引入可观测退化 | 纯转发（无业务计算）＋ 复用既有客户端 | 抽样 ≥30 次/端点 |
| **NFR-02** | 首请求 ≤ 热态 P95 量级 | **已由 OpenLLM v2.14.4 交付**（`lifespan` 预热） | 60 轮抽样对比 2,150 ms |
| **NFR-03** | 零密钥／零凭据 | 前端零接触 ＋ 日志禁落清单 | 代码检索 ＋ 日志抽查 |
| **NFR-04** | 隔离呈现（空／403，无 500） | 租户隔离沿用 ＋ 403 语义化呈现 | E2E 隔离回归 |
| **NFR-05** | 兼容性（既有 12 路由 ＋ 画像 2 页） | **仅新增，不改既有** | 既有用例回归 |
| **NFR-06** | 上游不可用**明确呈现**（不静默降级） | 5xx 兜底分支 ＋ 重试入口 | 异常场景用例 |
| **NFR-07** | 页面↔端点映射 **100%** | 8 页 × 10 端点映射表 | 映射表逐项核对 |
| **NFR-08** | 结构化日志占比提升 | **跨仓 OpenLLM v2.14.4 已交付**（`SQL_ECHO` 与 `DEBUG` 解耦） | 日志统计对比 |
| **NFR-09** | 覆盖率门禁达标 | 沿用 S6 口径 | 门禁脚本 |

## 2. 可观测性设计（对齐 `observability-standards`）

### 2.1 日志（Logging）

| 标准项 | 本版落地 |
|--------|----------|
| 结构化 JSON | **沿用既有日志装配**（本仓为新路由，不引入新日志格式） |
| 必备字段（`traceId`／`spanId`／`service`／`module`／`message`） | 沿用；`module` 取 `dps_proxy` |
| **`request_id` 串联** | `X-Request-Id` **透传上下游**（既有 `_request_id_of`），支持跨系统链路定位 |
| 禁落字段 | 沿用 `SENSITIVE_FIELD_KEYS`（密码／令牌／api_key／authorization） |
| **跨仓改善（已交付）** | OpenLLM v2.14.4：关闭 `sqlalchemy.engine` echo（原 `echo=DEBUG`）⇒ 消除日志淹没与敏感面扩大 |

### 2.2 指标（Metrics）

| 标准项 | 本版落地 |
|--------|----------|
| 14 种关键指标 | **沿用既有代理层指标**（`http_requests_total`／`http_request_duration_seconds` 等）；**10 条新路由复用同一中间件自动计入**，不新增指标名 |
| 端点级可观测 | 依赖既有指标中间件的 `path` 标签 ⇒ 新增端点**自动可见**，无需改动 |
| **评估（如实登记）** | 本版**未新增**业务维度指标（如需按端点族细分，登记为后续演进项） |

### 2.3 追踪（Tracing）

| 标准项 | 本版落地 |
|--------|----------|
| OTLP 协议 ／ W3C TraceContext | 沿用既有装配 |
| **跨系统传播** | `X-Request-Id` ＋ 既有 trace 上下文透传至 DPS；**DPS 侧具备同名字段**（`request_id`）⇒ 可跨系统定位 |
| 采样 | 沿用（生产 10% ／ 错误 100%） |

### 2.4 Dashboard 与告警

| 标准项 | 本版落地 |
|--------|----------|
| 6 个必备 Dashboard | 沿用既有（Service Overview／Resource／Dependencies／Business／Errors／Alert History） |
| **新增告警** | **无**（新路由复用既有端点级告警规则） |
| 排障上下文 | `request_id` 串链 ＋ 4xx/5xx 语义保留 ⇒ 可从告警直达上游错误 |

### 2.5 可观测性覆盖检查表（逐项）

| # | 检查项 | 结论 |
|:-:|--------|:----:|
| 1 | 日志结构化 JSON | ✅ 沿用（无新格式） |
| 2 | 14 种关键指标覆盖 | ✅ 复用中间件自动计入 |
| 3 | OTLP／W3C 追踪 | ✅ 沿用 |
| 4 | 6 个 Dashboard | ✅ 沿用 |
| 5 | 错误码可定位 | ✅ 4xx/5xx 语义保真 ＋ `request_id` |
| 6 | 排障上下文（跨系统） | ✅ `X-Request-Id` 透传 |
| 7 | 新增告警 | ⬜ **不适用**（复用既有规则） |
| 8 | 业务维度指标 | ⬜ **本版未新增**（如实登记为演进项） |

## 3. 其他非功能面

| 面 | 结论 |
|----|------|
| **可维护性** | 复用既有模式（一路由一函数）；`dps_proxy` 体积增长登记为观察项（ADR-01） |
| **可用性** | 无新增单点；代理层无状态 |
| **兼容性** | 仅新增路由；既有 12 路由与画像 2 页行为不变 |
| **国际化** | 不涉及（中文界面沿用） |
| **备份恢复** | 本版无存储变更 ⇒ 沿用既有策略 |

## 4. 与既有标准的偏差登记

| # | 偏差 | 级别 | 处置 |
|:-:|------|:----:|------|
| 1 | 未新增业务维度指标（如 `dps_proxy_*_total`） | P3 | **本版不新增**（范围纪律）；登记为演进项 |
| 2 | 新增路由未新增专属告警 | 说明项 | 复用既有端点级规则即可；**不构成缺口** |
| 3 | `dps_proxy` 单文件体积增长 | P3 | 观察项（ADR-01）；超阈值再拆分 |
