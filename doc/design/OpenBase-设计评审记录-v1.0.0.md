## 5. 争议与决策

| # | 争议点 | 决策 | 依据 |
|---|--------|------|------|
| D1 | 异步 vs 同步 SQLAlchemy | 异步优先（AsyncSession） | 与 FastAPI 异步原生一致，三系统已验证异步模式 |
| D2 | 多租户隔离粒度 | Schema 隔离（每租户 Schema） | OpenMemory EdgeRouter 全栈抽取（成熟度最高） |
| D3 | 用户删除策略 | 软删（is_deleted） | 审计与历史数据关联保留 |
| D4 | 配置缓存 | 无 TTL，变更失效 | 配置变更低频，保证强一致 |

### 7.2 开发注意事项（移交给 AD）

1. 模块实现顺序遵循 Phase 计划：Phase 1 审计定源 → Phase 2 内核 → Phase 3/4 核心模块 → Phase 5 补齐+工具链 → Phase 6 发布
2. 数据模型以数据库设计文档为基准（14 张表），字段/约束/索引对齐
3. API 以 API 接口设计文档为契约（路径/参数/响应/错误码/权限点），Step 3 开头创建设计开发追溯矩阵
4. 模块必须遵循弱依赖（settings 配置驱动）与异步优先
5. 统一错误码格式 {code, message, request_id}
6. 管理接口设计已对齐 v1.2.0 前端契约（auth/tenants/dicts 等），不得随意变更

### 7.3 测试注意事项（移交给 AT）

1. 验收标准 AC-CORE/MOD/SUP/TOOL-xxx 映射测试用例（RT-ID 关联）
2. 性能验证：多租户路由 <1ms、中间件 <5ms、CRUD 等价 <5%（基准测试）
3. 安全验证：JWT/RBAC/越权/密码/密钥（SR-001~009）
4. 覆盖率门槛 ≥85%
5. 模块弱依赖验证 6/6（BL-015）
