## 5. 不适用项说明（设计规范矩阵逐项）

| 设计类别 | 结论 | 原因 |
|----------|:----:|------|
| Agent 架构设计 | 🚫 不适用 | 本版本不涉及 Agent/LLM 编排（无智能体角色、工具、多智能体关系） |
| 第三方集成设计 | 🚫 不适用 | 轨道 🔗 未激活（需求 §11：不调用四仓任何接口） |
| Figma 设计交付 | 🚫 不适用 | 无外部设计稿来源；原型以本地静态 HTML 交付（`prototype/logs.html`） |
| 缓存与消息设计 | 🚫 不适用 | 只读查询不需缓存（陈旧风险 > 收益）；无异步解耦需求（非功能 §7） |
| 数据库设计（新版本） | 🚫 不适用 | **零迁移**：不新增表/字段/索引；复用《数据库设计文档-v1.2.0》既有定义 |
| 独立设计系统文档 | 🚫 不适用 | 复用既有设计系统；仅 1 页，差异点已在 UI §6 说明 |
| 可访问性专项（全站） | 🚫 不适用 | 仅 1 新页，按 UI §7 四项要求执行，不做全站专项 |

> 上述 7 项均**不产生设计缺口**（逐项说明原因，符合"若某项不适用必须在设计评审记录中说明原因"）。

## 7. 评审意见与决策

| 意见 | 决策 |
|------|------|
| `logs` 模块独立 vs 扩展 `audit` 模块 | **采纳独立模块**：写链路（中间件/队列）与查链路（多源检索）职责分离，便于独立测试（ADR-146-01/§2.2） |
| L1 无索引如何保证响应时间 | **采纳"分片倒序 + 提前终止 + 显式截断"**；默认上限 2 分片 / 200,000 行；**禁止静默截断**（ADR-146-03） |
| 导出留痕与"只读"声明冲突 | **采纳留痕**（决议 2），并在需求文档 §5.3 精确表述为"只读，唯一例外是导出留痕"；留痕失败**不阻断导出**（ADR-146-04） |
| 是否引入全局 store / 缓存 | **不引入**（YAGNI）：单页自足，`ref` 本地状态；不做缓存（非功能 §7） |
| 是否拆分 5 个子组件 | **允许内联**：按体量决定物理拆分，避免过早抽象（前端架构 §2 注） |
| `total` 在截断时语义 | **明确**：`total` = 扫描上限内的命中数，须与 `truncated` 同读（API §3.1/§6） |
| 多选参数传参形态 | **采纳重复同名参数**（后端按 OR 解析），前后端一致（API §3.1 / 前端架构 §4） |

**无 P0/P1 设计缺口留待 Step 3。**
