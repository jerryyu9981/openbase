## 1. 性能目标（本版）

| ID | 目标 | 判据 | 来源 |
|:--:|------|------|------|
| **P-1** | **代理不引入可观测退化** | 新增 10 端点热态 **P95 ≤ 既有 proxy 端点同量级** | NFR-1410-01／AC-01 |
| **P-2** | 首请求不再承担惰性初始化 | 重启后首请求 ≤ 热态 P95 量级 | **已由 OpenLLM v2.14.4 交付**（`lifespan` 预热） |
| **P-3** | 前端页面可交互时间不劣化 | 首屏无新增阻塞依赖（**无新依赖**，ADR-05） | 架构 §3 |
| **P-4** | 大包导入不阻塞界面 | 提交态可见 ＋ 不自动重试 | 威胁 D（安全 §2） |

### 1.1 基线（v1.4.9 实测，**仅作量级参照**）

| 指标 | 值 | 说明 |
|------|----|------|
| 热态 P50 | **37.5 ms** | 既有服务实测 |
| 热态 P95 | **71.2 ms** | 同上 |
| 首请求（改造前） | **2,150 ms** | 唯一 ≥2s 样本；**已由 v2.14.4 预热前移** |

> ⚠ **口径说明**：DPS 侧端点的真实耗时**取决于其库内数据量与查询复杂度**（如影响面统计、血缘反查），可能显著高于上述基线。**P-1 只要求"不因本仓代理引入额外退化"**，不对 DPS 查询本身设时限。

## 2. 关键路径与瓶颈分析

```text
前端 → 本仓 dps_proxy（身份构造 ＋ 转发）→ DPS 端点 → DB
        └── 本仓开销：仅头构造 ＋ HTTP 转发（无业务计算、无落库）
```

| 路径 | 本仓开销 | 主要成本所在 | 结论 |
|------|----------|--------------|------|
| 只读端点（对比／预检／血缘／建议／评分类型） | **低**（转发） | **DPS 查询** | 本仓无需优化 |
| 写端点（导入／回滚） | 低（转发） | **DPS 事务 ＋ 校验** | 同上 |
| AI 候选生成 | 低（转发） | DPS ＋（可选）LLM 适配器 | 503 降级非阻塞 |
| 复核辅助（`llm_proxy`→OpenLLM） | 中（含 LLM 调用） | **LLM 推理** | 异步体验：可流式（`/chat/stream`） |

**瓶颈结论**：**本仓不是瓶颈**（纯转发层）；性能风险集中在 ① DPS 侧慢查询（不受本版控制）② LLM 推理延迟（走流式缓解）。

## 3. 设计对策

| 面 | 对策 |
|----|------|
| 转发层 | **复用既有 `_forward()`**（连接复用由既有 `httpx` 客户端承载）；**不新增中间层** |
| 超时 | 沿用既有 proxy 超时口径；**长耗时操作（导入/预检）由上游决定**，本仓不额外截断 |
| 并发 | 无本仓共享可变状态；**无并发写入**（透明代理） |
| 缓存 | **不引入本仓缓存**（避免与上游数据口径分叉；见前端架构 §3.2） |
| 流式 | AI 复核辅助优先用 `POST /chat/stream`（SSE 透传），改善感知延迟 |
| 前端 | **无新依赖**（ADR-05）⇒ 构建体积增量主要来自页面代码；页面级懒加载（Step 3 落地） |

## 4. 容量假设

| 项 | 假设 | 说明 |
|----|------|------|
| 并发用户 | 沿用既有 OpenBase 容量规划（**本版不改变**） | 代理层无状态，可水平扩展 |
| 单请求体 | 导入包可能较大（含模板与依赖） | 沿用上游限制；超限由 DPS 返回 4xx |
| 数据量 | 由 DPS 侧决定 | 本版不引入新数据表 |
| 峰值 | 无新增峰值场景 | 管理面操作为低频（人工触发） |

> **结论**：**本版不需要扩容**；代理层无状态 ＋ 无新存储 ⇒ 容量特征不变。

## 5. 测量与验证方案（→ Step 4）

| # | 项 | 方法 | 通过判据 |
|:-:|----|------|----------|
| 1 | 代理不退化 | 新增端点各抽样 **≥30 次**，统计 P50／P95 | 与既有 proxy 端点**同量级** |
| 2 | 首请求 | 重启后 **60 轮抽样**，记录最大样本 | ≤ 热态 P95 量级（对比 2,150 ms 基线） |
| 3 | 前端 | 构建体积对比基线；关键页首屏 | 无新增阻塞依赖 |
| 4 | 流式 | `chat/stream` SSE 首字节时间 | 明显优于聚合端点（体验判据） |

**证据要求**：原始数据留档于 `doc/test/evidence/v1410/`（Step 4 产出）。

## 6. 风险

| # | 风险 | 级别 | 缓解 |
|:-:|------|:----:|------|
| 1 | DPS 侧慢查询（影响面/血缘）导致体验差 | P2 | **明确非本仓问题**；如实反馈 DPS 侧（依 D-1410-02 可直接提改动） |
| 2 | 大包导入超时 | P2 | 提交态可见 ＋ 不自动重试；失败明确提示 |
| 3 | LLM 推理延迟影响 P-08 | P2 | 优先流式；`llm_proxy` 不可用时降级（不阻断提交） |
| 4 | 性能基线不可直接套用于 DPS 端点 | 说明项 | 已在 §1.1 声明「仅作量级参照」 |
