## 1. 目标与非目标

### 1.1 目标

1. **模板项可视化配置**：把当前 5 个 JSON 文本框（`dimension_config` / `attributes_schema` / `tag_bindings` / `evidence_policy` / `anomaly_rules`）改为结构化编辑器，业务人员可零 JSON 完成模板设计。
2. **规则引擎可视化**：条件组（AND/OR 可嵌套）+ 6 种打分规则的可视化编排，支持试运行与逐条报文。
3. **画像可读**：单主体 360 视图，直观呈现维度得分、标签分组、命中证据、时间线与数据完整度。
4. **契约不破坏**：P0 仅改前端，写回仍是现有 JSONB 结构；后端仅新增只读校验/试算接口（P1）。

### 1.2 非目标

- 不改造 DPS 打分算法与评分白名单（`ScoringDispatcher` 仍是唯一裁决者）。
- 不引入可视化拖拽 DSL 编译器（P2 再评估）；P0/P1 的规则仍落为现有 JSON。
- 不做标签加工调度、数据源接入（属标签工厂域，另行立项）。

## 2. 对标分析与设计原则

| 参考产品 | 可借鉴能力 | 本项目落地 |
|---|---|---|
| 阿里云 Dataphin 标签工厂 | 标签定义→加工→质量→服务四段式；维度/标签分层 | 模板工作台按「维度 → 标签绑定 → 证据 → 异常」分段 |
| 腾讯云 / 阿里画像平台 | 人群画像 360、标签树分组、覆盖度 | 画像视图采用「身份卡 + 雷达 + 分组标签 + 证据」 |
| 神策用户标签 | 规则标签可视化条件组、试算 | 条件组构建器 + 试运行抽屉 |
| 火山引擎 DataFinder | 维度权重、TGI/分布对照 | 维度权重滑块 + 得分分布条形 |
| Segment / Salesforce 人群构建器 | 嵌套 AND/OR、实时预估人数 | 嵌套条件组 + 前端实时语法校验 |

**五条设计原则**：① 结构先于表单（树 → 表单 → JSON）；② 一切可预览（改即见结果）；③ 错误就近提示（字段级而非提交级）；④ 继承可感知（覆盖项显式标记）；⑤ 只读兜底（高级用户可切 JSON 视图，双向同步）。

## 5. 模板项配置详细设计

### 5.1 模板工作台布局

```
┌──────────────────────────────────────────────────────────────┐
│ 模板：community-correction-v1   [已校验 ✓] [试运行] [保存]   │
├──────────────┬───────────────────────────┬───────────────────┤
│ 结构树        │ 编辑区（随选中节点切换）   │ 属性面板           │
│ ▾ 维度(4)     │  ┌ 维度 A：基础属性 ────┐  │ code  name  weight │
│   • 基础属性  │  │ 权重 ▓▓▓▓▓░░ 0.30    │  │ 规则列表 / 继承来源 │
│   • 行为特征  │  │ 规则：enum_score …   │  │ 字段引用选择器      │
│ ▾ 属性字段(12)│  └──────────────────────┘  │ 校验提示            │
│ ▾ 标签绑定(18)│                            │                   │
│ ▾ 异常规则(3) │                            │                   │
└──────────────┴───────────────────────────┴───────────────────┘
```

- 拖拽排序维度与字段；维度/字段/规则均支持「复制」「禁用」「删除」。
- 继承（`extends`）：来自父模板的节点显示 `继承` 徽标，编辑即生成覆盖项；提供「恢复继承」。
- 顶部状态条常驻：必填项缺失数、规则引用失效数、权重合计（应 = 1.00）。

### 5.2 `dimension_config` 编辑器（维度与权重）

| 元素 | 控件 | 约束 |
|---|---|---|
| 维度 code | 输入框（前缀只读） | 模板内唯一，`^[a-z][a-z0-9_]{1,39}$` |
| 维度名称 | 输入框 | 必填，≤30 字 |
| 权重 | 滑块 + 数字 | 0.01~1.00，两位小数；全模板合计须 = 1.00（实时提示差额） |
| 规则列表 | 规则卡片（见 §6） | 至少 1 条；`type` 必须属白名单 |
| 排序 | 拖拽 | 影响画像视图展示顺序 |

### 5.3 `attributes_schema` 编辑器（属性字段）

字段属性：`key / label / type(text|number|date|enum|boolean) / required / options / default / help / group`。
- 表格式编辑 + 行内校验（key 唯一、enum 必须给 options）。
- **保留未知键**：读取时保留 `ext_types` 等非编辑器管理的键，保存时原样回写（避免覆盖扩展配置）。

### 5.4 `tag_bindings` 编辑器（标签绑定）

- 行模型：`tag_code → 目标（维度 code / 属性 key） + 取值来源 + 生效条件（可选）`。
- 提供「从标注模板导入字段」：选择已激活标注模板 → 勾选字段 → 自动生成绑定行。
- 冲突检测：同一 `tag_code` 绑定多次时高亮并要求指定优先级。

### 5.5 `evidence_policy` 编辑器（证据策略）

- 开关式表单：是否保留证据、最大条数（1~100）、保留字段多选、脱敏开关、留存天数。
- 右侧实时展示「一份画像将携带的证据示例」卡片。

### 5.6 `anomaly_rules` 编辑器（异常规则）

- 规则行：触发条件（复用 §6 条件组） + 严重级别（info/warn/error） + 处置动作（标记/扣分/告警）。
- 提供 3 个内置模板：缺失率过高、权重越界、标签冲突。

### 5.7 校验与保存

- 前端即时校验（字段级红框 + 右侧问题列表，点击定位节点）。
- 保存前调用 DPS 校验（P1 提供 `/validate`）；失败时把后端 `field path` 映射回节点高亮。
- 保存即生成新版本（沿用现有 `version` 递增与快照）；提供「保存草稿（不激活）」。

## 6. 规则引擎可视化

### 6.1 规则模型（沿用现有契约，增量扩展）

```json
{
  "dimensions": [{
    "code": "behavior",
    "name": "行为特征",
    "weight": 0.3,
    "rules": [
      {"type": "enum_score", "tag_code": "cor_reward_level", "mapping": {"A": 100, "B": 80}},
      {"type": "interval_score", "tag_code": "cor_edu_years", "ranges": [[0, 6, 40], [7, 12, 80]]},
      {"when": {"all": [{"field": "cor_risk_level", "op": "in", "value": ["高", "极高"]}]},
       "type": "boolean_flag", "tag_code": "cor_high_risk", "score": 0}
    ]
  }]
}
```

- **新增可选键 `when`**：条件成立才执行该规则；不写等价于恒真（向后兼容，旧模板零改动）。
- 条件组结构：`{"all":[...]}` / `{"any":[...]}`，可嵌套 3 层；叶子 `{field, op, value}`。

### 6.2 条件组构建器（参考 Segment 人群构建器）

- 视觉：嵌套卡片，组头可切换 **且/或**；组内「＋条件」「＋条件组」。
- 算子按字段类型动态给出：文本（=、≠、包含、正则）、数值（=、>、≥、<、≤、区间）、枚举（属于、不属于）、日期（早于、晚于、近 N 天）、布尔（为真/为假）。
- 右侧常显只读表达式预览：`risk_level ∈ {高, 极高} AND edu_years ≥ 9`。
- 字段选择器数据源：当前模板属性字段 + 绑定标签 + 系统内置字段（只读）。

### 6.3 打分规则表单（覆盖 6 种白名单类型）

| type | 表单要素 | 校验 |
|---|---|---|
| `legacy_map` | 值→分数映射表 | 分数字典必填 |
| `enum_score` | 枚举→分数映射 | 至少 2 项 |
| `boolean_flag` | 真/假分值 | 0~100 |
| `interval_score` | 区间列表（左闭右闭）→ 分数 | 区间不重叠、覆盖完整 |
| `ratio_target_score` | target / cap / half_floor | `0<target≤1`，`cap≥0` |
| `grade_map_score` | 1~4 级→分数 | 四级必填 |

- 每种类型给出「一句话说明 + 示例」，降低业务人员理解成本。
- 未知 `type`：以只读 JSON 卡片展示并提示「该类型未注册，模板不可激活」。

### 6.4 试运行（Dry-run）

- 抽屉三栏：样例输入（JSON 或表单）→ 逐规则结果表（tag/条件命中/得分/耗时）→ 维度加权与总分。
- 未命中/异常的规则以黄色标注并给出原因（缺字段、类型不符、除零等）。
- 可「保存为测试用例」，随模板版本留痕，供回归。

## 7. 画像 360 视图

```
┌ 身份卡：姓名/编号 · 模板 v3 · 更新时间 · 数据完整度 86% ───────────────┐
├───────────────┬────────────────────────────────────────────────────────┤
│ 维度雷达       │ 维度得分条：基础属性 82 · 行为特征 64 · 心理评估 71      │
│ （6 维）       │ 标签分组（可折叠）：风险等级 / 矫正阶段 / 教育程度 …     │
├───────────────┴────────────────────────────────────────────────────────┤
│ 证据抽屉（点击任一标签）：命中规则、原始值、来源标注模板、采集时间        │
│ 时间线：标签变化 / 分数跃迁 / 异常告警（近 90 天）                       │
└────────────────────────────────────────────────────────────────────────┘
```

- **维度雷达**：得分 0~100，缺失维度灰显并提示「未采集」。
- **标签树**：按维度分组；每个标签显示值 + 置信度/来源；长文本折叠。
- **证据抽屉**：当前模板 `evidence_policy` 决定展示范围；无证据时提示策略未开启。
- **时间线**：复用现有版本/变更数据；无数据时给空态与引导。
- **版本对照**：同主体跨版本得分 diff（+/- 与颜色），用于验收「模板改动是否生效」。
- **画像列表增强**：列增加「完整度」「最近变化」，支持按维度分数区间筛选（P1）。

## 8. 接口与数据契约

### 8.1 复用（P0，不改后端）

- `GET/POST /api/v1/dps-proxy/templates`、`PUT /templates/{code}`、版本列表/回滚、`annotation-templates` CRUD、`template-packages/import`。
- 前端负责结构编辑与基础校验，写回现有 JSONB 键名，**不新增数据库列**。

### 8.2 新增（P1，DPS 侧，均只读/无副作用）

| 接口 | 用途 | 备注 |
|---|---|---|
| `GET /api/v2/portrait/meta/schema` | 字段类型、算子、6 种规则类型及其参数模式 | 供前端动态渲染表单 |
| `POST /api/v2/portrait/templates/{code}/validate` | 服务端全量校验 | 返回 `[{path, code, message}]` 供节点定位 |
| `POST /api/v2/portrait/templates/{code}/preview` | 样例试算 | 入参 `sample`，返回逐规则得分与总分 |
| `GET /api/v2/portrait/profiles/{id}/dimensions` | 维度分数 + 证据 | 若已有聚合可直接复用 |

> 实现第一步先做「契约对齐核对」：以 `template_engine` 校验与 `DpsAnnotationFieldView` 现有字段项为准，逐键确认后再落地表单。

## 9. 前端实现要点

- 技术栈：Vue 3 + TypeScript + Element Plus（现有）；图表用轻量 SVG/自绘，避免新增重依赖。
- 组件：`TemplateWorkbench`、`StructureTree`、`DimensionEditor`、`AttributeFieldTable`、`TagBindingTable`、`EvidencePolicyForm`、`AnomalyRuleList`、`ConditionGroupBuilder`、`RuleCard`、`DryRunDrawer`、`PortraitRadar`、`TagGroupPanel`、`EvidenceDrawer`、`TimelinePanel`。
- 状态：页面级 `reactive` 草稿模型 + 与 JSON 双向映射（`toDraft/fromDraft`），脏数据离开拦截。
- 性能：结构树虚拟滚动（>200 节点）；试运行结果分页；大模板按分区懒渲染。
- 可访问性：键盘可达、表单 label 关联、颜色不作为唯一语义（分数同时显示数字）。

## 11. 验收标准

- 功能：业务人员不接触 JSON 即可完成「新建模板 → 配维度/规则 → 校验 → 激活 → 查看画像」全流程。
- 正确性：任一配置保存后 `GET /templates/{code}` 返回结构与编辑器一致；旧模板打开无字段丢失（未知键保留）。
- 可用性：必填缺失与规则失效在保存前 100% 暴露，且可点击定位。
- 性能：200 节点模板编辑交互 < 100ms；试运行（单样例）< 2s。
- 兼容：不改变现有 API 契约与库表结构；存量模板可读可编辑。

## 12. 风险与回滚

| 风险 | 影响 | 措施 |
|---|---|---|
| 编辑器与引擎契约不一致 | 保存失败/丢字段 | P0 前做契约核对；未知键透传；保存前服务端校验 |
| 大模板渲染卡顿 | 体验下降 | 分区懒渲染 + 虚拟滚动 |
| 规则理解门槛高 | 配置错误 | 内置说明/示例 + 试运行 + 异常高亮 |
| 后端接口延期 | 试运行不可用 | P0 先做前端静态校验，试运行降级为「结构预检」 |

回滚：前端按路由灰度（新工作台与旧 JSON 编辑页并存一个版本周期）；后端新增接口只读，回滚仅需下线路由。

## 13. 已确认决策（2026-11-15）

1. **实施范围：P0 + P1**。P0 交付前端可视化工作台与规则构建器；P1 交付 DPS 只读接口（`/meta/schema`、`/validate`、`/preview`）与试运行闭环。
2. **规则 `when` 允许落库**，由 DPS 打分前求值：条件不成立则跳过该规则；需同步补 DPS 单测与向后兼容验证（旧模板无 `when` 行为不变）。
3. **画像视图（后续期）范围：单主体 + 版本对照**，不做人群分布/跨主体对比。
4. **权限：沿用管理员权限**（`portrait_template:create/update`），本期不引入业务角色与审批流。
