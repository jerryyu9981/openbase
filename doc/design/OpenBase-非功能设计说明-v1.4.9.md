## 1. 功能正确性（硬判据 NFR-149-01）

| 指标 | 目标 | 落地机制 | 验证 |
|------|------|----------|------|
| 超窗发生率 | **0** | 预算计算 + 二次校验 + 硬截断保险丝（架构 §3.3/§3.6） | AC-149-12（实测统计） |

## 2. 可观测性（NFR-149-03，内联 observability-standards）

| 检查项 | 设计 |
|--------|------|
| 日志结构 | 结构化 JSON，含 `request_id`/`tenant`/`module`（沿用既有） |
| 关键指标 | `context_budget_available`、`context_tokens_before/after`、`context_hard_truncated_total`、`context_degraded_total`、`knowledge_write_blocked_total`（**新增 5 项，命名对齐既有前缀**） |
| 追踪 | 沿用 OTLP/W3C 传播；装配各阶段为同一 trace 内的 span |
| Dashboard | 6 类既有 Dashboard 复核：**预算/裁剪指标需在 Service Overview 呈现** |
| 告警 | `context_hard_truncated_total` 突增告警（P2，24h IM）；失败标记告警（P1） |
| 排障上下文 | 回执 `degraded`/`hard_truncated`/`enabled` 三字段可直接定位降级原因 |
| **回执覆盖率** | **100%**（AC-149-05）：字段齐备性检查作为用例 |

## 3. 性能（NFR-149-04）

| 项 | 设计 |
|----|------|
| 复杂度 | 选择与排序 **O(n log n)**；切分为 O(n)；无嵌套重算 |
| 预算 | 不新增外部调用（不引入网络往返） |
| 目标 | 不引入**可感知回归**（沿用既有性能基线；本版本不新增 SLA 承诺） |
| 验证 | 既有性能记录对照 ＋ 单元级耗时断言（宽松界） |

## 4. 兼容性与可回退（NFR-149-02）

- 开关**默认关闭** ⇒ 默认路径与 v1.4.8 **逐字一致**（AC-149-09）；
- 关闭开关即回退（无需发版）；无 schema 迁移 ⇒ 无数据回退需求。

## 5. 可维护性（NFR-149-05）

- **不复用** `manage_context` / `_prune_recent`；静态检查可证（AC-149-10）；
- 新模块单一职责、依赖单向（架构 §2）。

## 6. 条件项（NFR-149-06，受 D2/D3）

WCR 与人工走测评分：**过渡口径「先记录、不判定」**，待 B1/B2 数据回填；
**不得**据此规避 §1 硬判据。
