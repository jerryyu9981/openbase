### 2.3 口径更正（如实登记）

> **更正**：本方案编写前，曾口头表述「判别式重排器不依赖任何前置、可立即开工」。**该表述不准确，现予更正。**
>
> 依据：技术方案 §5.5「相关性筛选」行明确「**重排器为 0.6B 判别式模型**」，§5.8 明确重排在线预算 **≤100ms**。而 §5.4 实测中 4B 生成式在 `select` 任务虽 `f1 = 0.873`（≥ 0.70 门槛）达标，**P95 = 35729.9ms ≈ 35.7s**，既远超在线档 100ms 预算，亦超异步档 30s 预算（证据：`small-model-bench-20260928-lan-qwen35-4b.md`）。
>
> 结论：**生成式模型做重排不可行**，判别式重排器须使用**专用判别式（cross-encoder 类）模型**，而该类模型**尚未选型与实测** ⇒ 判别式重排器**存在未满足前置**，归入 §3.2 B 类。

## 5. B 类：判别式重排器前置工作（题 10）

### 5.1 为何不是「无前置」

| 事实 | 证据 |
|------|------|
| 重排器设计形态 = **0.6B 判别式模型** | 技术方案 §5.5「相关性筛选」行 |
| 重排在线预算 **≤100ms** | 技术方案 §5.8 预算行 |
| 生成式 4B 在 `select` 任务 `f1 = 0.873`（≥0.70 达标） | `small-model-bench-20260928-lan-qwen35-4b.md` |
| 但同任务 **P95 = 35729.9ms ≈ 35.7s** | 同上 |
| ⇒ 生成式做重排既超在线档 100ms、亦超异步档 30s | 技术方案 §5.6 补测通过标准 |

**结论**：判别式重排器需**专用判别式（cross-encoder 类）重排模型**，该类模型**尚未选型与实测** ⇒ 前置未满足。

### 5.2 前置工作（可立即开工）

| 步骤 | 内容 | 产出 |
|:----:|------|------|
| 1 | **选型**：候选判别式重排模型（cross-encoder 类，量化档优先），须能在**本环境（无 GPU、局域网 CPU）**运行 | 候选清单 |
| 2 | **实测**：扩展 `local-model-bench` 基准的 `select` 任务口径，测 **F1 ≥ 0.70** 与 **P95 ≤ 100ms** | 基准报告（落 `doc/test/evidence/local-model-bench/`） |
| 3 | **判定**：达标 ⇒ 进入主体实施（接线为在线档允许手段，见技术方案 §5.8「允许手段」行）；不达标 ⇒ **如实登记不达标，维持 OpenRAG 服务端 rerank**（现行能力） | 判定结论 + 登记 |

**说明**：在线重排能力**当前已具备**（`RAG_RERANK_ENABLED=true` + `RAG_SCORE_THRESHOLD=0.15`，走 OpenRAG 服务端 rerank，判据 T3 段② PASS）。判别式重排器的价值是**不依赖外部服务端重排能力**的本地兜底，属**增益项**而非**缺口项**；因此**前置不达标可不阻塞收口**（见 §8 收口判据）。
