## 1. 回滚方案

### 1.1 回滚触发条件

| 触发 | 条件 |
|------|------|
| 自动 | 健康检查失败 / 错误率 > 1% / P99 超基线 50% / 冒烟失败 |
| 手动 | P0 缺陷 / 脏数据 / 安全 / 合规 / 性能问题 |

### 1.2 回滚路径（直接部署模式）

| 步骤 | 操作 | 说明 |
|------|------|------|
| 1 | 停止新版本 | 停止 uvicorn:8000 与 vite preview:5173 |
| 2 | 代码回滚 | `git checkout v1.2.0 -- openbase openbase-ui`（或 git revert） |
| 3 | 服务回滚 | 启动 v1.2.0 后端 + 前端 |
| 4 | 数据回滚 | 不涉及（本版本无 DB schema 变更） |
| 5 | 验证 | 15 分钟内健康检查 200 + 登录冒烟通过 |

### 1.3 审批流程

| 环境 | 审批 |
|------|------|
| Dev | 自决 |
| Pro | 发布负责人 + PM 双签（数据回滚 + DBA 三签） |

## 2. 运维手册

### 2.1 服务清单

| 服务 | 端口 | 启动命令 | 健康检查 |
|------|------|---------|---------|
| 后端 API | 8000 | `python -m uvicorn openbase.demo_app:app --port 8000` | GET /health → 200 |
| 前端静态 | 5173 | `npx vite preview --port 5173`（或 Nginx 托管 dist/） | GET / → 200 |

### 2.2 常见故障排障

| 故障 | 排查 | 处理 |
|------|------|------|
| 登录超时 | bcrypt 计算耗时（内存模式） | 等待 5-10s 或检查 CPU |
| 数据库不可达 | 启动日志 "database init failed, fallback to memory" | 启动 PG 后重启后端（数据迁移至 PG） |
| Redis 不可达 | "redis unavailable, cache disabled" | 启动 Redis（缓存降级不影响核心功能） |
| 代理 502 | 上游系统未启动 | 启动对应系统（OpenLLM:8001 等）后重试 |
| 代理 402 | 模型提供商余额不足 | 联系提供商充值（BIZ_MODEL_QUOTA） |
