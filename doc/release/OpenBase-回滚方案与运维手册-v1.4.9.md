## 1. 回滚方案

| 项 | 内容 |
|----|------|
| 目标版本（回滚到） | **v1.4.8**（最近一次完整闭环版本） |
| 部署策略 → 回滚路径 | Dev ＝ **直接部署**（单进程 `uvicorn`）⇒ 回滚 ＝ **停进程 → 代码回退 → 重启 → 验证**；蓝绿／金丝雀／K8s 滚动 **不适用**（本版无多实例编排环境，须在发布计划中声明） |
| **首选回滚路径：配置回滚（零代码变更）** | 本版 **6 个开关出厂默认全为关闭** ⇒ **不开启即为 v1.4.8 行为**（**关闭态逐字回退已实测**：`TT-v1.4.9-028/045` —— 回执字段 28 → **11**，扩展字段组泄漏 = **`[]`**）。因此**首选**回滚＝**关闭开关并重启**，无需回退代码、无需回退数据 |
| 次选回滚路径：代码回滚 | ① `git revert b261010`（**保留历史**，推荐 —— 仅撤 Step 4 那笔缺陷修复）；② 整版回退：`git checkout v1.4.8` 或 `git reset --hard d4bff29`（**仅本地**，协作场景禁用） |
| 数据回滚 | **本版无 DDL/DML 迁移**（无 schema 变更）⇒ **无需数据回滚**。唯一持久化面 `backend/data/writeback.db`（SQLite 队列）为**只增不改**语义，跨版本兼容；如需兜底，发布前留存副本（`Copy-Item writeback.db writeback.db.bak-<ts>`） |
| 配置回滚 | 开关回退即配置回滚（见上）；另需还原 `.env` 中 `CONTEXT_BUDGET_ENABLED` 等 6 项的显式设置；**新增键默认值 = 回退态**（`CONTEXT_SAFETY_MARGIN_TOKENS=256` 等，不设即默认） |
| 缓存 / 消息 | 本版无缓存预热步骤；回写队列（SQLite）**不因回滚丢数据**（恢复逻辑沿用 v1.4.8 启动恢复），消息链路无需暂停 |
| 审批 | **Dev**：自决；**Test**：审查者审批；**Pro**：发布负责人 ＋ PM 双签（数据回滚另加 DBA）——**本次发布目标为 Dev**，Test/Pro **未涉及** |
| 触发条件（自动） | 健康检查失败 ／ 错误率 > 1% ／ P99 超基线 50% ／ 冒烟失败 |
| 触发条件（手动） | P0 缺陷 ／ 脏数据 ／ 安全或合规事件 ／ 性能不可接受退化 |
| 紧急回滚 | P0 故障**可绕过审批**；**2 小时内**补录材料，**24 小时内**输出 RCA |
| **回滚后门禁** | **15 分钟内**完成「健康检查 ＋ 冒烟验证」；**未通过视为回滚失败，按 P0 升级** |
| 记录要求 | 任何回滚**必须在《发布复盘与问题跟踪记录-v1.4.9》中记录原因与影响**；生产回滚须在复盘记 RCA |

## 3. 运维手册（要点）

| 场景 | 处置 |
|------|------|
| 服务不可用 | 查进程/端口（`Get-NetTCPConnection -LocalPort <port> -State Listen`）→ 读结构化日志按 `request_id` 串联 → 必要时按 §1 回滚 |
| **组件级降级（常态）** | `openrag`／`dps`／`ollama` 可用性会波动；不可用时**必须如实留痕**（`degraded`／`errors`／ERROR 日志），**不得静默**。判据：`/openllm/v1/health` 的 `data.components[*].status` |
| 健康检查语义 | `data.status=healthy` 与**逐组件** `status` 需**分别读**；健康 ≠ 全组件可用 |
| 检索为空导致 `dropped=[]` | **属预期**（无检索条目即无整条丢弃），**非缺陷**；需真实检索数据方可观测明细（`TD-新增-032`） |
| 回写重试打 ERROR | 回写目标不可用时会重试至上限后记 ERROR（**可观测，非缺陷**）；检查目标服务与队列 `stats` |
| 预算/超窗异常 | 读回执 `model_window`／`output_reserve`／`safety_margin`／`available_budget`／`prompt_tokens_before|after`；不一致时先核对 `.env` 的 `CONTEXT_SAFETY_MARGIN_TOKENS` |
| 通道切换与审计 | `CHANNEL_AUDIT_ENABLED`（默认关）开启后组件级切换事件可检索；关闭即不落库（逐字回退） |
| 配置变更 | 6 个开关**出厂默认全关**；变更须显式声明环境并记录；**新增键必须先在 `Settings` 声明**（该仓 `extra=forbid`，未声明键为**死开关**——见 G5 教训） |
| 排障命令（示例） | `python -m pytest tests/unit -q`；`python -m compileall -q app main.py`；`git log --oneline -5`；判据复核 `python doc/test/evidence/cr149/v149_receipt_and_purity_probe.py`（**6/6**）／`v149_increment_runner.py`（离线 **7/7**） |
| 日志卫生 | **工作区 `.env` 的 `DEBUG=true` 会打开 SQLAlchemy echo（输出量极大）**；生产/长期运行应关闭；**日志不得含令牌、密钥、完整请求体、片段或回答正文** |
| 密钥与配置安全 | `.env*` 不入 git（AGENTS.md §6）；**当前存在已知偏差 TD-新增-029（`.env.shared-infra` 被跟踪）**，发布放行前须处置 |
| 联系人 | DO-OpenBase-Dev（部署）／TE-OpenBase-Dev（测试）／AU-OpenBase-Test（审计）／PM-OpenBase-Dev（产品）；**发布负责人**：DO-OpenBase-Dev |
| SLA / SLO | 本次目标环境 **Dev ⇒ 无 SLA 承诺**；SLO 建议（待 Test/Pro 环境约定后确认）：可用性 99.9%／关键接口 P99 ≤ 基线 ×1.5／错误率 ≤ 1%／回执齐备率 100%（预算生效请求）／超窗率 0 |
