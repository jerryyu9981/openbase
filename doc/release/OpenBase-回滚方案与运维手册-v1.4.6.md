## 1. 回滚方案

### 1.1 回滚触发条件

| 触发 | 条件 |
|------|------|
| 自动 | 健康检查失败 / 错误率 > 1% / P99 超基线 50% / 冒烟失败（回滚后 15 分钟内未通过即升级 P0） |
| 手动 | P0 缺陷 / 脏数据 / 安全 / 合规 / 性能问题 |

### 1.2 回滚路径（直接部署模式）

| 步骤 | 操作 | 说明 |
|------|------|------|
| 1 | 停止新版本 | 停止 uvicorn:8000（PID）与 vite preview/dev:5173 |
| 2 | 代码回滚 | `git checkout v1.4.5 -- openbase openbase-ui .devflow` 或 `git revert` |
| 3 | 服务回滚 | 启动 v1.4.5 后端 + 前端 |
| 4 | 数据回滚 | 不涉及（本版本无 DB schema 变更；`audit_db`/四仓数据为上游系统） |
| 5 | 验证 | 15 分钟内健康检查 200 + 登录冒烟通过；未通过升级 P0 处置 |

> 说明：v1.4.6 无迁移脚本、无 schema 变更，回滚为纯代码回退，风险低。若 v1.4.6 期间新增了审计/日志数据，回滚后这些数据在历史版本接口下仍可查询（字段兼容）。

## 2. 运维手册

### 2.1 服务清单

| 服务 | 端口 | 启动命令 | 健康检查 |
|------|------|---------|---------|
| 后端 API | 8000 | `python -m uvicorn openbase.demo_app:app --host 127.0.0.1 --port 8000` | GET /health → 200 |
| 前端静态 | 5173 | `npm run dev`（Dev）/ `npx vite preview --port 5173`（或 Nginx 托管 dist/） | GET / → 200 |
| PostgreSQL | 5432 | 进程环境（.env.shared-infra） | 连接 + 基础 SELECT |
| Redis | 6379 | `REDIS_URL` 注入 | 可选（缓存降级可用） |

### 2.2 关键配置与开关（v1.4.6 新增）

| 配置 | 说明 |
|------|------|
| `log:read` | 日志中心读取权限（管理员跨租户） |
| `module:manage` | 模块开关权限；写路径留痕；生效滞后 `next_login`（`effective=next_login`） |
| 响应采集 | **默认关闭**；开启时强制脱敏 + 单条上限 2KB + 生产永久关闭 + 开关留痕 + 域级最小化 |
| `audit_db` 不可用 | 返回显式 503 `SYS_503`（`detail={"source":"audit_db"}`），主事件循环 `fetch_async` 取数 |

### 2.3 常见故障排障

| 故障 | 排查 | 处理 |
|------|------|------|
| 登录超时 | bcrypt 计算耗时（内存模式） | 等待 5-10s 或检查 CPU |
| 数据库不可达 | 启动日志 "database init failed, fallback to memory" | 启动 PG 后重启后端（数据迁移至 PG） |
| Redis 不可达 | "redis unavailable, cache disabled" | 启动 Redis（缓存降级不影响核心功能） |
| 代理 502 | 上游系统未启动 | 启动对应系统（OpenLLM:8001 等）后重试 |
| 日志中心四仓源为空 | 四仓未接入 JSONL | 待各仓落地 R-384 契约后自动显示 |
| 日志脱敏异常（敏感信息披露） | 检查 `core/mask.py` 匹配规则 | 补充凭据模式规则 + 回归测试 |
| `audit_db` 503 | 审计库不可用 | 确认审计数据源后重试（显式 503，非静默空结果） |
