## 2. 阻塞项定性、加强证据与放行动作清单

### 2.1 阻塞项：TD-新增-029（P1，安全／合规）

| 项 | 内容 |
|----|------|
| 现象 | OpenLLM 仓**跟踪** `.env.shared-infra`，内含 **10 行敏感项**（`POSTGRES_PASSWORD`／`REDIS_PASSWORD`／`MINIO_SECRET_KEY`／`NEO4J_PASSWORD`／`OPENRAG_API_KEY`／`OPENMEMORY_API_KEY`／`OPENMEMORY_JWT_SECRET` 等）；该文件自身注释即写「**勿落 git**」 |
| **加强证据（本批新增，风险等级上调依据）** | 该文件**不只在本地历史**：`git ls-tree origin/feature/s4-identity-channel-b -- .env.shared-infra` → **命中 blob `5c03043d…`**；且仓内存在 **`origin` / `backup` / `github` 三组远端** ⇒ **凭据已随历史推送至远端** ⇒ 「仅本地未外泄」的缓解假设**不成立** |
| 冲突 | AGENTS.md §6「敏感数据不落日志、**不落 git**（`.env*` 排除）」；`.gitignore` 仅排除 `.env`（`backend/.env` 命中），**未排除** `.env.shared-infra` |
| 为何不能由本阶段自行闭环 | ① **撤跟踪会破坏协作方**：`git rm --cached` 提交后，其他人 `git pull` 会**删除其本地 `.env.shared-infra`**（且已被 gitignore，需手工重建）⇒ 属**跨人/跨仓协调动作**；② **轮换**涉及 postgres/redis/minio/neo4j（本机 docker 栈）与跨仓（OpenRAG／OpenMemory）凭据，需三方同步改配置，**超出本阶段权限**；③ 远端历史清理（`filter-repo`）需与远端使用者约定窗口 |
