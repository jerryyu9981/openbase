# 第一部分　回滚方案

## 1. 版本特征与回滚难度评估

| 项 | 本版实际 | 对回滚的影响 |
|----|----------|--------------|
| 运行时开关 | **无**（本版不引入任何开关） | ⇒ **不适用**「配置回滚」路径（与 v1.4.9 的『关开关即回退』不同） |
| DB 迁移 | **无 DDL/DML** | ⇒ **不适用**「数据回滚」路径 |
| 后端变更面 | 单文件 `openbase/modules/dps_proxy/__init__.py`（＋508 行，端点扩展） | 代码回退粒度小、影响面清晰 |
| 前端变更面 | `dps.ts`／`error.ts`／`router/index.ts` ＋ 12 个 `Dps*View.vue` ＋ 2 组合式函数 | 制品回退＝替换 `openbase-ui/dist` |
| 对既有能力影响 | 既有 12 端点与既有页面**零破坏**（Step 4 隔离回归通过） | 回退后行为等同 v1.4.9 |

## 2. 回滚触发条件

| 类型 | 触发条件 |
|------|----------|
| **自动触发** | 健康检查连续失败；错误率 > 1%；P99 超基线 ×1.5；核心冒烟用例失败 |
| **手动触发** | 发现 P0 缺陷；脏数据；安全／合规问题；**既有 12 端点或既有页面出现回归**（本版兼容红线） |
| **上游异常触发** | DPS 上游持续不可用导致 `dps-proxy` 返回 503 且**持续超过发布观察窗**，且判定与本版变更相关 |

## 3. 回滚路径分类与命令

| # | 路径 | 适用 | 命令 / 动作 | 审批 |
|:-:|------|------|-------------|------|
| ① | **前端制品回退（首选）** | 仅前端缺陷 | 将 `openbase-ui/dist` 替换为上一发布制品（`v1.4.9` 构建物）→ 重新加载静态服务 | Dev 自决（DO） |
| ② | **后端代码回退** | 后端缺陷 | `git revert <本版发布提交>` 并重新部署；或 `git checkout v1.4.9 -- openbase/modules/dps_proxy/__init__.py` 后重启 | Dev 自决（DO） |
| ③ | **整版回退** | 前后端同时异常 | `git checkout v1.4.9`（tag 已存在）→ 重建前端制品 → 重启后端 | Dev 自决（DO） |
| ④ | **数据回滚** | — | **不适用**（本版无 DB 迁移；`dps_proxy` 为无状态透传，不落库） | — |
| ⑤ | **配置回滚** | — | **不适用**（本版无运行时开关） | — |
| ⑥ | **服务回滚（蓝绿／金丝雀）** | — | **不适用**（Dev 为单进程 `uvicorn` 直接部署，无多实例编排） | — |

## 4. 回滚步骤（可执行清单）

| 步 | 动作 | 命令 | 预期 |
|:--:|------|------|------|
| 1 | 冻结变更、通知 | — | 发布窗口冻结生效 |
| 2 | 确认回退目标可用 | `git tag -l v1.4.9`；`git rev-parse v1.4.9^{commit}` | tag 存在且指向上一发布提交 |
| 3 | 执行回退（择①／②／③） | 见 §3 | 工作区／制品回到 v1.4.9 口径 |
| 4 | 重启后端 | `python -m uvicorn openbase.demo_app:app --host 127.0.0.1 --port 8000` | `Application startup complete.` |
| 5 | **15 分钟验证门禁** | `GET /health`；`GET /openapi.json`；抽检既有端点 | `/health` → 200 `{"status":"ok"}`；既有端点行为与 v1.4.9 一致 |
| 6 | 记录 | 《发布复盘与问题跟踪记录-v1.4.10》§回滚记录 | 原因、影响、RCA 入档 |

> **门禁（强制）**：回滚完成后 **15 分钟内**必须完成健康检查 ＋ 冒烟验证；未通过视为回滚失败，升级 P0 处理。

# 第二部分　运维手册

## 7. 服务拓扑与启停

| 项 | 内容 |
|----|------|
| 后端 | 单进程 `uvicorn`：`python -m uvicorn openbase.demo_app:app --host 127.0.0.1 --port 8000`（cwd＝仓根） |
| 前端（Dev） | Vite dev server：`npm run dev -- --strictPort`（127.0.0.1:5173）；制品模式＝静态托管 `openbase-ui/dist` |
| 依赖 | 共享 PostgreSQL（`192.168.0.151:5432`，经 `.env.shared-infra`）**可选**：不可达时 `demo_app` **自动降级内存演示用户**（`fallback: memory demo user seeded`），服务不中断 |
| 上游 | **DPS v2.12.1 @ 127.0.0.1:8030**；DPS 侧需 `TRUSTED_PROXY_SOURCES=openbase-dps-proxy` 方信任本仓注入的身份头 |
| 启停 | 启动＝上述命令；停止＝`Ctrl+C` 或终止 PID；**无守护进程／无 systemd 单元**（Dev 口径） |

## 8. 健康检查与可观测性

| 面 | 入口 | 判定 |
|----|------|------|
| 存活 | `GET /health` | 200 `{"status":"ok"}` |
| 契约 | `GET /openapi.json` | 200；`paths` 计数 **144**（v1.4.10 口径，含 `dps-proxy` **26** 条） |
| 上游探活 | `GET /api/v1/dps-proxy/health`（需令牌） | 透传 DPS 存活；上游不可达时返回保真错误体 |
| 降级可观测 | 响应头 `X-DPS-Upstream-Degraded`；结构化日志 `dps-proxy upstream unreachable` | 连续失败达阈值 ⇒ `503` 显式降级（fail-open，恢复自动归零） |
| 日志 | `logs/openbase/openbase-<YYYYMMDD>.jsonl`（结构化 JSONL：`ts`／`level`／`service`／`module`／`message`／`env`／`version`／`request_id`） | 符合 `observability-standards` 字段面 |
| 日志安全 | 抽样扫描 | 响应与日志**零凭据**（仅出现语义词 `token`／`bearer`，非密钥值） |
| 告警 | **本仓未接入告警系统**（无 Alertmanager／通知通道） | ⛔ **不适用（声明）**；阈值与 SLO 建议见 §9 |

## 9. SLO / 告警阈值建议

| 指标 | Dev | Test/Pro 建议 | 告警级别 |
|------|-----|---------------|:--------:|
| 可用性 | 无承诺 | ≥ 99.9% | P0（15 分钟电话） |
| 错误率 | 观察 | ≤ 1% | P0 |
| 关键接口延迟 | 无承诺（本版 Dev 实测见《部署执行与上线检查报告》§7） | P99 ≤ 基线 × 1.5 | P1（1 小时 IM） |
| `dps-proxy` 降级率 | 观察 | ≤ 1%（超阈值 P1） | P1 |
| 健康检查失败 | 观察 | 连续 3 次失败即告警 | P0 |

## 10. 常见故障与排障

| 现象 | 根因 | 处置 |
|------|------|------|
| 启动日志 `database init failed, fallback to memory` | 共享 PostgreSQL 连接抖动（`asyncpg ConnectionDoesNotExistError`） | **属既有降级设计**：服务继续可用；如需库能力，待共享库稳定窗口重启 |
| `GET /api/v1/dps-proxy/*` 返回 **502 `SYS_502`** | DPS 上游不可达 | 确认 DPS 进程与端口 8030；恢复后自动归零（无需重启本仓） |
| 返回 **503「DPS 上游持续不可用（降级）」** | 连续失败达 `dps_degrade_threshold` | 同上；`X-DPS-Upstream-Degraded: true` 为显式降级标记 |
| DPS 侧返回 **401「missing bearer token」** | DPS 未配置 `TRUSTED_PROXY_SOURCES=openbase-dps-proxy` ⇒ 不信任本仓身份头，回落到自身 JWT 认证 | 在 DPS 侧补齐该环境变量后重启 DPS |
| DPS 侧返回 **403「组织不存在」** | DPS 数据库**组织/租户种子缺失**（如 SQLite 回退新库、共享 PG 不可达） | 恢复共享 PG 或用 DPS 侧种子脚本初始化后再联调 |
| 前端页面可达但数据空 | 上游 401/403/502 透传（**错误保真**，非前端缺陷） | 按上游状态处置；前端仅呈现上游错误码 |
