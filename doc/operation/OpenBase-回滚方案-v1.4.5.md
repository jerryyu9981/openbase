## 1. 回滚目标

| 项 | 内容 |
|----|------|
| 回滚目标版本 | v1.4.4（OpenRAG 对接，已发布） |
| 回滚原因 | v1.4.5 出现 P0/P1 上线问题（登录失败/核心链路不可用/安全事件） |
| 数据变更 | **无 DB 变更**（DPS 数据为上游系统，OpenBase 本地库无迁移）→ 无需数据回滚 |

## 2. 回滚触发条件

| 触发类型 | 条件 |
|----------|------|
| 自动 | dps-proxy 健康检查失败 / 错误率 >1% / P99 超基线 50% |
| 手动 | P0/P1 缺陷、脏数据、安全、合规、性能问题 |

## 3. 回滚步骤

| 步骤 | 操作 | 命令 |
|:----:|------|------|
| 1 | 代码回滚到 v1.4.4 | `git checkout v1.4.4 -- openbase openbase-ui`（或 `git revert`） |
| 2 | 配置回滚 | 移除/注释 dps_* 配置（settings 默认不启用 dps_proxy） |
| 3 | 服务重启 | 重启 OpenBase 8000 + 前端 build |
| 4 | 验证 | 回滚后 15 分钟内完成健康检查 + 登录 + 核心链路冒烟 |

## 4. 审批流程

| 环境 | 审批 |
|------|------|
| Dev | 发布负责人自决 |
| Test | 审查者审批 |
| Pro | 发布负责人 + PM 双签（无数据回滚，不需 DBA） |

## 5. 回滚验证（回滚后 15 分钟）
