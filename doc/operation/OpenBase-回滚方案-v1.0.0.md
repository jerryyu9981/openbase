## 1. 回滚目标与基线

| 项 | 内容 |
|----|------|
| 当前版本 | v1.0.0（commit 4c2edd8） |
| 回滚目标 | 上一可用基线（git 历史保留，可 checkout 任意历史 commit） |
| 回滚类型 | 代码回滚（git）+ 数据回滚（幂等重建，无需破坏性操作） |

## 2. 回滚触发条件

| 触发 | 指标 | 动作 |
|------|------|------|
| 自动 | /health 非 200 连续 3 次 | 回滚 |
| 自动 | 核心 API 5xx 率 > 1%（5min） | 回滚 |
| 自动 | 登录 P99 > 基线 50%（5min） | 告警 + 人工确认 |
| 手动 | P0 缺陷 / 数据异常 / 安全事件 | 紧急回滚 |

## 3. 回滚步骤（Dev/Test 直接部署）

| 步骤 | 操作 | 命令 |
|------|------|------|
| 1 | 停止当前服务 | Stop 进程（uvicorn） |
| 2 | 回退代码 | `git checkout {previous-commit}` 或 `git revert` |
| 3 | 重新启动 | `uvicorn openbase.demo_app:app` |
| 4 | 健康检查 | `GET /health` → 200 |
| 5 | 冒烟验证 | login + 核心 API（TT-101/102/111） |

**回滚后 15 分钟内必须完成验证，未通过升级 P0。**

## 4. 数据回滚方案

| 场景 | 方案 |
|------|------|
| 表结构变更 | 本版本无破坏性变更（幂等 create_all + 种子），重跑即恢复 |
| 数据污染 | openbase schema 数据可重建（admin 种子 + 配置 restore）；业务数据依赖各系统自身备份 |
| 缓存 | Redis 缓存键自动过期（TTL 300s），无需手动清理 |
