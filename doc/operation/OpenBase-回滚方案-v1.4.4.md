## 1. 回滚概述

| 项 | 内容 |
|----|------|
| 当前版本 | v1.4.4（commit 2dde2c6，tag v1.4.4） |
| 回滚目标版本 | v1.4.3（tag v1.4.3，commit 850b2b6） |
| 回滚类型 | 代码回滚（git）+ 服务重启 |
| 数据影响 | 无（v1.4.4 无数据库变更；OpenRAG 数据为上游系统，不受影响） |

## 2. 回滚触发条件

| 触发类型 | 条件 |
|:--------:|------|
| 自动触发 | 健康检查失败（OpenBase 8000 不可达）/ 错误率 > 1% / rag-proxy P99 超基线 50% |
| 手动触发 | P0 缺陷 / 数据异常 / 安全合规问题 / rag-proxy 转发大面积 5xx |

## 3. 回滚步骤

| 步骤 | 命令/操作 | 预期 |
|------|-----------|------|
| 1. 确认版本 | `git log --oneline -1` | 当前 2dde2c6（v1.4.4） |
| 2. 切回 v1.4.3 代码 | `git checkout v1.4.3`（或 `git revert 2dde2c6`） | 代码恢复 v1.4.3 |
| 3. 重启服务 | 停止 OpenBase uvicorn → `python -m uvicorn openbase.demo_app:app` | 8000 恢复 |
| 4. 确认 OpenRAG | OpenRAG 8010 独立系统，无需回滚 | 保持运行 |
| 5. 回滚验证 | 15 分钟内：health 200 + 登录 + llm-proxy 冒烟（v1.4.3 功能） | 全部通过 |

## 4. 审批流程

| 场景 | 审批 |
|------|------|
| Dev 环境 | 发布负责人自决 |
