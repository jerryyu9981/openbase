## 1. 回滚触发条件

| 条件 | 级别 | 动作 |
|------|------|------|
| 上线检查失败（关键项） | P0 | 立即回滚 |
| 线上 P0 故障（服务不可用/数据异常） | P0 | 紧急回滚 |
| 指标异常（P99>500ms 持续/错误率上升） | P1 | 评估后回滚 |
| 四系统灰度失败 | P1 | 逐系统 git revert |

## 2. 回滚步骤（蓝绿场景）

| 步骤 | 操作 | 时长 |
|------|------|------|
| 1 | 停止 Green 实例（Stop-Process） | <1min |
| 2 | 负载均衡流量切回 Blue（v1.0.0） | <30s |
| 3 | 验证 Blue health/login | <2min |
| 4 | 记录问题至问题跟踪记录 | - |

## 3. 回滚步骤（金丝雀场景）

| 阶段 | 动作 |
|------|------|
| 10%/50% 阶段失败 | 流量切回 100% v1.0.0，停止新实例 |
| 100% 阶段失败 | 蓝绿切换回退（流量切至 Blue） |

## 4. 数据库回滚

| 项 | 说明 |
|----|------|
| 迁移策略 | 幂等（无破坏性变更），v1.1.0 无 schema 变更（新增配置/脚本/兼容层） |
| 数据保留 | 业务数据在 openbase schema，回滚不删除数据 |
| 特殊处理 | 回滚后重新部署 v1.0.0 时自动跳过已存在对象（create_all 幂等） |

## 5. 回滚验证

| 检查 | 标准 |
|------|------|
| health | ok |
| 登录 | 200 |
| 鉴权门禁 | 匿名 401 |
| 数据 | 无丢失、无重复 |
