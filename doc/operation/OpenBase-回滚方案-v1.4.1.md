## 1. 回滚目标版本

| 项 | 值 |
|----|-----|
| 回滚目标 | v1.4.0（基线版本） |
| 部署策略 | Dev 环境直接部署（无蓝绿/金丝雀） |
| 回滚路径 | 代码回滚（git）+ 服务重启（进程级切换） |

## 2. 回滚触发条件

| 触发 | 条件 |
|------|------|
| 自动触发 | 健康检查失败 / 错误率 >1% / P99 超基线 50% / 冒烟失败 |
| 手动触发 | P0 缺陷 / 脏数据 / 安全合规 / 性能退化 |

## 3. 回滚影响评估

| 项 | 说明 |
|----|------|
| 数据影响 | 无（v1.4.1 无 schema 变更；服务 Key 为内存态随进程消失） |
| 用户影响 | 服务 Key 签发功能回退至 v1.4.0 状态（无 API 签发端点，仅内部存储） |
| 依赖影响 | 四系统未接入，无上游影响 |

## 4. 回滚步骤（Dev 环境）

| 步骤 | 操作 | 验证 |
|:----:|------|------|
| 1 | `git checkout v1.4.0 -- openbase/`（恢复 v1.4.0 代码）或 `git revert` | git status 确认 |
| 2 | 停止 uvicorn 进程 | 端口释放 |
| 3 | 重新加载 `.env.shared-infra` 并启动 v1.4.0 后端 | `/health` → 200 |
| 4 | 冒烟：登录 + 基础 API | 15 分钟内完成 |

> 审批：Dev 环境回滚由 DO 自决；Pro 环境需发布负责人 + PM 双签（本项目 Dev 阶段适用自决路径）。
