## 1. 背景与来源

| 项 | 内容 |
|----|------|
| 触发事件 | v1.4.7 **DEF-BE-147-005**（P1：`rag-proxy/collections` 在 OpenRAG M2 受信模式下 200 → 400）的根因定位与处置复核 |
| 根因（已定位） | OpenRAG `identity_gate` 的**保留租户码碰撞**防护：M2 受信路径下 `X-Tenant-ID` 缺省即保留码 `default`，而 OpenBase 联调租户码亦为 `default` → 命中防护返回 400 |
| 本仓处置（已闭环） | 按**方案 B**：`rag-proxy` 对 OpenRAG **不注入身份头**（新增显式开关 `rag_inject_identity_headers`，默认 `true` 保持既有语义；联调由编排器声明 `false`）→ 复测 200 且 `items=12`；护栏 `tests/test_rag_proxy_identity_policy.py`（3 例）+ `tests/test_bl147_trust_env_wiring.py`（4 例） |
| 为何仍需派单 | 上述处置是**规避**而非**消解**：① 租户码语义在跨域场景下仍存在同名冲突风险（属跨仓/设计议题）；② OpenRAG 拒绝路径**无结构化拒绝原因日志**，排障成本高（同类问题再次定位仍需多口径抓取） |

## 3. R-387 派单内容（设计议题）

### 3.1 交付要求

1. **冲突清单**：逐一列出 OpenBase 侧租户码（联调/默认/示例）与四仓「保留码 / 本地码」的取值与语义来源，标注同名项。
2. **方案选项（至少 2 个）与判定依据**：例如 ① OpenBase 侧联调租户码前缀化/改名；② `rag-proxy` 侧建立「跨域租户码映射表」；③ 目标侧新增「可信代理来源可携带保留码」白名单（需评估防护削弱风险）。
3. **触发条件（本派单的关键判据）**：明确**何时必须由「方案 B（不注入）」回到「注入模式」**，例如：当出现需按租户隔离检索的场景、或 OpenRAG 侧支持非保留码的可信代理映射时。该条件一旦满足，须同步调整 `settings.rag_inject_identity_headers` 与编排器声明。
4. **影响面与回滚**：受影响的接口、编排器 env、护栏用例与文档清单。

### 3.2 验收标准

| # | 验收项 | 通过标准 |
|:-:|--------|---------|
| 1 | 冲突清单完整 | 覆盖 OpenBase 默认/联调租户码与四仓保留码，逐项给出取值、语义与冲突判定 |
| 2 | 方案可选可评 | ≥2 个方案，含优劣、成本、风险与对既有防护语义的影响 |
| 3 | 触发条件可执行 | 以「可观测事件或配置状态」表述，可直接转成版本规划输入 |
| 4 | 与护栏一致 | 若结论涉及策略变更，`tests/test_rag_proxy_identity_policy.py` / `tests/test_bl147_trust_env_wiring.py` 必须同步更新并通过 |

## 4. R-388 派单内容（OpenRAG 仓，单点改造）

### 4.1 改造要点

1. **拒绝路径补结构化事件**：在 `identity_gate`（拒绝分支，如 `_reject`）补充一条结构化拒绝日志事件，字段建议与既有 `request_started` / `request_completed` 同构：
   - 必含：`ts`、`request_id`、`status_code`、**`reject_reason`**（如 `BIZ_RESERVED_TENANT_CODE_COLLISION` 等错误码）、`principal/tenant`（若有）。
   - 建议：保留 `path` / `method` 与判定入口标识，便于与网关侧串联比对。
2. **与 JSONL 契约一致**：输出须落在既有结构化流（`OPENRAG_LOG_JSON` 开启时），保持四仓 JSONL 契约（`ts` / `request_id` / `method` / `path` / `status_code` 为**数字**）。
3. **不改判定逻辑**：仅补日志，不改变拒绝条件与状态码语义。

### 4.2 验收标准

| # | 验收项 | 通过标准 |
|:-:|--------|---------|
| 1 | 拒绝事件可检索 | 触发保留码碰撞时，采集文件中可按 `request_id` 检索到含 `reject_reason` 的应用日志行 |
| 2 | 契约不变 | 该行 JSON 合法、`status_code` 为数字；不破坏既有 JSONL 契约判据 |
| 3 | 回归 | 该仓单测与回归通过，且不改变既有拒绝行为（状态码与响应体一致） |
