## 2. 设计原则与派生要求

原则由人工给定：以画像、记忆、知识库为基础把上下文补得更准，同时把投喂给 LLM 的 token 压得更省。

两条要求互相拉扯，更准要求多给，更省要求少给。编排的实质工作是在固定预算内按相关性选择，而非把素材拼长。由此派生四条要求：

| 要求 | 含义 | 现状 |
|------|------|:----:|
| 先排序后裁剪 | 裁剪必须发生在仍带相关性信息的结构化层面 | 不满足 |
| 预算含输出预留 | 预算 = 模型窗口 − 输出预留 − 安全余量 | 不满足 |
| 配额与竞争显式化 | 四类素材先给保底配额，余额按相关性竞争 | 不满足 |
| 裁剪可观测 | 丢弃了哪些片段、多少 token、原因，必须可查 | 不满足 |

## 4. 选定组合

**方案 B（编排归 OpenLLM）+ B2（结构化片段 + 配额保底 + 相关性竞争）+ 会话轴独立前置 + 双路径收敛 + 三路回写接齐（含流式）。** 该组合即本方案的实施对象；比选过程、不采纳理由与全部备选路线见评估报告 §5。

四条要点提示：B1（按条目尾截断）为过渡形态、B2 为终态；会话轴独立成条并作 R-395 的前置；双路径收敛为前置零；回写三路须接齐（含流式与画像）。

## 5. 统一方案设计

### 5.1 目标形态

会话是上下文的累积单位与预算的记账单位；画像、记忆、知识库、会话历史四类素材在**同一份会话预算**下竞争；编排负责选择与渲染，会话负责状态、序号与幂等。

### 5.2 四段实施链

| 段 | 内容 | 为什么在这个位置 |
|:--:|------|------------------|
| 前置零 | 双路径收敛（R-397，含 F-01） | 不收敛则后续每项都要双份实现，且行为漂移 |
| 第一批 | 会话轴接入（R-396）+ 三路回写接齐（R-398，含 F-09）+ 幂等键修正（F-08） | 同属会话维度，天然同批；会话轴以 `get_context_window` 对历史做窗口，不引入超窗；回写与读取共用同一会话标识 |
| 第二批 | 结构化片段 + 预算裁剪 + 可观测回执（R-395，含 F-02、F-06） | 输入集合已完整，配额与竞争规则只需调一次 |
| 第三批 | 回写质量与反馈：`save_if_valuable` 口径统一（F-10）、写入内容治理、回写携带本轮使用的上下文片段 | 闭环质量依赖前两段的键与选择能力，前置完成后才有意义 |

### 5.3 各段设计要点

**前置零（双路径收敛）**

把「组件执行 → 上下文格式化 → 预算 → 组装」抽为共用步骤，供 `/chat` 与 `/chat/stream` 共用；流式路径补齐回写与缓存语义，或显式声明不提供并写入契约。`model="auto"` 与 `mode="auto"` 在两路径行为一致。

**第一批（会话轴与回写接线）**

OpenLLM 侧把 `messages` 的历史按窗口纳入上下文，用 `ContextManager.get_context_window` 或等价的按 `max_tokens` 截取，而非只取最后一条 user 消息；`OpenLLMChatRequest` 增加会话标识字段；回写幂等键由 `user_id` 改为会话标识，`seq` 改用 DB 侧 `max_seq + 1`（替换进程内计数器）。会话标识字段为可选，缺省时退化为按用户记账，保持既有调用方兼容。

回写三路接齐：流式路径补齐 memory 与 rag 回写（当前完全没有）；编排链路把 profile 一路纳入回写回调（当前只有 memory 与 rag 两个回调参数）；回写通道的失败不得影响主链路，沿用既有的异步队列与退避重试。

**第二批（预算与选择）**

`format_context` 之前保留结构化片段（含 `score`、来源、时间）；预算取 `(get_model_context_limit(model) − 输出预留) × 安全余量`；四类素材先给保底配额，余额按相关性竞争；裁剪按条目切分而非按字符切分，单条超预算时做文本级截断并标记；裁剪后二次计数校验，仍超预算则显式降级，不放行也不静默丢弃。

**第三批（回写质量与反馈）**

`save_if_valuable` 的判定口径在 API 路径与编排选项路径之间统一为同一实现；写入内容加治理，模型生成文本进入知识库前须经价值判定，避免自引用污染；回写 payload 除 `query` 与 `response` 外，携带本轮实际使用的上下文片段标识与得分，使下一轮可据此做记忆价值的强化与衰减。

### 5.4 可观测回执

`routing_trace` 增补预算回执：模型、窗口、输出预留、实际预算、裁剪前后 token 数、被丢弃片段清单与原因、是否发生硬截断。无回执视为该段未完成，否则「精准」既无法验证也无法调优。

回写侧同步增补回执：三路各自的受理状态（accepted / duplicated / failed）、投递序号、被丢弃片段标识。回写静默失败是当前最难察觉的一类问题（见 F-08、F-09），回执是其唯一可见性来源。

## 6. 改动面与跨仓边界

问题「是否所有改动都在 OpenLLM 侧」经核实**不成立**，实际为三方触达。

| 触达方 | 需要的改动 | 依据 |
|--------|------------|------|
| **OpenLLM（主体）** | 编排与预算能力、会话轴接入、三路回写接齐、双路径收敛、回写幂等键修正、窗口前缀匹配修正 | 评估报告 §3 |
| **前端（openbase-ui）** | 发消息时提交会话标识（当前只提交 `{ model, messages }`，`llm.ts:101`、`:113`）；历史已随 `messages` 提交，无需改造 | 同上 |
| **本仓文档** | R-394 的编排 DSL 边界定界（口径整合，不涉代码） | 评估报告 §7 |
| **OpenBase 网关** | **无需改动**：`llm_chat(payload: dict[str, Any])` 原样转发请求体（`llm_proxy/__init__.py:355-366`），新增字段直接透传 | 代码实测 |

由此得到对「是否都放在 OpenLLM 侧会话里迭代」的准确回答：**在 OpenLLM 侧以「会话」为迭代主题归集这些方案是合理的，但不应把它们都归到「会话模块」里实现。** 编排还依赖模型路由（`core/router.py`）、组件适配器、配额中间件与语义缓存，这些不在会话域；预算裁剪的落点在 `orchestration/`，双路径收敛的落点在网关入口。硬合会让会话模块承担全部职责。

主题归集与模块归属是两件事：**主题按「会话」归集（一个迭代主题下挂 R-395 / R-396 / R-397 / R-398 与 F-01 / F-02 / F-06 / F-07 / F-08 / F-09 / F-10），实现按模块落位（会话域 / 编排域 / 网关入口）。**

本仓不实施上述 OpenLLM 侧改动（`VC-014`），一律走跨仓派单。

## 7. 登记与承接建议

登记载体的判据：既有债务走技术债务总表（TD）；发布期发现的缺陷走问题跟踪记录（DEF）；能力缺口与设计取舍走候选需求池（R）；跨仓执行走 `doc/planning/` 派单项。本轮各发现均为评估期发现的既有缺口，非 v1.4.7 发布缺陷，故主要归 TD 与 R。

| 对象 | 载体 | 级别 |
|------|------|:----:|
| 回写未接线（F-09） | 候选需求池 **R-398** + 技术债务总表 **TD-新增-022** | P1 |
| 回写幂等键（F-08） | 技术债务总表 **TD-新增-023** + 派单项修正项 | P1 |
| 会话轴缺位（F-07） | 候选需求池 **R-396**（本体即需求，不另建 TD） | P2 |
| 双路径分叉（F-01） | 候选需求池 **R-397** + 技术债务总表 **TD-新增-024** | P2 |
| 窗口前缀匹配（F-02） | 随 R-395 修正，不单独建 ID + **TD-新增-025** | P2 |
| 裁剪方法不二次校验（F-06） | 随 R-395 修正，不单独建 ID + **TD-新增-026** | P2 |
| 写入质量开关失效（F-10） | 随 R-398 修正，不单独建 ID | P2 |
| 预算裁剪缺位（F-11） | 候选需求池 **R-395**（本体即需求，不另建 TD） | 高 |
| 编排归属与 DSL 边界（F-12） | 候选需求池 **R-394**（文档口径整合） | 中高 |
| 固定 1000 配额、死参数、system_prompt 恒空（F-03~F-05） | 仅记录于评估报告 | P3 |

F-08 与 F-09 建议走立即登记而非「延后到版本收口复核」的既有范式：该范式的理由是避免归属未定的设计议题反复改版，而两者定性明确（F-08 有他仓 P1 先例、F-09 是能力已实现但未接线）、范围固定，不属于该情形。F-08 的前提是先复现。

### 8.3 验收判据与测试策略

| 层级 | 用例要点 |
|------|----------|
| 单测 | 正常裁剪；**单片段即超预算**（触发文本级硬截断）；空上下文（无 memory / 无 rag）；超长 query（唯一必须保留项本身超预算时的显式降级）；**日期化模型名**（`gpt-4o-2024-08-06` → 须得 128000 而非 8192，回归 F-02）；预算恰好等于片段总和（边界不裁） |
| 集成 | 同一输入分别打 `/openllm/v1/chat` 与 `/chat/stream`，断言两路径 prompt token **均 ≤ 预算**且丢弃清单一致（防止第三处实现分叉） |
| 回写 | 三路各自受理状态可查；`session_id + seq + target` 幂等语义在**会话维度**成立；重启后不再静默丢写（F-08 回归用例）；`save_if_valuable=false` 时知识库不写入（F-10 回归用例） |
| 回归 | 本仓无代码变更，既有 4 仓回归基线不受影响；OpenLLM 侧须补其自身回归 |
| 证据 | 裁剪前后 token 数、丢弃片段清单及原因、`routing_trace` 预算与回写回执快照 |
