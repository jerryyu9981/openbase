## 1. 建议摘要

| 序 | 方案 | 内容 | 工作量 | 结论 |
|:--:|------|------|:------:|------|
| **A** | **拆双小版本（已采纳）** | **v1.4.8** = 第零段 + 前置零 + 第一批；**v1.4.9** = 第二批 + 第三批 | 14.5~20 + 14~18 人天 | **采纳**（2026-09-21 裁定） |
| B | 单版本承载 | v1.4.8 = 五段全套 | 28~37 人天 | 未采纳（超出小版本容量口径，风险隔离与可证伪性均下降） |

**推荐方案 A 的核心判断：v1.4.8 应承载「第零段 + 前置零 + 第一批」，因为它同时满足三件不可替代的事——把两个 P1 债务直接闭合、让「精准」在本版本内可被证伪、并把唯一会改变模型输入内容（第二批裁剪与第三批写入）的有损改动隔离到 v1.4.9。**

## 2. 决策依据

### 2.1 依赖链决定拆分点

五段实施链（《统一方案》§13.2）的顺序不是人为安排，而是依赖约束：

| 段 | 依赖关系 | 能否与后续段解耦 |
|:--:|----------|:----------------:|
| 第零段（基线工装 + F-02） | 无前置；只观测不改行为 | 可独立交付、独立验收 |
| 前置零（R-397 双路径收敛） | 无前置；可并行于第零段 | 可独立交付 |
| 第一批（R-396 + R-398 + F-08） | 会话轴与回写共用同一会话标识，必须同批 | 可独立交付（前两段完成后） |
| 第二批（R-395 预算裁剪） | 依赖会话轴，输入集合须先完整 | 依赖 v1.4.8 全部 |
| 第三批（回写质量与反馈） | 依赖前两段的键与选择能力 | 依赖 v1.4.9 第二批 |

**拆分点在「第一批 / 第二批」之间**：此处依赖最松、且是「修缺陷与补接线」到「改模型输入内容」的性质转折点。

### 2.2 还债优先：v1.4.8 直接闭合两个 P1

《技术债务总表》0.0a 跨版本债务审查（2026-09-21 复核）：

| 检查项 | 结果 |
|--------|------|
| 待偿还 | **16** 项（含 P1 两项：TD-新增-022、TD-新增-023） |
| 挂起中 | 1 项（连续挂起版本数 0） |
| 老化升级触发 | **无**（P3 挂起 >2 / P2 >2 / P1 >2 均未满足） |

| 版本 | 还债项 | 债务数 | Backlog 条目数 | 还债占比 | 门禁 |
|------|--------|:------:|:--------------:|:--------:|:----:|
| **v1.4.8** | TD-新增-022（P1 回写未接线）、TD-新增-023（P1 幂等键）、TD-新增-024（P2 双路径分叉）、TD-新增-025（P2 窗口前缀） | 4 | 8 | **4/8 = 50%** | ≥15% ✅ |
| **v1.4.9** | TD-新增-026（P2 裁剪无二次校验） | 1 | 4 | **1/4 = 25%** | ≥15% ✅ |

两项 P1 均为**静默数据丢失**（回写恒不执行 / 重启后前 N 次丢弃，F-08 已实测复现），属「数据完整性」级别，按 P1+ 优先原则应最紧排期。

### 2.3 可证伪性：v1.4.8 内可闭环「测量 → 改进」

这是方案 A 相较方案 B 的关键优势，也是上一轮刚落地的基线测量方案（《统一方案》§16.4）的直接推论：

- 第零段交付后方能测 **B0**（现状绝对水平）
- 第一批交付后方能测 **B1**
- **B0 → B1 的差值即证明或证伪 P1 精准与 P3 回写两条原则**

若把五段压在一个版本内，B0/B1 虽仍在版本内可测，但 B2/B3 与三个待定阈值（注入片段相关性下限、预算利用率区间、回写受理成功率）的回填全部挤在同一版本末尾，**基线数据来不及反馈到裁剪参数上**，等于失去了「先测基线、后定阈值」的意义。拆开后 v1.4.8 的 B0/B1 数据正好成为 v1.4.9 三项阈值的输入。

### 2.4 风险隔离：有损改动单独成版

| 段 | 对模型输入的影响 | 风险性质 |
|:--:|------------------|----------|
| 第零段 | 无（只观测） | 无 |
| 前置零 | 无（仅统一两路径行为） | 低 |
| 第一批 | 增加历史素材、回写开始生效 | 低（只增不减） |
| **第二批** | **裁剪上下文（可能损精准）** | **中高（唯一有损改动）** |
| **第三批** | **改变知识库写入内容** | **中（影响库质量）** |

把两个有损改动放在 v1.4.9 独立成版，可独立回退而不牵连 v1.4.8 已交付的缺陷修复。

### 2.5 容量与节奏

| 版本 | 工作量（人天，估算值） | 折合周 | 与《版本规划总纲》§5.2 口径 |
|------|:----------------------:|:------:|------------------------------|
| v1.4.8 | 14.5~20（第零段 3.5~5 + 前置零 3~4 + 第一批 6~8 + 基线测量 2~3） | ≈2~2.5 周 | 落在 1.4.x 承接线区间（v1.4.7 为 ≈1.5~2 周 / 12~15 人天） |
| v1.4.9 | 14~18（第二批 8~9 + 第三批 4~6 + 基线测量 2~3） | ≈2 周 | 同上 |
| 合并（方案 B） | 28~37 | ≈3.5~4.5 周 | **超出单版本容量口径**，与 v1.5 前置准备窗口冲突 |

### 2.6 为何不并入 v1.5

v1.5 的前置门禁为「基础设施（OTel / Vault / OpenLLM virtual_key）就绪」，而 v1.4.7 的 Step 5 收口实测显示：`otel_enabled=False`、`langfuse_enabled=False`、无监控栈文件、无 Vault。门禁未满足 → **v1.5 排期不确定**。把两个 P1 数据丢失修复挂在 v1.5 上，等于无限期拖延。此外 v1.5 主题为「统一集成测试 + 平台治理」，与本次「会话上下文编排能力补齐」不同源，混入会稀释两个主题的验收边界。

### 3.2 v1.4.9 — 上下文预算与回写质量（承接型小版本）

#### 3.2.1 版本目标（可衡量）

| # | 目标 | 量化成功指标 |
|:-:|------|--------------|
| 1 | **超窗归零**（P2） | **超窗发生率 = 0**（硬判据） |
| 2 | **token 更省且不损精准**（P2） | 无效上下文占比（WCR）较 B1 **下降**，且人工走测评分**不低于** B1；预算利用率落入 B1 数据回填的区间 |
| 3 | **选择可追溯** | 预算回执齐备（模型/窗口/输出预留/实际预算/裁剪前后 token/被丢弃片段及原因/是否硬截断），覆盖率 **100%** |
| 4 | **写入不再自污染**（P3） | `save_if_valuable=false` 时知识库不写入；知识库写入价值判定拦截率可观测 |
