## §1 背景与来源

| 项 | 内容 |
|----|------|
| 触发事件 | OpenBase 侧 R-387 收口（`DEF-BE-1410-001`：rag-proxy 写类端点恒 403）完成后，依据人工指令「纳入统一码空间收口」，对**各下游可接受码空间**逐目标实测 |
| 实测发现 | OpenMemory 按**组织策略 fail-closed**，**仅登记 `default`**；对 OpenBase `tenants.code` 中的 `tenant-1`/`tenant-2` 返回 **403「组织 'X' 不存在或未配置策略，按 fail-closed 拒绝访问」** |
| 结果 | OpenBase 无法单方面把 memory 目标统一到非保留码（`tenant-1`）；**全量统一以本派单交付为前提** |
| 为何需派单 | ① 属 OpenMemory 侧组织/租户策略登记（数据或配置面），非本仓可改；② 若不登记，OpenBase 侧「统一码空间」只能维持**按目标两套码值**（rag=`tenant-1`、memory=`default`），且 `oidc_default_tenant` 与本地 IdP 演示用户池的保留码消除**被一并阻塞** |

**实测摘录**（2026-10-08，直连 `http://127.0.0.1:8020`，双层认证）：

| 调用 | 租户头 | 结果 |
|------|-------|------|
| `POST /api/v1/recall` | 无 | **200** |
| `POST /api/v1/recall` | `X-Tenant-ID: default` | **200** |
| `POST /api/v1/recall` | `X-Tenant-ID: tenant-1` | **403** `组织 'tenant-1' 不存在或未配置策略，按 fail-closed 拒绝访问` |
| `POST /api/v1/recall` | `X-Tenant-ID: tenant-2` | **403**（同上，码值为 `tenant-2`） |

## §2 派单范围

| 序号 | 需求 | 归属 | 性质 | 优先级 |
|:----:|------|------|------|:------:|
| 1 | **登记目标组织码**（使 OpenMemory 接受 OpenBase `tenants.code` 的租户码，至少 `tenant-1`） | OpenMemory 仓 | 配置/数据登记 | **P2**（阻塞 OpenBase 侧码空间统一，不阻塞 OpenMemory 自身功能） |
| 2 | （可选）提供**组织码登记接口或脚本**，供上游按需登记 | OpenMemory 仓 | 可运维性 | P3 |

**明确不做（本轮边界）**：① **不**要求 OpenMemory 放宽 fail-closed 语义（该防护有效且方向正确）；② **不**要求其接受任意未登记码；③ OpenBase 侧在登记完成前**保持 memory 目标码值为 `default`**（不擅自切换，避免造成记忆链路 403）。

---

## §3 交付内容

1. **登记组织码 `tenant-1`（及其后按需的其他 `tenants.code`）**：使其通过组织策略校验，`POST /api/v1/recall`、`POST /api/v1/remember` 等业务端点在该组织下可正常放行。
2. **保持既有 semantics 不变**：保留码/fail-closed 行为对**未登记**码值继续生效；不得为本次登记放宽任何防护。
3. **登记方式可重复执行**（幂等），并给出登记来源说明（配置文件 / 种子数据 / 登记接口，以 OpenMemory 仓自身既有机制为准）。
4. **登记范围说明**：明确「已登记组织码清单」的查询方式与维护责任方，便于跨仓对账。

---

## §4 验收标准

| # | 验收项 | 通过标准 |
|:-:|--------|---------|
| 1 | 组织码可放行 | 以 `X-API-Key` + 受信代理来源 + `Authorization: Bearer <OpenBase 用户 JWT>` + `X-Tenant-ID: tenant-1` 调用 `POST /api/v1/recall` → **2xx** |
| 2 | 写路径可放行 | 同头部调用 `POST /api/v1/remember`（角色具备写权限）→ **2xx**；写入后可按 `memory_id` 清理 |
| 3 | 未登记码仍拒 | `X-Tenant-ID: <未登记码>` → **仍 403**「组织不存在或未配置策略」（**防护未放宽**的负向断言） |
| 4 | 既有行为不回归 | 既有 `default` / 无租户头调用仍 **2xx**；该仓单测与回归通过 |
| 5 | 清单可对账 | 提供「已登记组织码清单」查询方式，且与 OpenBase `tenants.code` 可逐项比对 |
| 6 | 回执留痕 | 按 §6 回执字段登记 commit / 配置变更 / 验证结果 |

## §5 前置与依赖

| 项 | 内容 |
|----|------|
| 前置 1 | 本派单**不阻塞** OpenBase 当前版本交付：OpenBase 侧已完成「按目标登记 + 护栏 + 可一处切换」（见上游依据 §11.2） |
| 前置 2 | OpenMemory 侧改造须走其自身评审/提交流程 |
| 依赖 3 | OpenBase 侧目标码值口径：`tenants.code` 为唯一事实源（`dps_code_map.py: SOURCE_OF_TRUTH`）；本派单建议至少登记 `tenant-1`（OpenBase 平台默认兜底码） |
| 解锁收益 | 登记完成后，OpenBase 仅需改 `OPENBASE_MEMORY_DEFAULT_TENANT_CODE` **一处配置**，即可与 `oidc_default_tenant`、本地 IdP 演示用户池**同批**完成全量统一（上游依据 §11.6 终态路线） |
