## 1. 目的与口径

### 1.1 目的

1. 把 R1~R7 收口后**仍然登记但未执行**的事项统一成一张台账，消除「文档里挂着、排期里没有」的盲区；
2. 把**跨仓未执行**（OpenLLM / OpenRAG / OpenMemory / DPS / 运维）与**本仓未执行**分开列账，明确责任方与前置条件；
3. 按依赖关系拆入**小版本迭代**（每个小版本 1~5 项、可独立验收、可独立回滚），避免再次出现大轮次混提交；
4. 明确「建设 / 收敛 / 冻结 / 不建设」四种处置，不再以 mock 填充。

| 来源 | 纳入内容 |

## 5. 依赖与顺序

```text
v1.9.8 处置窗口
  ├─ 服务可启动 ──→ v1.10.0 租户隔离 / OpenLLM 四页 / DPS 指标
  ├─ 四仓远程一致 ──→ 后续所有小版本可追溯
  └─ G1/G2/G7 ──→ 生产上线门禁
v1.10.0 ──→ v1.10.1（个人中心可独立并行）
v1.10.0 ──→ v1.10.2（治理收口依赖租户口径稳定）
v1.10.2 ──→ v1.11.0（长尾裁定需治理口径稳定）
```

**关键依赖**：

1. XR-LLM-02 依赖 R6 已完成的超时/N+1 修复，不得回退；
2. XR-LLM-01 必须先写列并回填，再开查询过滤，否则会误伤历史数据；
3. XR-DPS-01 与 OB 监控页扩展同批验收，避免前端先上后端口径变化；
4. XR-GOV-01 涉及三仓，按 OpenLLM → OpenRAG → OpenMemory 顺序回执；
5. XR-MEM-01 退役 `default` 前必须确认无存量依赖（影子期观测）。
