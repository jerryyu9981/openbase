## 3. 契约（强制）

### 3.1 三条基本原则与派生要求

| 原则 | 派生要求 | 落点 |
|:----:|----------|------|
| P1 精准 | 素材齐备（画像/记忆/知识库/会话历史四类全部参与，不可用须留降级记录） | 第一批 |
| P1 | 先排序后裁剪（裁剪须发生在仍带相关性信息的结构化层面，不得先拼字符串再截断） | 第二批 |
| P1 | 选择可追溯（注入了哪些片段、得分多少、是否被使用可查） | 第二批 + 第三批 |
| P2 省 token | 预算 = 模型窗口 − 输出预留 − 安全余量 | 第二批 |
| P2 | 配额与竞争显式化（四类素材先给保底配额，余额按相关性竞争） | 第二批 |
| P2 | 超窗显式降级（不得静默放行，也不得静默丢弃） | 第二批 |
| P3 回写 | 全路径接齐（同步与流式两条路径均须覆盖三路回写） | 第一批 |
| P3 | 幂等且不丢（幂等键回会话维度；序号取持久化来源） | 第一批 |
| P3 | 写入质量受控（模型生成文本入库前经价值判定） | 第三批 |
| P3 | 回写可观测（受理状态、投递序号、被丢弃项可查） | 第一批 |

### 3.2 回写幂等键契约（F-08 修正）

| 项 | 约定 |
|----|------|
| 键 | `(session_id, seq, target)`，其中 **`session_id` 必须为真实会话标识**，禁用 `identity.user_id` 顶替 |
| `seq` 取值 | **必须取持久化来源**：`WritebackStore.max_seq(session_id) + 1`；**禁止**使用模块级进程内计数器（`openllm_gateway.py:620-626`） |
| 依据 | F-08 实测复现：进程重启后计数器归零，`session_id=user_id` 且历史行已存在时 `INSERT OR IGNORE` 命中，`submit` 返回 False 且不执行 → **重启前 N 次回写全部静默丢弃**（实测 N=3，桩 handler 应执行 4 次实际 1 次） |
| 已有实现 | 独立 API 路径 `api/writeback.py:376-378` 已按 `max_seq+1` 修复（他仓 R-003）；编排路径未同步，本次即**补齐漏改** |
| 禁止 | 不得仅靠 `recover_pending` 自愈（它只重跑已入库行，不回填计数器） |

### 3.3 计量与回执契约（第零段）

| 字段组 | 必需字段 | 说明 |
|--------|----------|------|
| Prompt 组成 | `prompt_total_tokens`、`segment_tokens`（`system` / `profile` / `memory` / `rag` / `history` / `query` 分项） | 分母口径：四类素材注入片段之和，**不含** `query` 与输出 `max_tokens` 预留 |
| 检索快照 | `memory_items`、`rag_items`（条目数、各条 `score`、实际进入 prompt 的条目与 token） | 支撑 WCR 判定 |
| 预算回执 | `model_window`、`output_reserve`、`budget`、`tokens_before_trim`、`tokens_after_trim`、`dropped_fragments`（含原因）、`hard_truncated` | 第二批起必需 |
| 回写回执 | 三路各自的 `accepted` / `duplicated` / `failed`、投递 `seq`、被丢弃项标识 | 第一批起必需 |
| 维度字段 | `request_id`、会话标识、模型、时间戳 | 须可批量导出 |
| 禁止 | 记录令牌/密码/密钥/完整请求体；工装不得含裁剪、改写或截断逻辑 | — |

### 3.4 兼容与降级

1. 新增字段一律可选，缺省时保持既有行为（会话标识缺省 → 按用户记账；预算缺省 → 不裁剪但**须记录计量**）
2. 组件不可用一律降级不报错（沿用既有 `ComponentUnavailableError` 与 degraded 标记语义）
3. 回写通道失败不得影响主链路（沿用既有异步队列与指数退避 ≤3 次）

### 5.3 基线测量要求（第零段专项）

1. **时点**：B0（第零段后、前置零前，严格只观测）→ B0′（前置零后，可选）→ B1（第一批后）→ B2（第二批后）→ B3（第三批后）
2. **可比性**：只认同一方法、同一参数、同一固定集、同一模型下的**相邻点位差值**；B0 本身测不出改善，报告以差值为主
3. **WCR 口径**：`硬浪费片段 token / 注入上下文 token`；须同时给出软占用率与必要占用率（三者之和 = 1），不得只给单值
4. **归因方法**：A 引用检测（每次调用，主指标）+ B LLM 归因（抽样 ≥30 条，校准漏检率，判定模型优先不与被评模型同源）+ C 消融（一次性 10~15 条，效度检验）；**A 层数值只能纵向对比，不得作绝对值解读**
5. **人工走测**：7 场景矩阵、每场景 ≥5 条共 ≥35 条（含 2 组负例）、四维 1~5 分量表、固定 `temperature=0`、盲评 + ≥20% 样本间隔 ≥24h 复评算自一致性
6. **判定规则**：token 降但评分明显降 → **判失败**（以精准换 token）；评分升但 token 显著升 → 须预算利用率仍有余量且超窗率 = 0；指标未变须说明原因；数据不足记「不可判定」须重测

## 8. 边界、风险与约束

### 8.1 边界

1. 本派单**只覆盖 OpenLLM 仓**；OpenBase 侧仅保留评估与登记职责，不实施代码改动（`VC-014`）
2. 第零段作为 R-395 的**观测前置，不单独立项**，但在本派单中独立成段以便单独验收
3. 第零段不改行为，故**不视为 R-395 已完成**，亦不解除 TD-新增-025（F-02 仅是其最小偿还）

### 8.2 跨仓依赖（openbase-ui）

前端发消息当前只提交 `{ model, messages }`（`llm.ts:101`、`:113`），不带会话标识。第一批需前端提交会话标识，否则会话记账只能在 OpenLLM 侧按用户退化。**此项属 openbase-ui 仓，需另行派单。**

### 8.3 风险

| # | 风险 | 应对 |
|:-:|------|------|
| 1 | 第二批裁剪上线后「省了 token 但损了精准」 | §5.3 判定规则已约定「token 降但评分明显降即判失败」；裁剪由开关控制，可回退 |
| 2 | 第零段工装污染基线（顺手做了裁剪或改写） | 硬约束：第零段不得含裁剪逻辑；裁剪开关默认关闭 |
