## 1. 任务与目标

| 项 | 内容 |
|----|------|
| 背景 | 前端发消息当前只提交 `{ model, messages }`（`llm.ts:101`、`:113`），**不带会话标识**；导致 OpenLLM 侧会话记账只能退化为「按用户」，多轮会话无法按会话维度记账与回写（影响 P1 精准与 P3 回写闭环） |
| 目标 | 前端在发消息时提交**会话标识**，使 OpenLLM 侧可按真实会话维度记账、落库与回写 |
| 范围 | 接口层变更（请求体新增字段 + 会话标识的生成/维护/复用）；**无 UI 展示、无交互改造、无路由改造** |
| 不改动 | 历史消息传输方式（历史已随 `messages` 提交，**无需改造**） |

---

## 2. 契约（强制）

### 2.1 请求体字段

| 项 | 约定 |
|----|------|
| 字段名 | `session_id` |
| 类型 | 字符串（可选） |
| 提交位置 | 与 `model` / `messages` 同级，位于 `/chat` 与 `/chat/stream` 请求体 |
| 缺省行为 | **不提交时后端按用户记账**（既有调用方行为不变，前端可渐进接入） |
| 脱敏红线 | `session_id` **不得携带任何凭据类信息**（令牌 / 密码 / 密钥 / 用户隐私）；建议使用随机标识（如 UUID v4） |

```json
{
  "model": "auto",
  "messages": [ { "role": "user", "content": "..." } ],
  "session_id": "sess-8f3c1a2b-0001"
}
```

### 2.2 落点

| # | 落点 | 改动 |
|:-:|------|------|
| 1 | `openbase-ui/src/core/api/llm.ts:101` | 同步调用请求体新增 `session_id` |
| 2 | `openbase-ui/src/core/api/llm.ts:113` | 流式调用请求体新增 `session_id` |
| 3 | 会话标识的生成与维护 | 新建会话时生成；同一会话的后续轮次**复用同一标识**（前端会话生命周期内维护，具体载体由接收仓自定，如内存状态 / `sessionStorage`） |

---

## 3. 行为要求

| # | 要求 | 判据 |
|:-:|------|------|
| 1 | 同一会话多轮请求携带**同一** `session_id` | 抓包 / 日志可验 |
| 2 | 新建会话生成**新的** `session_id` | 抓包 / 日志可验 |
| 3 | 后端未识别该字段时行为不劣化（字段透传，前端不因缺省而报错） | 缺省回归 |
| 4 | 不引入界面变化（无新增/改造 UI） | 代码审查 |
| 5 | `session_id` 不含凭据类信息 | 代码审查（脱敏红线） |

---

## 4. 验收判据

| # | 判据 | 方式 |
|:-:|------|------|
| 1 | `/chat` 与 `/chat/stream` 请求体均携带 `session_id` | 接口 / 抓包 |
| 2 | 同一会话多轮 `session_id` 一致；不同会话互异 | 集成 |
| 3 | 缺省（不提交）时后端仍按用户记账，前端无异常 | 缺省回归 |
| 4 | 无界面交互改造（diff 仅限接口层与会话标识维护） | 代码审查 |
| 5 | OpenLLM 侧可按该标识检索到该会话的多轮回写记录（**端到端证据**） | 联调 / E2E |

> 判据 5 为端到端闭环证据：前端走流式路径的会话须能被后续会话检索到（派单验收总纲第 ④ 项）。

---

## 5. 边界、依赖与风险

| # | 项 | 说明 |
|:-:|----|------|
| 1 | 边界 | 本派单**只覆盖 openbase-ui 仓**；OpenLLM 侧字段消费属《会话编排派单-OpenLLM-v1.0.0》范围 |
| 2 | 依赖 | 依赖 OpenLLM 侧已支持 `session_id` 字段（否则字段被忽略，行为退化为按用户，不报错） |
| 3 | 风险 | 若前端不实施，则本版本会话记账与回写仍按用户退化 —— 本版本不因此判定失败，但 P1/P3 闭环证据不完整（记入遗留项） |
| 4 | 兼容 | 字段可选，前端可分阶段接入（先流式或先同步） |
| 5 | 交付物 | 本仓改动提交（独立可评审）+ 判据 1~5 的实测证据 |
