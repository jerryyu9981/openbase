## 3. 争议与决策

| 争议点 | 决策 | 依据 |
|--------|------|------|
| 版本拆分（原 v1.2.1~v1.5.0 四版本） | 合并为 v1.3.0 + v1.4.0 两版本（VC-003） | P0 26 项构成"四系统核心业务可用"完整闭环；与 VC-001 版本收敛原则一致 |
| 补全与对接顺序 | 先补全（P1-P2 OpenLLM），再对接（P3 OpenLLM），后续系统补全+对接同批 | 用户要求"先补全，再对接"；OpenLLM 先行验证代理链路后推广 |
| 已验证功能基线 | 以独立前端已验证实现为基线逐页"平移"，不重新设计 | 用户要求"尽量保留已验证接口的功能" |
| 402 错误处理 | 纳入 v1.3.0 Phase 1（BL-328，TD-新增-008） | 线上真实错误（模型提供商余额不足），代理层需统一包装 |
| 去 mock 时机 | OpenLLM 在 P3 统一替换；其余系统补全即对接真实 API | 避免双倍返工（先 mock 后替换） |
