## 1. 背景与问题

| 项 | 内容 |
|----|------|
| 背景 | v1.2.0 统一前端已发布（底座 + 动态模块 + 四个特色模块简化版），但经《OpenBase-统一前端与独立前端功能差距分析-v1.2.0.md》逐页核对，四系统独立前端已在生产/原型验证过的功能大量缺失或仅占位（24 个占位页、14 个页面为本地 mock），保留率仅 15%~25% |
| 问题 | ①四系统核心业务功能在统一前端不可用（无增删改查/筛选/导入导出/图表） ②页面均为 mock 数据，未对接四系统真实 API ③代理链路（/api/v1/proxy/*）后端已就绪但前端侧空白 ④模型提供商 402（余额不足）错误无统一处理 |
| 来源 | 功能差距分析报告 §8.1 P0 必须保留 26 项（VC-003 合并 v1.2.1/v1.3.0/v1.4.0 建议）+ 后端代理调研 + 线上问题（402） |

## 2. 版本目标

| 目标 | 描述 | 成功指标 |
|------|------|---------|
| G1 P0/P1 高耦合功能全保留 | 差距分析报告 P0 必须保留 26 项 + 高耦合 P1 4 项全部在统一前端真实实现（前端完整） | 30/30 项可用；占位页清零 |
| G2 基座调试完整（VC-005 调整） | 基座部分（登录/鉴权/路由/动态模块/公共组件/公共页面）与 OpenBase 后端调试完整 | 基座功能与后端联调 100% 通过；登录/鉴权/RBAC/动态模块 E2E 通过 |
| G3 已验证功能平移 | 以独立前端已验证实现为基线逐页"平移"，不重新设计已验证功能 | 逐页对照差异 0 项（组件/表单/图表复用，交互能力 ≥ 独立前端） |
| G4 质量门禁 | 前端测试与质量达标 | 前端测试通过率 100%、覆盖率 ≥80%、Lint 0 错误、E2E 走查通过 |
| G5 技术债偿还 | 占位页/mock 清理、基座代理链路、402 错误码三项债务处理 | TD-新增-006 清理；基座代理链路可用；402 统一错误响应可识别 |
| G6 四系统对接（挂起分批，VC-005） | OpenMemory/OpenRAG/OpenLLM/DPS 与后台接口对接调试挂起，后续按需分批进行 | 本版本不强制验收；前端按契约 mock 先行，对接批次后续排期 |

## 6. 关键风险与依赖

| 风险 | 级别 | 缓解 |
|------|------|------|
| R-301 四系统 API 契约与独立前端实现存在偏差（字段/端点不一致） | P1 | 对接前置接口契约核对（逐页对照独立前端实际调用）；契约缺口登记并走 v1.3.x 补 |
| R-302 流式对话（SSE）经代理透传存在兼容风险 | P1 | Phase 3 先行验证 SSE 透传链路（Playground 已留接入点）；失败则走独立通道 |
| R-303 独立前端组件抽取工作量大（React/Vue 混用） | P2 | 以交互能力对齐为准，不强制组件级复用；分批交付可回归 |
| R-304 四系统 Dev 实例未全部启动导致联调阻塞 | P1 | 依赖项确认：四系统 API 可访问（8001/8010/8020/8030）；未启动系统标记风险，先推进已启动系统 |
| R-305 本地模型/GPU 调度依赖宿主机 Ollama 环境 | P2 | 功能实现 + 环境缺失时降级提示，验收以 API 契约行为为准 |

## 7. 发布策略草案

| 项 | 内容 |
|----|------|
| 环境 | Dev 先行（四系统对接联调），Test/Pro 后续 |
| 分批 | 按系统分批交付（OpenLLM → OpenRAG → OpenMemory → DPS），每批独立可回归 |
| 灰度 | 前端静态资源灰度（10%→50%→100%） |
| 回滚 | 静态资源版本回退（保留上一版本目录）；代理链路关闭开关（proxy 模块可禁用） |
