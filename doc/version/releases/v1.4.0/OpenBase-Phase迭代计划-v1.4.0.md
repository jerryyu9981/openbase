## 1. Phase 拆分

| Phase | 时间 | 内容 | BL 项 | 里程碑 | 验收重点 |
|-------|------|------|-------|--------|---------|
| P1 | 第 1-2 周 | OpenLLM 高级功能：开源模型市场、下载管理、GPU 监控、Prompt 模板/实验 | BL-401~405 | OpenLLM 高级功能可用 | 市场/下载/GPU/模板/实验对接真实 API |
| P2 | 第 3-4 周 | OpenLLM 平台与系统管理：插件、工具调用、A/B、角色权限、组织用户、工作空间 | BL-406~411 | OpenLLM 平台管理可用 | 插件/工具/A-B + 系统管理 CRUD 对接 |
| P3 | 第 5-6 周 | OpenLLM 配置与审计：配置管理、审计日志、EdgeRouter、文档中心、计费 | BL-412~416 | OpenLLM 管理完备 | 配置热加载/审计/EdgeRouter/计费对接 |
| P4 | 第 7-8 周 | OpenRAG 管理后台 + OpenMemory 监控工具 | BL-417~419 | OpenRAG/OpenMemory 管理可用 | 管理概览/控制台/系统监控/API 测试对接 |
| P5 | 第 9-10 周 | DPS 管理与监控：限流、API 管理、权限、系统监控 + P2 项 | BL-420~424 | DPS 管理完备 | 限流/API 管理/权限/监控 + P2 项对接 |
| P6 | 第 11-12 周 | 生态工具链：测试基座 + 示例项目 | BL-426, BL-428 | 生态基座可用 | 测试基座覆盖率门槛生效；示例项目可运行 |
| P7 | 第 13-14 周 | 生态工具链：i18n + 文档站点 + 全量回归 + E2E 走查 + 三环境部署验收 | BL-425, BL-427, BL-401~428 | v1.4.0 发布 | i18n 全页面覆盖；文档站点上线；测试 100%、覆盖率 ≥80%、Lint 0 |
| P8 | 第 3-10 周（与 P2~P5 并行） | 统一网关后端（S1-1~S1-4）：gateway 模块 + DiscoveryProvider 抽象 + ConfigProbeProvider + scheduler 健康探测 + 加权轮询/故障剔除 + `/api/v1/services` 注册表 + `/api/v1/gateway/aggregate` 代码式并发聚合 | BL-429~430 | 网关后端能力可用 | 实例健康感知 ≤30s；连续 3 次失败剔除/冷却恢复；aggregate 并发聚合 2~3 子请求正确 |
| P9 | 第 13-14 周（与 P7 并行） | 统一网关收尾（S1-5~S1-6）：proxy `_resolve_base_url` → `DiscoveryRegistry.pick` 改造 + 网关管理前端页（服务列表/健康状态/聚合测试）+ 指标 + 全量回归 + 三环境部署验收 | BL-429~430 | 网关随 v1.4.0 发布 | 静态表兜底向后兼容；`/api/v1/modules` 不受影响；开关 `gateway.discovery.enabled=false` 可回退 |
