## 1. Phase 总览

| Phase | 主题 | 任务 | 周期 | 门禁 |
|:-----:|------|------|:----:|------|
| **Phase 1** | 前置核实 + 跨仓施工（批 A/批 B） | BL-147-01、BL-147-02、BL-147-03 | **约 1 周**（不含四仓排期等待） | 6.0 三项核实结论齐备；四仓回执（commit hash + 单测 + 回归）齐备；四仓日志携带 `request_id` 且写出 JSONL |
| **Phase 2** | 采集对齐 + 端到端验收 + 收口 | BL-147-04、BL-147-05 | **约 0.5~1 周** | 采集命名对齐生效；串联一致性抽样 ≥20 次 100% 一致；日志中心可检索四仓；四仓与本仓回归通过；TD-新增-020 偿还登记 |

**总周期**：约 1.5~2 周（单人串行；四仓排期为外部等待，不计入本仓工时）。

**依赖顺序**：Phase 1 的 6.0 前置核实为**硬门禁**（未产出结论不得动四仓代码）；BL-147-02 与 BL-147-03 **建议合并同批施工**（省一轮跨仓评审/提交/回归 ≈8h）；Phase 2 依赖 Phase 1 四仓回执齐备。

## 2. Phase 1 详情（前置核实 + 跨仓施工）

| 序 | 任务 | 交付物 | 关联 |
|:--:|------|--------|------|
| 1.0 | **前置核实三项**（跨仓开工前必做） | 前置核实记录（3 项结论） | BL-147-01 |
| 1.1 | **批 A：D-6 四仓 `request_id` 接线**（4 仓 / 7 文件；各仓独立评审与提交） | 四仓改动 + 各仓单测 + 各仓 commit hash | BL-147-02 |
| 1.2 | **批 B：四仓日志结构化（JSONL）**（字段按《施工派单》§5 契约对齐） | 四仓格式改造 + 样例行 + 解析验证 | BL-147-03 |

**Phase 1 门禁**：

| 门禁项 | 判据 |
|-------|------|
| 6.0 核实结论 | 三项均有书面结论（含 OpenMemory 启动路径定论与 OpenRAG 栈单一来源定论） |
| 四仓接线就绪 | 四仓日志中出现 `request_id`，且与网关出站头取值一致（各仓自测 + 抽样比对） |
| 四仓结构化就绪 | 采集文件每行为合法 JSON，含 `ts`/`request_id`/`method`/`path`/`status_code`（数字）/`duration_ms` |
| 跨仓凭据 | 各仓评审记录 + commit hash + 回归证据（按《施工派单》§9 回执要求） |
| 降级声明 | 若某仓未就绪 → 显式标注覆盖范围，**不得静默降级**（沿用 Phase 6 降级条款） |

## 3. Phase 2 详情（采集对齐 + 验收 + 收口）

| 序 | 任务 | 交付物 | 关联 |
|:--:|------|--------|------|
| 2.1 | **采集按日切分与命名对齐**（编排器输出 `{svc}-YYYYMMDD.jsonl`；OpenRAG 启动时间戳命名收口） | 编排器改造 + 命名实测 | BL-147-04 |
| 2.2 | **端到端串联与接入验收**（串联一致性抽样；日志中心 `source=repo_log` + `module` 检索；本仓侧适配器 JSONL 优先路径实数据复核） | 验收证据（抽样比对记录 + 检索截图/JSON） | BL-147-05 |
| 2.3 | **四仓与本仓回归** | 各仓回归报告 + 本仓回归结果 | BL-147-05 |
| 2.4 | **收口登记** | TD-新增-020 状态 → 已偿还；覆盖状态说明回填四仓 hash；本仓 tag `v1.4.7` | BL-147-05 |

**Phase 2 门禁**：

| 门禁项 | 判据 |
|-------|------|
| 串联一致性 | ≥20 次请求抽样，网关 ↔ 四仓 `request_id` **100% 一致** |
| 可检索 | 四仓各 ≥1 条按 `request_id` 反查命中（`source=repo_log`） |
| JSONL 可解析 | 抽样 **100% 行为合法 JSON** 且 `status_code` 为数字 |
| 回归 | 四仓回归全通过；本仓回归无新增失败（`pytest` / `ruff`） |
| 收口 | TD-新增-020 偿还；本仓 tag 创建并推送双远程 |
