## 1. 版本目标（可衡量）

| # | 目标 | 量化成功指标 |
|:-:|------|-------------|
| 1 | 四仓请求日志携带 `request_id`，取值与网关出站头 `X-Request-Id` 完全一致 | **四仓接线完成率 4/4**；串联一致性抽样 **≥20 次请求，100% 命中且取值一致** |

| 3 | 日志中心可检索四仓日志（`source=repo_log` + `module` 维度） | 四仓各 **≥1 条端到端检索命中**（按 `request_id` 反查） |

## 2. 版本范围

| 序 | 内容 | 关联 | 归属 |
|:--:|------|------|------|
| 1 | **6.0 前置核实三项**（OpenMemory 实际启动路径与根 logger；OpenRAG 日志栈单一来源；四仓受信来源判定口径） | Phase 6 任务 6.0 | 本仓（核实）+ 四仓（配合） |

## 7. 版本发布策略草案

| 项 | 内容 |
|----|------|
| 发布方式 | Dev 环境直接部署（沿用 v1.4.6 方式：后端 uvicorn 8000 + 前端 vite 5173） |
| 跨仓发布 | **四仓各自独立评审、提交与发布**（各仓 tag 由各仓自建）；本仓发布不含四仓代码 |
| 本仓 tag | `v1.4.7`（在四仓回执齐备且验收通过后创建） |
| 回滚策略 | 本仓无 DB schema 变更；回滚为代码回退（`git revert` / 切回 `v1.4.6`） |
| 兼容策略 | 适配器保持「JSONL 优先 + 纯文本回退」，四仓未就绪亦可降级运行（不静默降级） |
| 验收前置 | 四仓回执（commit hash + 回归证据 + 单测）齐备 |
