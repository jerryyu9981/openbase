## 1. 版本概述

### 1.1 版本定位

| 项 | 内容 |
|----|------|
| 版本主题 | OpenLLM 系统对接（1.4.x 逐个系统对接线第 1 站，共 4 站） |
| 版本类型 | 系统对接增量版本 |
| 基线 | v1.4.2（Step 5 已部署发布，全流程闭环） |
| 周期 | 2 周（Phase 1 OpenLLM 服务接入 + Phase 2 proxy 转发适配 + Phase 3 前端真实化 + Phase 4 联调收尾） |

### 1.2 背景与问题

| # | 问题 |
|---|------|
| ① | 用户决策（VC-011，2026-08-30）："OpenBase 的后续版本规划先暂时小版本一个一个对接，完成初步测试之后，再进行所有的统一集成测试"；对接从 v1.4.3 开始，四系统对接线为 v1.4.3 OpenLLM → v1.4.4 OpenRAG → v1.4.5 DPS → v1.5 统一集成测试 + 平台治理 |
| ② | v1.4.2 已完成 OpenMemory 对接（R-378）并沉淀可复用模式：双层认证（X-API-Key + JWT Bearer）共享、memory-proxy 转发适配、前端真实化、双系统联调，v1.4.3 OpenLLM 对接对标复用该模式 |
| ③ | OpenBase 网关已具备四系统服务发现骨架（openllm/openrag/openmemory/dps 循环探测 + 注册），但 OpenLLM 仅停留在服务发现层，无业务 proxy 转发、无认证适配、前端 OpenLLM 相关页仍为占位/mock（候选需求池 R-301~R-312 为 v1.3.0 目标的历史条目） |
| ④ | OpenLLM 后端（backend/main.py，PORT 环境变量可覆盖，默认 8000）需以 8001 端口启动，与 OpenBase 8000 并存；具备独立认证体系（JWT + Redis，OpenLLM-v2.x 系列） |

### 1.3 版本目标

| 目标 ID | 目标 | 验收指标 |
|---------|------|---------|
| G1 | OpenLLM 服务就绪 | OpenLLM 后端以 8001 启动，健康检查通过，PG/Redis 依赖可用，与 OpenBase 8000 并存无冲突 |
| G2 | 认证适配打通 | OpenBase 与 OpenLLM 认证契约对齐：OpenBase 侧适配 OpenLLM 认证通道（JWT/API Key 注入），共享密钥或网关签名配置可复现 |
| G3 | proxy 转发适配 | OpenLLM 业务路由经 OpenBase 代理（模型列表/详情/对话等核心只读+读写端点），统一响应 {code,message,data,timestamp} 适配，错误透传（error>code>detail） |
| G4 | 前端真实化 | OpenLLM 相关页 mock/占位替换为真实 API（走 OpenBase proxy，前端不接触 OpenLLM 密钥），核心页：模型管理/对话管理 |
| G5 | 双系统联调闭环 | OpenBase 统一认证 → OpenLLM 模型列表/对话真实闭环；集成测试 + UAT 走查；初步测试完成（为 v1.4.4 预留对接模式基线） |

## 3. 范围

### 3.1 包含范围（四 Phase）

**Phase 1：OpenLLM 服务接入（0.5 周）** —— 以 8001 启动 OpenLLM 后端，健康检查、依赖可用性验证，与 OpenBase 并存

**Phase 2：认证适配 + proxy 转发（0.5 周）** —— OpenBase 侧 OpenLLM 认证通道适配（JWT/API Key 注入）+ llm-proxy 转发适配（模型列表/详情/对话核心端点，统一响应适配 + 错误透传）

**Phase 3：前端真实化（0.5 周）** —— 模型管理/对话管理核心页 mock/占位替换为真实 API（走 OpenBase proxy）

**Phase 4：联调收尾（0.5 周）** —— 双系统联调（登录→模型列表→对话闭环）、集成测试、UAT 走查、回归 + 覆盖率、Step 4/5 文档、发布

## 4. 版本成功指标

| 指标 | 目标 |
|------|------|
| OpenLLM 服务 | 8001 健康检查通过，PG/Redis 依赖可用，与 OpenBase 8000 并存无冲突 |
| proxy 端点 | 核心业务端点经 OpenBase 代理 ≥5 个（模型列表/详情/对话等），响应适配 + 错误透传正确 |
| 前端真实化 | 模型管理/对话管理 2 页 mock/占位替换为真实 API（走 proxy，无密钥接触） |
| 联调闭环 | OpenBase 统一认证 → OpenLLM 业务闭环（模型列表 + 对话）真实可用 |
| 质量门槛 | 全量回归通过率 ≥95%；覆盖率 ≥80%（承接 v1.4.2 测试基座）；无新增 P0/P1 缺陷；Step 4/5 文档齐备 |
