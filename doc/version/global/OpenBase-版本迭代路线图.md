**前端整合方案**（来源：OpenLLM 方案 §15.7）：
- 四系统共用一套统一前端（vue-vben-admin），不单独建站，不存在五套独立前端
- 模块归属：公共模块（OpenBase 必启，常显）+ 动态业务模块（OpenLLM/OpenRAG/OpenMemory/DPS 域，服务发现驱动显隐）
- 共用/独立双模式：一套代码库，构建配置控制业务域模块加载；共用模式（四系统整体部署）+ 独立模式（单系统单独部署）
- 菜单分组："系统管理"分组（OpenBase 公共模块，常显）+ 各业务域分组（动态，服务发现驱动）
- OpenBase 必启约束：登录依赖 OpenBase auth API，部署编排中先行启动

**前端统一策略**：
- **一套统一前端**：OpenLLM/OpenRAG/OpenMemory/DPS 四系统共用一套统一前端，不存在五套独立前端
- **择优抽取而非从零新建**：从四系统现有前端中逐模块挑选最完整、最成熟的实现，作为统一前端对应模块的基础
- **公共底座重设计**：整体布局、Design Token、风格体系、路由架构需重新统一设计，不直接照搬任一系统，确保全新的设计质量
- **动态业务模块**：各业务系统的特色功能（OpenLLM 对话监控、OpenRAG 知识库管理等）是统一前端中的动态模块，前端代码统一维护，按服务发现动态显隐
- **抽取优先级**：登录/鉴权页 → 用户/角色/权限 → 租户管理 → 公共组件 → 请求层 → 布局壳 → Design Token → 各业务域特色页面
- **需求设计索引**：统一前端详细需求（FR-UF-001~018 + 非功能/接口/数据/权限/UI-UX + 追溯矩阵）见《OpenBase-统一前端需求设计说明-v0.1.0.md》（doc/requirements/）

**交付物**：
- 统一前端代码库（openbase-ui）+ 构建产物（共用/独立双模式）
- 四系统业务域动态模块接入
- 服务发现动态显隐验证报告
- CRUD 页面生成器前端模板

**独立性说明**：本版本以"一套壳整合四系统"为闭环——统一前端上线后四系统管理功能收敛为单一入口，服务发现动态显隐，可独立发布 v1.2.0。
