## 2. 功能需求

### 2.1 R-367 服务级 API Key 认证（P1）

| 项 | 内容 |
|----|------|
| 用户故事 | As a 外部系统/Agent, I want 使用服务级 API Key 访问网关（/proxy 通道）, so that 机器对机器调用无需用户 JWT |
| 功能描述 | API Key 签发（名称/scope/租户绑定）→ Bearer Key 认证中间件（网关 /proxy 通道）→ 吊销/轮换 |
| 验收标准 | AC-367-1 Key 签发/列表/吊销 API 可用；AC-367-2 /proxy 通道支持 Bearer Key 认证（JWT 优先 + Key 回退双通道）；AC-367-3 无效/吊销 Key 返回 401；AC-367-4 Key 绑定 scope 校验生效 |

### 2.2 R-368 网关服务 Key 认证决策矩阵（P1，随 R-367）

| 项 | 内容 |
|----|------|
| 用户故事 | As a 网关, I want 按 Key scope 校验租户与配额, so that 服务 Key 访问受控 |
| 功能描述 | Key 有效 → scope 租户校验 → 配额检查（402） |
| 验收标准 | AC-368-1 越 scope 租户访问 403；AC-368-2 配额超额 402 |

### 2.3 R-369 四维身份头基础承载（P1）

| 项 | 内容 |
|----|------|
| 用户故事 | As a 网关, I want 解析并透传 X-User-Id/X-Team-Id/X-Agent-Id, so that 四维身份上下文可贯穿 |
| 功能描述 | 依赖注入解析 4 头（X-Tenant-Id 已有）→ 网关透传（下游不改写） |
| 验收标准 | AC-369-1 4 头解析依赖可用；AC-369-2 透传链保持原值 |

### 2.4 R-370 审计绑定租户/用户（P1）

| 项 | 内容 |
|----|------|
| 用户故事 | As a 管理员, I want 审计记录绑定 tenant_id/user_id, so that 跨租户操作可追溯 |
| 功能描述 | 审计上下文注入（从请求头/当前用户提取写入审计记录） |
| 验收标准 | AC-370-1 审计记录含 tenant_id/user_id 字段 |

### 2.5 R-371 openbase-cli 脚手架（P1）

| 项 | 内容 |
|----|------|
| 用户故事 | As a 开发者, I want 用 CLI 创建项目/模块/CRUD, so that 新模块开发效率提升 |
| 功能描述 | create-project/create-module/create-crud 三子命令 + 模板生成 |
| 验收标准 | AC-371-1 三子命令可用；AC-371-2 生成模块可导入并挂载路由 |

### 2.6 R-372 BaseCRUDRouter（P1）

| 项 | 内容 |
|----|------|
| 用户故事 | As a 开发者, I want 一行声明生成 CRUD 路由, so that 通用管理接口快速产出 |
| 功能描述 | 通用 CRUD 路由自动生成（模型/模式驱动，fastapi-crudrouter 模式） |
| 验收标准 | AC-372-1 CRUD 端点自动生成；AC-372-2 鉴权/错误码统一 |

### 2.7 R-373 storage 扩展 MinIO/S3 适配（P2）

| 项 | 内容 |
|----|------|
| 用户故事 | As a 运维, I want 存储后端支持 S3 兼容对象存储, so that 文件可扩展存储 |
| 功能描述 | S3 兼容适配器（可选依赖 boto3），本地回退 |
| 验收标准 | AC-373-1 S3 后端可选启用；AC-373-2 本地后端回退正常 |

## 3. 非功能需求

| 项 | 要求 |
|----|------|
| 兼容性 | 服务 Key 认证不破坏既有 JWT 通道（双通道） |
| 安全 | Key 加密存储（哈希）、敏感信息不落日志 |
| 测试 | 新增代码覆盖率 ≥80%，遵循 AGENTS.md |
