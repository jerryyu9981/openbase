## 3. 需求来源 → 需求项映射

| 需求项 | 来源通道 | 来源细节 |
|--------|----------|----------|
| RT-146-01 统一日志查询接口 | 用户反馈 + 业务输入 | 用户诉求（三源统一入口）；现状核实确认无查询接口（R-382） |
| RT-146-02 四维分类浏览 | 用户反馈 | 用户明确选择"模块 / 操作类型 / 结果 / 操作人+时间"四维 |
| RT-146-03 关键字与多条件组合 | 用户反馈 | 用户明确选择该项 |
| RT-146-04 时间窗与分页 | 用户反馈 | 用户明确选择该项 |
| RT-146-05 测试三元组检索 | 用户反馈 | 用户明确选择该项（与三测试头口径一致） |
| RT-146-06 导出 CSV/JSON | 用户反馈 | 用户明确选择该项；决议 2 追加导出留痕 |
| RT-146-07 权限与脱敏 | 用户反馈 + 合规 | 用户选择"仅管理员 + 新增 `log:read`"；决议 1 定为管理员跨租户可见；导出含个人信息需脱敏可审计 |
| RT-146-08 前端日志中心页 | 用户反馈 | 用户诉求的交付形态（"前端可以直接查看"） |
| RT-146-09 存量 mock 页收口 | 线上问题（隐患） | `/system/audit` 为 mock，存在误导风险；决议 3 定为下线重定向 |
| **RT-146-10 顶层导航"三分"骨架** | 用户反馈 | 用户 2026-09-15 诉求 + 决议 5（顶层三分） |
| **RT-146-11 平台管理四域归并与归属矩阵** | 用户反馈 | 用户 2026-09-15 诉求 + 决议 6（四域全选） |
| **RT-146-12 模块瘦身：系统性能力上收** | 用户反馈 | 用户诉求"尽可能不要打破四模块特色功能，把全局性和系统性功能统一起来"+ 决议 7 |
| **RT-146-13 目录与模块边界治理** | 内部改进（代码实测发现） | 全局页组件寄居 `modules/openllm/pages/`，模块边界失真 |
| **RT-146-14 路由兼容与权限一致性** | 内部改进 + 用户反馈 | "兼顾整体布局功能"；旧路径兼容与权限一致为可用性底线 |
| **RT-146-15 模块开关管理页新建** | 用户反馈 + 内部改进 | **决议 10 纳入**：平台管理「平台配置与密钥」域若无模块开关管理页则名不副实（现仅有只读消费侧） |
| **RT-146-16 D-6 四仓 `request_id` 接线** | 用户反馈 + 线上问题（排障诉求） | 用户 2026-09-15"日志系统是所有子系统都有还是部分有？都是持久化的吗？"→ 实测确认四仓 `request_id` **全部未打通**（DPS 死接线 / OpenLLM 只进审计库 / OpenMemory `extra` 被丢 / OpenRAG 中间件未注册） |
| **RT-146-17 四仓日志结构化（JSONL）** | 内部改进（代码实测） | 四仓运行日志为**纯文本**（`basicConfig` / `StreamHandler`），仅 OpenBase 与 oidc-idp 有 `.jsonl` |
| **RT-146-18 采集按日切分与命名对齐** | 内部改进（文件系统实测） | 编排器已捕获但按**启动时间戳**命名（如 `openllm-20260914.log`），与 L1 的 `-YYYYMMDD.jsonl` 口径不一致 |
| **RT-146-19 四仓日志适配器与字段映射** | 用户反馈（可检索诉求） | 用户诉求"分类查看和检索"（2026-09-14）的延伸；四仓日志当前**不可被日志中心检索** |
| **RT-146-20 端到端串联与接入验收** | 内部改进 + 用户反馈 | 保证"一个 `request_id` 从网关追进任一子系统"的目标可验证（G7） |

**版本范围登记**：RT-146-01~09 归入 **R-382** → **VC-012**；**RT-146-10~15 归入 R-383 → VC-013**；**RT-146-16~20 归入 R-384 → VC-014（日志域工作归并至 v1.4.6）**。
