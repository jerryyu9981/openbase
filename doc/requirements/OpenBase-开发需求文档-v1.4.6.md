## 3. 现状核实结论（Step 1 关键输入，代码实测）

> 本节为写需求前对现状的**实测核对**，用于锁定范围与排除项，避免需求落在不存在的接口上。

| # | 核实项 | 实测结论 | 证据（代码位置） |
|:-:|--------|----------|------------------|
| 1 | 是否已有日志查询接口 | **没有**。全仓 `api_router` 上仅 `/audit/records` 一个端点（内存态），无任何读取 L1 文件或 `audit_logs` 表的 HTTP 接口 | `openbase/modules/audit/__init__.py`（`@api_router.get("/audit/records")`） |
| 2 | `/audit/records` 的数据源 | `AuditService` **内存环形缓冲**（`MAX_RECORDS = 5000`，注释"生产接数据库"）→ **进程重启即清空**、仅最近 5000 条 | `openbase/modules/audit/__init__.py`（`class AuditService`） |
| 3 | `audit_logs` 库表是否可检索 | 有函数级检索口 `query_audit_logs_by_case()`（C-4 跨重启持久化），但**未暴露为路由** | `openbase/modules/audit/__init__.py` |
| 4 | L1 日志文件 | `logs/openbase/openbase-<date>.jsonl`，逐请求一条（`api.request`，含 `resp_*`/`upstream_*`），**无任何接口可读** | S7 批 1（C-1）落地 |
| 5 | 测试记录 | `POST /test-runs`、`POST /test-records`、`PATCH /test-records/{id}`、`GET /test-runs/{run_id}/summary`，已有前端页 `/system/test-records` | `openbase/modules/testing/__init__.py`、`openbase-ui/src/pages/SystemTestRecords.vue` |
| 6 | 既有"审计日志"页 | `/system/audit`（`AuditLogsView.vue`）是**纯前端 mock**（`const mockLogs`），不调后端 | `openbase-ui/src/modules/openllm/pages/AuditLogsView.vue` |
| 7 | DPS 审计日志 | `GET /api/v1/dps-proxy/audit/logs` 为**转发 DPS 上游**日志，非 OpenBase 自身日志；前端无页面引用 | `openbase/modules/dps_proxy/__init__.py`、`openbase-ui/src/core/api/dps.ts` |
| 8 | 已接通前端的真实审计入口 | `/memory/api-gateway` 页"审计日志"页签调用真实 `GET /audit/records` | `openbase-ui/src/modules/memory/pages/ApiGateway.vue` |

**结论**：本功能**必须新增后端只读查询接口 + 前端页面**，不能只改前端；三源中 L1 与 `audit_logs` 需要**新建读取适配器**，测试记录可**复用既有端点**。

## 4. 功能需求

### 4.1 BL-146-01 统一日志查询接口（多源适配）（P0）

新增单一只读查询接口 `GET /api/v1/logs/search`，按 `source` 参数路由到三个适配器（`l1_file` / `audit_db` / `test_record`），对外返回**统一的 `LogEntry` 分页结构**。

| 项 | 要求 |
|----|------|
| 输入 | `source`（必填，枚举）、分类维度、关键字、时间窗、三元组、分页（见 §6.2） |
| 处理 | 按 `source` 选择适配器 → 归一为 `LogEntry` → 在适配器内完成过滤与排序（时间倒序）→ 统一分页 |
| 输出 | `{ items: LogEntry[], total, page, page_size, source, truncated }` |
| 异常 | `source` 非法 → `PARAM_400`；单源不可用（如库连接失败）→ `SYS_503` 且 `items=[]`，**不影响其他源**（源内降级） |
| 分层 | Controller 只做参数校验与调用 Service；读取逻辑（文件/DB/服务）在 Repository 层；禁止路由内拼 SQL |

### 4.2 BL-146-02 四维分类浏览（P0）

| 维度 | 取值（枚举） | 派生规则（三源统一） |
|------|--------------|----------------------|
| `module` 业务模块/页面族 | `identity` 身份鉴权 / `dps` 画像 / `rag` 知识库 / `memory` 记忆 / `llm` 模型 / `gateway` 网关与系统 / `testing` 测试记录 / `other` | 由 `path` 前缀映射（`/auth`、`/identity`、`/users`、`/tenants`→identity；`/dps-proxy`→dps；`/rag-proxy`→rag；`/memory-proxy`→memory；`/llm-proxy`→llm；`/gateway`、`/system`、`/modules`→gateway；`/test-runs`、`/test-records`→testing） |
| `operation` 操作类型 | `auth_login` 登录鉴权 / `read` 查询 / `write` 写入提交 / `delete` 删除 / `config` 配置变更 / `proxy` 代理转发 | 登录鉴权=`/auth/login`、`/oidc/**`；删除=`DELETE`；配置变更=路径含 `config`/`settings`/`switch`；代理转发=路径含 `-proxy`；其余按 `GET`→read、`POST/PUT/PATCH`→write |
| `result` 结果状态 | `success` 2xx / `client_error` 4xx / `server_error` 5xx / `unknown` | 由状态码区间映射；`audit_logs` 的 `action=proxy.outbound` 无状态码时取 `detail.status`，缺失则 `unknown` |
| `operator` 操作人 | 具体操作人 ID（可多选/空=全部） | `operator_id`（L1 为 `actor`，`audit_logs` 为 `user_id`，测试记录为记录人） |

要求：四维**可单独或叠加**过滤；分类导航需返回各取值的**计数**（用于"我平时用哪块"的快速收窄）。

### 4.3 BL-146-03 关键字与多条件组合检索（P0）

关键字 `q` 对 `path` / `request_id` / `operator` / `ip` 做**包含匹配**（不区分大小写）；`q` 与四维分类、时间窗、三元组**可任意叠加**（AND 语义）。

### 4.4 BL-146-04 时间窗与分页（P0）

| 项 | 要求 |
|----|------|
| 时间窗 | `from` / `to`（ISO8601）；**默认近 24 小时**；上限见 §7 扫描约束 |
| 分页 | `page`（默认 1）、`page_size`（默认 20，**上限 100**） |
| 排序 | 时间**倒序**（最新在前）；同秒按 `request_id` 稳定排序（保证分页不重不漏） |
| 截断提示 | 触及扫描上限时返回 `truncated=true` 并提示收窄时间窗（**不得**静默返回不完整结果） |

### 4.5 BL-146-05 测试三元组检索（P1）

支持 `case_id` / `run_id` / `step_id` 检索，与三测试头口径一致（`X-Test-Case-Id` / `X-Test-Run-Id` / `X-Test-Step-Id`）；三源均可按此定位（L1 取同名顶层字段，`audit_logs` 取 `detail` 同名键，测试记录取记录字段）。

### 4.6 BL-146-06 导出 CSV / JSON（P1）

`GET /api/v1/logs/export?format=csv|json`，复用与 `/logs/search` **完全相同的筛选参数**；条数上限 **10000**，超限返回 `PARAM_400` 并提示收窄条件；导出内容同样脱敏；**导出行为写一条审计留痕** `audit_logs(action=log.export)`（记录操作人 / 筛选条件摘要 / 导出条数）。

### 4.7 BL-146-07 权限与脱敏（P0）

| 项 | 要求 |
|----|------|
| 权限码 | 新增 **`log:read`**，仅管理员角色持有 |
| 可见范围 | 持有 `log:read` 者**可见全部租户**日志（**决议 1**：管理员跨租户；不按 tenant 强制过滤） |
| 未授权 | 无令牌 → 401（`AUTH_*`）；有令牌但无 `log:read` → 403（`PERM_*`） |
| 脱敏 | 复用既有统一脱敏口径（C-18 `mask_sensitive`）：`token`/`key`/`password`/证件号/手机号等**不得返回明文**；`detail` 中的敏感键遮蔽 |
| 路径安全 | L1 读取仅允许 `logs/openbase/` 目录下匹配 `openbase-YYYYMMDD.jsonl` 白名单文件名，**禁止路径穿越** |
| 检索词 | 查询关键字**不写入日志**（避免把敏感检索词落盘） |

### 4.8 BL-146-08 前端日志中心页（P0）

新增页面 `/system/logs`（侧栏：系统管理 → 日志中心，权限 `log:read`）：

| 区域 | 要求 |
|------|------|
| 顶部检索栏 | 数据源切换（L1 / 审计库 / 测试记录）+ 关键字 + 时间窗 + 导出按钮 |
| 左侧分类导航 | 模块 / 操作类型 / 结果 三组可点选（含计数）+ 操作人下拉；选中即过滤 |
| 主体表格 | 时间 / 数据源 / 模块 / 操作类型 / 结果 / 方法 / 路径 / 状态码 / 耗时(ms) / 操作人 / 请求 ID（列可配置） |
| 详情抽屉 | 完整 `LogEntry` + 测试三元组 + 摘要（脱敏后） |
| 分页 | 服务端分页，展示 `total`；`truncated=true` 时显著提示 |
| 状态 | 加载中 / 空结果（区分"无数据"与"条件未命中"）/ 错误（含 `request_id`）三态齐备 |

### 4.9 BL-146-09 存量 mock 页收口（P2）

`/system/audit`（`AuditLogsView.vue`）当前为 mock，存在**误导风险**。按**决议 3**：**下线该入口并重定向到 `/system/logs`**，并清理前端 mock 数据源（`mockLogs` 静态扫描 0 命中）；**不得**保留 mock 作为"可选页面"。

### 4.10 BL-146-10 顶层导航"三分"骨架（P0，VC-013 追加）

| 顶层区 | 内容 | 说明 |
|--------|------|------|
| **仪表盘** | `/dashboard` | 保留，个人化总览入口 |
| **业务模块** | 画像（portrait / DPS）· 知识库（knowledge / RAG）· 记忆（memory）· 模型（openllm / LLM） | 四模块**平行**呈现；**`gateway` 迁出**至平台管理（基础设施能力，非业务模块） |
| **平台管理** | 四域二级分组（见 §4.11） | 全局/系统性功能统一区；**不受任何单一模块启停影响** |
| **个人与帮助** | 个人设置 / 帮助与文档入口 | 个人设置由 `/openllm/settings` **归位**至本区 |

要求：① 顶层区语义固定（不随模块启停增减）；② 支持分组、折叠与当前项高亮（模块子页回退到模块根）；③ 模块未启用/无权限时该模块入口不显示，**但平台管理区始终按权限独立判定**。

### 4.12 BL-146-12 模块瘦身：系统性能力上收（P0，VC-013 追加）

**判定原则（契约化，写入评审依据）**

| 判定 | 口径 | 示例 |
|------|------|------|
| **留模块** | 该能力**仅**服务本模块业务语义 | DPS 业务权限（`DpsPermissionView`）、DPS 业务限流（`DpsRateLimitView`）、DPS 接口管理（`DpsApiManageView`）、LLM 工具调用监控、记忆衰减（`MemoryDecay`） |
| **上收** | 该能力**跨模块通用**（治理/观测/配置/身份/密钥/用量） | 个人设置、API 密钥、用量统计、监控仪表盘、链路追踪、成本与预算、告警中心、通用用户/组织/角色管理、插件与扩展 |

**硬门禁**：四模块**特色页零删减**（仅变更归属与入口，不删除任何业务功能）；迁移后模块内以**链接/快捷入口**指向平台管理域对应页。

### 4.13 BL-146-13 目录与模块边界治理（P1，VC-013 追加）

**问题（代码实测）**：`/system/roles`、`/system/org`、`/system/workspaces`、`/system/config`、`/system/audit`、`/system/edgerouter`、`/system/docs`、`/system/billing` 的组件文件**全部位于 `modules/openllm/pages/`**，由静态路由 `import` 直接引用。

**要求**：平台/全局类页面组件**迁出模块目录**（目标如 `src/pages/platform/**`），使**模块目录只含本模块特色**；迁移后 openllm 的构建 chunk 不得再包含全局页（模块可插拔性与打包边界恢复）。迁移涉及**破坏性变更**时，须先做全局引用检索并存证（见 §7 风险 7）。

### 4.14 BL-146-14 路由兼容与权限一致性（P0，VC-013 追加）

要求：① 产出**全量旧路径 → 新路径重定向映射表**，旧路径**禁止 404**（兼容书签、走查脚本、既有 E2E 与文档引用）；② 平台管理统一前缀（`/platform/**` 或保留 `/system/**`）在 Step 2 设计定案，但**无论选哪个都必须保留旧路径可达**；③ **权限码 ↔ 菜单可见性 ↔ 路由守卫三处一致**；④ E2E 断言：菜单可见性（有/无权限两种角色）、深链直访、旧路径重定向、`console.warn=0`。

### 4.15 BL-146-15 模块开关管理页新建（P0，VC-013 追加；决议 10 纳入）

| 项 | 要求 |
|----|------|
| 背景 | 平台管理「**平台配置与密钥**」域若无模块开关管理页则**名不副实**；当前仅有后端 `GET /api/v1/modules` **消费侧**（`moduleRegistry` 按权限过滤并驱动前端模块路由装载），**无任何管理界面** |
| 目标页 | `/platform/config/modules`（平台配置与密钥域下） |
| 功能 | ① 模块列表（`id`/名称/图标/`route_prefix`/`permission`/`status`）；② **启停开关**（`enabled`/`disabled`）；③ 变更需**权限校验**（建议权限码 `module:manage`，仅管理员）；④ 变更**留痕**（写 `audit_logs`，`action=module.switch`，记录操作人/模块/前后状态）；⑤ 变更后前端模块注册表行为可预期（**不要求热生效**，可标注"下次登录/刷新生效"，如需热生效在 Step 2 评估） |
| 后端配套 | 需新增模块状态**写接口**（如 `PATCH /api/v1/modules/{id}`）；若沿用既有只读 `GET /api/v1/modules` 所在模块，须评估其权限与分层合规性（Step 2 定案） |
| 依赖 | `modules` 注册表的持久化形态（DB 表 vs 配置）需在 Step 2 核实；**若为纯配置驱动**，则本页需先补最小持久化能力（影响工作量，**Step 2 评估后确认是否降级为只读展示**） |

## 5. 业务流程与逻辑

### 5.1 主流程（分类浏览 → 检索 → 查看 → 导出）

```
进入 /system/logs
  → 默认：数据源=L1、时间窗=近 24h、无分类过滤、page=1
  → 加载分类计数（模块/操作类型/结果）与首页数据
  → 用户点选分类（如 模块=memory、结果=失败）
  → 组合关键字/时间窗/三元组
  → 服务端过滤 + 倒序 + 分页 → 表格渲染
  → 点击行 → 详情抽屉（完整 LogEntry，脱敏）
  → 导出（同筛选条件，CSV/JSON，≤10000 条，写 log.export 审计留痕）
```

### 5.2 分支与失败流程

| 场景 | 期望行为 |
|------|----------|
| 数据源切换 | 保留关键字与时间窗，**清空**分类选择（各源枚举不完全一致），显式提示 |
| 时间窗过大 | 返回 `truncated=true` + 提示收窄；**不**静默截断 |
| 单源不可用 | 该源返回空 + 错误提示（含 `request_id`），其他源不受影响 |
| 无权限 | 401/403 统一错误体 `{code, message, detail, request_id}`，前端给出明确文案而非空白页 |
| 导出超限 | 400 + 提示当前命中条数与上限，引导收窄 |
| jsonl 文件不存在（当日无日志） | 返回空列表 + `total=0`，非错误 |

### 5.3 业务规则

1. 三源**只读**：本功能不写入任何日志文件与测试数据；**唯一例外**是导出行为写一条 `audit_logs(action=log.export)` 审计留痕（决议 2）；
2. 统一口径优先：同一语义字段（如 `result`）在三源返回**同一取值枚举**；
3. 时间倒序 + 稳定排序为**强制**，避免分页漂移；
4. 分类计数与实际列表**同源同条件**（避免"计数说有 3 条、列表只有 1 条"）；
5. 脱敏在**服务端**完成，前端不承担脱敏职责。

### 11.1 跨仓集成需求（R-384 / VC-014 追加）

**集成关系**：OpenBase 侧**不调用四仓接口**，而是通过**两条既有通道**接入：

| 通道 | 方向 | 内容 |
|------|------|------|
| 出站协议头 | OpenBase → 四仓 | 代理出站经 `openbase/modules/protocol_headers/inject.py` 装配 `X-Request-Id`（优先级：显式传入 > `request.state.request_id` > 新生成）—— **已就绪**，四仓无需等本仓改动即可接收 |
| 日志采集 | 四仓 → OpenBase | 编排器（C-6）重定向捕获四仓 stdout/stderr 至 `logs/{svc}/` —— **已就绪**，本版本仅需改造为**按日切分 + `.jsonl` 命名**（BL-146-18） |

**跨仓契约（四仓须遵守，强制）**

| 项 | 约定 |
|----|------|
| 头名与语义 | `X-Request-Id`；**受信来源透传复用**；**非受信携带则忽略并本地重生成** `req-{12hex}`（防伪造串联） |
| 日志字段名 | 统一 `request_id`（**禁止** `correlation_id` 等别名占该语义位） |
| 兜底 | 无上下文输出 `-`，**禁止 `KeyError`** |
| 输出流 | 维持现状（DPS/OpenLLM/OpenMemory → stderr；OpenRAG → stdout），**不得改为仅落自有文件** |
| 结构化 | 四仓统一输出 **JSON Lines**，字段最小集见 §4.17 |
| 禁止 | 不记录令牌/密码/密钥/完整请求体；沿用各仓既有脱敏逻辑 |
| 版本与流程 | 四仓**各自评审、各自提交、各自发布**；本仓**不代改**他仓代码 |
| 受信判定 | 沿用各仓既有代理来源校验实现（OpenBase 侧以 `X-Proxy-Source` 等既有口径为准） |

**集成边界与失败处理**

| 场景 | 处理 |
|------|------|
| 某仓未完成 `request_id` 接线 | 该仓日志 `request_id` 映射为 `null`（**不得伪造**）；交付说明显式标注覆盖范围（§4.20） |
| 某仓未完成结构化 | `RepoLogAdapter` 走**纯文本回退**分支解析（能力受限，须显式标注） |
| 某仓日志文件缺失 | 该 `module` 维度返回空集 + `truncated=false`（当日无日志属正常） |
| 跨仓排期延期 | **不阻塞** R-382 / R-383 部分；按 VC-014 缓解措施分批交付并在版本交付说明中登记未覆盖范围 |
