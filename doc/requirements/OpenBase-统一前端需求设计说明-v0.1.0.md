## 1. 需求背景与目标

### 1.1 背景

OpenLLM / OpenRAG / OpenMemory / DPS 四个自研系统原本各自拥有独立前端。版本规划确定：四系统共用**一套统一前端**，不存在五套独立前端。统一前端整体基于 vue-vben-admin 构建，OpenBase 公共模块是必启基础模块，各业务系统的特色功能（OpenLLM 对话监控、OpenRAG 知识库管理、OpenMemory 记忆管理、DPS 画像管理等）是统一前端中的**动态业务模块**，按服务发现动态显隐。

### 1.2 目标

| # | 目标 | 说明 | 对应版本 |
|---|------|------|---------|
| G1 | 统一入口 | 一个前端应用整合四系统管理功能，一套壳、一套登录、一次开发四系统共用 | v1.1.0 |
| G2 | 响应式多端 | 桌面/平板/手机自适应布局，移动端统一抽屉菜单 | v1.1.0 |
| G3 | 动态显示 | 后端服务未启动 → 对应业务域模块菜单与路由自动隐藏；恢复后自动出现 | v1.1.0 |
| G4 | 后端零改动 | 四系统仅暴露 API + /health，不承担前端渲染，现有服务不变 | v1.1.0 |
| G5 | 公共能力复用 | OpenBase 公共模块（登录/鉴权、用户/角色/权限、租户、字典、任务、文件、通知）一次开发，四系统共用 | v1.0.0 起步，v1.1.0 完整 |
| G6 | 择优抽取 | 从四系统现有前端逐模块挑选最完整、最成熟的实现，公共底座重新设计 | v1.1.0 |

### 1.3 核心概念定义

| 术语 | 定义 |
|------|------|
| 统一前端（Admin Shell） | 四系统共用的单一前端应用，基于 vue-vben-admin 构建，含动态菜单/动态路由/多端适配/服务发现 |
| 公共模块 | OpenBase 提供的必启基础页面（登录/鉴权、用户/角色/权限、租户、数据字典、定时任务、文件、通知），菜单常显 |
| 动态业务模块 | 各业务系统特色功能在统一前端中的对应模块（OpenLLM 域、OpenRAG 域、OpenMemory 域、DPS 域），按服务发现驱动显隐 |
| 服务发现 | 前端通过统一网关 `GET /api/v1/services` 获取各后端服务健康状态，驱动菜单与路由动态渲染 |
| 共用模式 | 四系统整体部署：统一前端 = 公共模块 + 全部业务域动态模块 |
| 独立模式 | 单系统单独部署：统一前端 = 公共模块 + 对应业务域动态模块 |
| Design Token | 全站统一的视觉设计变量（颜色/字体/间距/圆角等），接入 vue-vben-admin 主题系统 |

| 角色 | 描述 | 主要诉求 |

## 3. 总体架构

### 3.1 拓扑结构

```
┌──────────────────────────────────────────────────────┐
│          统一前端 Admin Shell（Vue3 + vue-vben-admin）  │
│    动态菜单 · 动态路由 · 多端适配 · 服务发现 · Design Token │
└──────────────────────────┬───────────────────────────┘
                           │ HTTP/JSON API（REST）
┌──────────────────────────▼───────────────────────────┐
│        统一网关 · 服务健康聚合（FastAPI）              │
│        GET /api/v1/services → 各系统 /health 聚合      │
└───────┬──────────────┬──────────────┬────────────────┘
        ▼              ▼              ▼
     OpenLLM         OpenRAG      OpenMemory / DPS
  （四系统仅提供 API + /health，后端零改动）
```

### 3.2 模块组成

| 分类 | 组成 | 后端 API 提供方 | 显隐方式 |
|------|------|----------------|---------|
| 前端底座 | 布局壳、Design Token、请求层、公共组件库、路由架构 | - | 常显（基础） |
| 公共模块（OpenBase） | 登录/鉴权、用户/角色/权限、租户、数据字典、定时任务、文件、通知、工作台首页 | OpenBase 服务（必启） | 常显 |
| 动态模块 - OpenLLM 域 | 对话监控、模型管理、路由配置 | OpenLLM 服务 | 服务发现驱动 |
| 动态模块 - OpenRAG 域 | 文档管理、知识库配置、检索测试 | OpenRAG 服务 | 服务发现驱动 |
| 动态模块 - OpenMemory 域 | 记忆管理、会话管理 | OpenMemory 服务 | 服务发现驱动 |
| 动态模块 - DPS 域 | 画像管理、标签维护 | DPS 服务 | 服务发现驱动 |

## 4. 功能需求

> 需求编号规则：FR-UF-xxx（UF = Unified Frontend 统一前端）。每个需求含用户故事（As a…, I want to…, so that…）与可验证验收标准。优先级映射：P0 = 版本必须（Must）、P1 = 应该（Should）。

### 4.1 前端底座

#### FR-UF-001 布局壳（Layout Shell）

**用户故事**：As a 平台管理员，I want 统一前端具备统一的侧边栏/顶栏/内容区布局和响应式断点，so that 四系统所有页面在桌面/平板/手机上呈现一致且自适应的体验。

**功能描述**：
- 布局壳包含：侧边栏（可折叠）、顶栏（面包屑/用户菜单/通知入口）、内容区（路由出口）、多端响应式断点（桌面/平板/手机）
- 移动端（<768px）使用抽屉式菜单，顶栏收起为汉堡按钮
- 菜单分组：`系统管理`分组（OpenBase 公共模块，常显）+ 各业务域分组（动态，服务发现驱动）
- 布局壳从四系统现有前端择优抽取 + 重设计，不直接照搬任一系统

**验收标准**：
1. 布局壳在 1920/1440/1024/768/375px 五种宽度下布局不破版，断点行为符合 vue-vben-admin 规范
2. 侧边栏可折叠且状态持久化（刷新后保持）
3. 移动端菜单以抽屉形式呈现，可正常展开/收起
4. `系统管理`分组常显，各业务域分组按服务状态动态出现/隐藏

**优先级**：P0（v1.1.0） | **关联候选需求**：F-005

#### FR-UF-002 Design Token 全站统一主题

**用户故事**：As a 业务系统管理员，I want 统一前端全站视觉风格一致（颜色/字体/间距/圆角），so that 四系统页面切换无割裂感。

**功能描述**：
- 从四系统现有主题抽取视觉规范为 Design Token（颜色/字体/间距/圆角/阴影）
- Design Token 接入 vue-vben-admin 主题系统（Ant Design Vue 自定义变量）
- 支持明暗主题切换（默认跟随系统，可手动切换）
- 所有模块（公共 + 动态业务域）统一引用 Design Token，不各自定义散落样式

**验收标准**：
1. Design Token 变量表完整覆盖颜色/字体/间距/圆角/阴影五类
2. 主题切换后全站（含动态模块页面）实时生效
3. 任一业务域页面不出现与全站主题不一致的硬编码颜色

**优先级**：P1（v1.1.0） | **关联候选需求**：F-008

#### FR-UF-003 请求层（axios 封装）

**用户故事**：As a 开发人员，I want 统一请求层封装 axios/拦截器/错误处理，so that 所有页面统一携带 Token、统一错误提示、避免重复代码。

**功能描述**：
- axios 实例统一配置 baseURL、超时（默认 15s）、请求拦截器（自动附加 JWT、租户上下文头）
- 响应拦截器：统一错误码处理（401 跳登录、403 提示无权限、5xx 提示服务异常）、Token 过期自动刷新
- 从四系统现有请求层择优抽取（OpenLLM 优先）
- 管理接口调用经统一网关代理，前端不直连 AI 服务接口

**验收标准**：
1. 未登录访问受保护接口 → 自动跳转登录页
2. Token 过期 → 自动刷新后重放原请求，刷新失败才跳登录
3. 接口错误按统一错误码格式提示，页面不出现未捕获异常
4. 请求层可被所有业务域模块直接引用，无需重复封装

**优先级**：P1（v1.1.0） | **关联候选需求**：F-007

#### FR-UF-004 公共组件库

**用户故事**：As a 开发人员，I want 统一的表格/表单/弹窗/图表组件库，so that 业务域页面开发高效且风格一致。

**功能描述**：
- 从四系统挑选成熟度最高的表格/表单/弹窗/图表组件，统一封装为公共组件库（基于 Ant Design Vue 扩展）
- 公共组件由 openbase-ui 提供，各业务域页面直接引用
- 组件支持与 openbase-cli 生成的 CRUD 页面对接

**验收标准**：
1. 公共组件库包含：表格（分页/排序/搜索/行操作）、表单（校验/布局）、弹窗（确认/表单弹窗）、图表（折线/柱状/饼图）四类基础组件
2. 每个组件有统一 props/events 约定和文档示例
3. 业务域页面引用公共组件无需二次封装

**优先级**：P0（v1.1.0） | **关联候选需求**：F-006

#### FR-UF-005 路由架构（动态路由基座）

**用户故事**：As a 开发人员，I want 统一前端具备动态路由能力（router.addRoute），so that 业务域模块可运行时注册/移除路由。

**功能描述**：
- 路由架构支持：静态路由（公共模块）+ 动态路由（业务域模块，运行时注册/移除）
- 动态路由按业务域命名空间隔离（如 `/openllm/*`、`/openrag/*`），避免冲突
- 路由级懒加载：未启用的业务域代码不加载
- 访问已离线模块路由 → 拦截并提示"服务未启动"，不报错崩溃

**验收标准**：
1. 动态路由可运行时注册与移除，移除后原路由不可访问
2. 访问离线模块 URL 时展示"服务未启动"友好提示页，控制台无未捕获异常
3. 懒加载生效：未启用模块的 chunk 不加载（Network 面板验证）

**优先级**：P0（v1.1.0） | **关联候选需求**：F-010

### 4.2 公共模块（OpenBase 必启）

#### FR-UF-006 统一登录与鉴权

**用户故事**：As a 普通用户，I want 用一套账号登录统一前端，so that 登录后可访问四系统所有已授权功能，无需重复登录。

**功能描述**：
- 登录页：账号密码登录、Token 刷新、找回密码
- 登录后签发 JWT，后续所有请求自动携带
- 用户/角色/权限体系与 OpenBase auth 模块 API 对齐（RBAC）
- 前端菜单按用户权限过滤（RBAC 菜单），无权限菜单不显示
- 登录页从四系统现有实现择优抽取（OpenLLM 优先）

**验收标准**：
1. 正确账号密码可登录并跳转工作台首页
2. 错误密码/锁定账号有明确错误提示
3. 不同角色登录后菜单按权限过滤，无权限入口不显示
4. Token 有效期默认 2h，刷新有效期 7d（与 OpenBase auth 模块配置一致）
5. 未登录访问任意页面 → 重定向登录页

**优先级**：P0（v1.0.0） | **关联候选需求**：F-001

#### FR-UF-007 用户/角色/权限管理

**用户故事**：As a 平台管理员，I want 在统一前端管理用户/角色/权限，so that 四系统共用同一套账号与权限体系。

**功能描述**：
- 用户管理：创建/编辑/禁用/删除用户、重置密码、分配角色
- 角色管理：创建/编辑角色、分配权限点
- 权限管理：权限点（菜单/按钮/接口）维护、角色-权限矩阵
- 与 OpenBase auth 模块 API 对齐；前端从四系统择优抽取（OpenLLM + OpenMemory 合并）

**验收标准**：
1. 用户 CRUD 全流程可用，禁用用户立即不可登录
2. 角色-权限矩阵保存后生效，重新登录按新权限渲染菜单
3. 页面级权限（菜单）+ 按钮级权限（操作）双层控制生效

**优先级**：P0（v1.0.0） | **关联候选需求**：F-002

#### FR-UF-008 租户管理

**用户故事**：As a 平台管理员，I want 在统一前端管理租户，so that 多租户的创建/隔离配置可视化。

**功能描述**：
- 租户 CRUD、启用/禁用
- 租户隔离配置（数据隔离级别、配额）
- 与 OpenBase tenant 模块 API 对齐；前端从四系统择优抽取（OpenMemory 优先）

**验收标准**：
1. 租户 CRUD 全流程可用
2. 租户启用/禁用状态即时生效
3. 租户上下文在请求中正确传递（切换租户后数据隔离正确）

**优先级**：P1（v1.0.0） | **关联候选需求**：F-003

#### FR-UF-009 数据字典/定时任务/文件/通知

**用户故事**：As a 平台管理员，I want 在统一前端维护数据字典、定时任务、文件、通知，so that 通用后台能力集中管理。

**功能描述**：
- 数据字典：枚举/选项配置，支持前端字典组件联动
- 定时任务：任务 CRUD、启停、执行日志查看
- 文件管理：上传/下载/预览（对接 storage 模块）
- 通知中心：SSE 推送、站内信、已读管理（对接 notify 模块）
- 与 OpenBase 对应模块 API 对齐；前端从四系统择优抽取

**验收标准**：
1. 数据字典配置保存后，依赖字典的前端组件联动刷新
2. 定时任务可创建/启停，执行日志可查询
3. 文件上传/下载/预览全流程可用
4. 通知实时推送（SSE），已读状态持久化

**优先级**：P1（v1.1.0） | **关联候选需求**：F-004

#### FR-UF-010 工作台首页（聚合概览）

**用户故事**：As a 普通用户，I want 登录后看到各在线业务模块的状态概览，so that 快速了解哪些系统可用并一键进入。

**功能描述**：
- 聚合工作台：展示各业务模块（OpenLLM/OpenRAG/OpenMemory/DPS）状态卡片
- 卡片显示：模块名称、状态（运行中/未启动）、版本号（如有）、快捷入口
- 未启动模块显示"未启动"，不可进入；运行中模块可点击进入对应首页
- 卡片数据来源于 `GET /api/v1/services`

**验收标准**：
1. 工作台正确展示所有已注册业务模块及其状态
2. 状态与后端服务真实健康状态一致（30s 内同步）
3. 点击运行中卡片进入对应模块首页；未启动卡片不可点击

**优先级**：P1（v1.1.0） | **关联候选需求**：F-010（动态模块框架配套）

### 4.3 动态模块框架

#### FR-UF-011 服务发现与动态显隐

**用户故事**：As a 运维人员，I want 后端服务未启动时对应业务域模块自动隐藏、恢复后自动出现，so that 前端不因服务状态变化报错，运维无需改前端配置。

**功能描述**：
- 服务注册：四系统各自暴露 `/health`（OpenLLM 已有，其余系统同样实现）
- 网关聚合：`GET /api/v1/services` 返回可用服务列表
- 前端消费：启动时拉取 + 每 30s 轮询（或 SSE/WebSocket 推送）
- 动态渲染：按服务状态注册/移除路由 + 渲染/隐藏菜单（router.addRoute）
- 懒加载：路由级懒加载，未启用系统代码不加载

**状态切换行为**：

| 场景 | 前端行为 |
|------|---------|
| 服务启动（health ✓） | 轮询发现 → 动态注册路由 → 菜单项出现（无需刷新） |
| 服务停止（health ✗） | 轮询发现 → 移除路由 → 菜单项隐藏（或置灰"服务不可用"） |
| 访问已离线模块 | 拦截并提示"服务未启动"，不报错崩溃 |
| 首次加载 | 仅渲染在线系统菜单，未启用系统完全不可见 |

**验收标准**：
1. `GET /api/v1/services` 返回的服务列表与四系统实际健康状态一致
2. 服务停止后 ≤30s 菜单隐藏；恢复后 ≤30s 菜单出现（轮询周期可配置）

## 6. 接口需求

### 6.1 服务发现接口（统一前端核心依赖）

**`GET /api/v1/services`**（统一网关提供，FastAPI）

**用途**：前端获取四系统服务健康状态与动态模块注册信息。

**请求**：无参数（携带用户 JWT）。

**响应**：

```json
{
  "services": [
    {
      "id": "openllm",
      "name": "OpenLLM 网关",
      "status": "up",
      "base_url": "/proxy/openllm",
      "version": "v1.2.3",
      "menu": ["对话监控", "模型管理", "路由配置", "回写日志"],
      "route": "/openllm/*"
    },
    {
      "id": "openrag",
      "name": "OpenRAG 知识库",
      "status": "down",
      "base_url": "/proxy/openrag",
      "version": "-",
      "menu": ["文档管理", "知识库配置", "检索测试"],
      "route": "/openrag/*"
    }
  ]
}
```

**字段说明**：

| 字段 | 类型 | 说明 |
|------|------|------|
| id | string | 服务标识，作为前端业务域模块命名空间（路由前缀/views 目录名） |
| name | string | 服务显示名称（菜单分组名） |
| status | string | up / down（依据后端 /health） |
| base_url | string | 网关代理前缀（/proxy/{id}） |
| version | string | 服务版本号，未启动为 "-" |
| menu | string[] | 该业务域菜单项清单 |
| route | string | 路由前缀（/{id}/*） |

**接口契约要点**：
- OpenBase 服务的 `id` 固定为 `openbase`，始终 `status: up`（必启服务），公共模块菜单不依赖该接口显隐
- 各业务域服务离线时，网关仍返回该服务条目但 `status: down`，前端据此隐藏菜单

### 6.2 后端 `/health` 接口

各业务系统（OpenLLM/OpenRAG/OpenMemory/DPS）必须暴露 `/health`，返回 `200` 表示在线。OpenLLM 已有，其余系统需补齐（后端零改动原则下为既有能力对齐）。

### 6.3 鉴权接口（对齐 OpenBase auth 模块）

| 接口 | 用途 |
|------|------|
| POST /api/v1/auth/login | 登录获取 Token |
| POST /api/v1/auth/refresh | 刷新 Token |
| POST /api/v1/auth/logout | 登出 |
| GET /api/v1/auth/me | 当前用户信息（含权限点/角色） |

### 6.4 管理接口代理约定

- 前端所有管理接口调用经统一网关代理（base_url 前缀），不直连业务后端
- 前端**不直连** AI 服务接口（/v1/chat 等机器调用接口），权限边界清晰
- 接口错误码统一格式（与 OpenBase 统一错误码规范一致）：`{code, message, request_id}`

## 10. 约束、边界与排除项

### 10.1 约束

| 约束 | 说明 |
|------|------|
| 技术栈 | Vue 3 + Ant Design Vue + vue-vben-admin 壳；TypeScript |
| 后端联动 | 四系统后端零改动（仅暴露 API + /health）；统一网关由 OpenBase 提供 |

| 代码归属 | 统一前端为一套代码库（openbase-ui），业务域模块代码统一维护，不分拆到各系统 |
| 复用原则 | 择优抽取 + 公共底座重设计；三不原则（不删除原实现、不急于替换、不回退特色） |

### 10.2 边界与排除项（本需求设计范围）

| 排除项 | 说明 |
|--------|------|
| 业务域模块内部功能细化 | OpenLLM 对话监控、OpenRAG 检索测试等业务域页面的内部功能需求由各系统需求文档定义，本设计只定义其在统一前端中的模块归属、显隐与来源 |
| AI 服务接口页面 | 前端不实现 AI 服务接口（机器调用）相关页面 |
| 低代码平台 | Amis 页面嵌入（如有）为可选能力，不在本版本强制范围 |
| 国际化（i18n） | 归入 v1.2.0 生态完善阶段，本设计不展开 |
| 前端自动化测试基座 | 归入 v1.2.0 框架级测试基座，本设计仅定义验收基线 |
