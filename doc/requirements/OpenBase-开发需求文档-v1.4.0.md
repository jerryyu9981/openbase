## 1. 版本概述

### 1.1 背景

v1.3.0 已发布（P0 26 项 + 高耦合 P1 4 项 + 基座调试完整，四系统对接挂起分批）。差距分析报告 §8.2/§8.3 的剩余 P1 建议保留项与 P2 可延后项尚未排期；统一网关（服务发现/路由转发/聚合）经确认归属 OpenBase，缺后端实例发现与聚合编排能力。本版本将 P1 建议保留项全量补齐、P2 项保留实现，并完成统一网关增强阶段一（零依赖落地）。生态工具链（i18n/测试基座/文档站点/示例项目，R-364）经 VC-007 决策挂起，不在本版本交付。

### 1.2 版本目标映射（G1~G4）

| 目标 | 描述 | 成功指标 | 关联需求 |
|------|------|---------|---------|
| G1 P1 全量补齐 | 差距分析 §8.2 剩余 P1 项全量实现（去占位/去缺失） | 剩余 P1 项 100% 可用；占位页清零 | RT-401~423 |
| G2 P2 保留 | 差距分析 §8.3 P2 项保留实现 | P2 项 4/4 可用 | RT-424 |
| G3 质量门禁 | 前端测试与质量达标 | 测试 100%、覆盖率 ≥80%、Lint 0、E2E 走查通过 | RT-401~426 |
| G4 统一网关增强 | 后端实例发现（阶段一）+ 聚合编排（阶段一） | 实例健康感知 ≤30s；`/api/v1/services` 与 `/api/v1/gateway/aggregate` 可用；静态表兜底向后兼容 | RT-425~426 |

### 1.3 业务目标与用户目标

| 类别 | 描述 |
|------|------|
| 业务目标 | 统一前端达到"已验证功能全保留"（P1 剩余 + P2 全量），消除剩余占位页；网关具备实例动态感知与跨系统聚合能力，为后续多实例/企业级部署打基础 |
| 用户目标 | 管理员/运营人员通过统一入口完成高级管理（模型市场/GPU/Prompt/角色权限/计费等）全部操作；平台运维可查看服务实例健康并一键聚合跨系统数据 |
| 成功指标 | 统一前端 P1/P2 功能操作覆盖率 100%（按差距分析清单）；网关实例变更 ≤30s 感知；聚合一次请求返回 2~3 系统数据 |

### 3.7 统一网关模块（RT-425~426，2 项，P1）

> 依据《OpenBase 网关服务发现与聚合编排技术方案》（ADR-网关-001/002）：阶段一零依赖落地（config 驱动 + scheduler 探测 + 代码式聚合），阶段二（Nacos/DSL/GraphQL）需求驱动再排期，不在本版本范围。

#### RT-425 后端实例服务发现（R-365 / BL-429）

| 项 | 内容 |
|----|------|
| 用户故事 | As a 平台运维, I want 查看四系统后端实例注册与健康状态，实例变更自动感知, so that 网关转发不依赖手工改配置 |
| 功能描述 | 新增 gateway 模块：DiscoveryProvider 适配器接口 + ConfigProbeProvider（阶段一默认）；健康探测接入 scheduler（interval job，默认 10s/轮，GET {host}:{port}/health）；加权轮询 + 连续 3 次失败剔除（冷却 60s）+ 恢复；服务管理 API（`GET/POST /api/v1/services`、`GET/DELETE /api/v1/services/{system}[/{instance_id}]`、`GET /api/v1/gateway/health|ping`）；proxy `_resolve_base_url` → DiscoveryRegistry.pick；静态表 PROXY_SYSTEMS 兜底；网关管理前端页（服务列表/健康状态） |
| 验收标准 | AC-425-1 实例注册/列表/下线 API 可用且带鉴权（gateway:register/view）；AC-425-2 实例上线/下线 ≤30s 内被健康探测感知（10s 轮询）；AC-425-3 连续 3 次探测失败实例被剔除，冷却 60s 后成功 1 次即恢复；AC-425-4 加权轮询按权重分配请求，剔除后自动避开故障实例；AC-425-5 `gateway.discovery.enabled=false` 时行为与 v1.3.0 一致（静态表兜底）；AC-425-6 `/api/v1/modules` 前端模块发现不受影响 |

#### RT-426 聚合编排（R-366 / BL-430）

| 项 | 内容 |
|----|------|
| 用户故事 | As a 应用开发者, I want 一次请求聚合多个系统的数据, so that 跨系统取数（如仪表盘）无需多次往返自行拼装 |
| 功能描述 | `POST /api/v1/gateway/aggregate` 代码式并发聚合（asyncio.gather 并发调 /proxy，支持 2~3 子请求）；整体超时（默认 5000ms）+ 单步超时 + 部分失败策略（return_errors 默认/strict/best_effort）；聚合结果按映射规则合并；DSL 注册表（config 键 `gateway.aggregates.*`）与 DSL 执行器为阶段二，本版本不实现；网关管理前端页提供聚合测试入口 |
| 验收标准 | AC-426-1 aggregate API 并发聚合 2~3 个子请求返回正确合并结果；AC-426-2 单子请求超时不影响其他（部分失败策略生效）；AC-426-3 整体超时返回 SYS_TIMEOUT（503）；AC-426-4 鉴权生效（gateway:aggregate）；AC-426-5 未注册 DSL 时调用聚合 API 返回明确错误且不影响现有功能 |
