## 4bis. 增量 I-6（用户裁定纳入，2026-09-28）

> **裁定**：CR-149 剩余项「**取数层逐组件路由 ＋ 通道裁决进取数层**」**纳入 v1.4.9**（用户在「归属待定清单」中选定）。
> **定性**：属「**主备通道畅通**」主线（非预算主线），与 I-1~I-5 **无依赖冲突**，可并行推进。

| 项 | 内容 |
|----|------|
| 增量 | **I-6 取数层逐组件通道路由** |
| 现状（CR-149） | §3.1 取数层：画像与组件并行、两路径时序统一**已实施**；**通道裁决尚未进入取数层**（§4.1「通道 A 无业务调用点」）；§6 第二批「待做：通道裁决进取数层；残留＝**取数层逐组件路由**」 |
| 本版新增 | ① **每组件取数前**经通道裁决器判定「本次该组件走主还是备」；② 连续失败**达阈值按组件维度**切换（而非整链路切换）；③ 路由决策**可观测**（轨迹/回执带**每组件通道**）；④ 与既有整体 `CHANNEL_PREFERENCE` **兼容且不冲突**（逐组件为**更细粒度**，整体仍为默认兜底） |
| 边界（避免与已完成项重复） | **不重复** §4.2「组件决策」三余项（阈值与单次命中语义对齐／规则集可配置／LLM 兜底接线）——那是**选哪些组件**；I-6 是**选定组件走哪条通道**。**不重复** W4 的 `describe_channel_report`（那是**状态上报与建议**）；I-6 是**取数层执行路由** |
| 依赖 | 既有通道裁决器（`ChannelStateManager`）＋ 组件执行层（`component_pipeline`）；**不依赖** D2/D3（评分与阈值回填） |
| 开关 | **新增能力默认关闭**；关闭时路由语义与现状**逐字一致**（fail-safe：裁决器不可用 ⇒ 退回整体 preference） |
| 优先级 | **P0**（直接决定「主备名副其实」） |
| Phase | **P5**（与 P1~P3 可并行；不阻塞预算主线） |
| 验收 | **AC-149-13**（见需求文档 §9ter） |
| 判据关系 | 与 **T4**（备通道接管轨迹）**互补**：T4 验「接管可复盘」，本判据验「**逐组件独立路由 + 每组件通道可观测**」 |
