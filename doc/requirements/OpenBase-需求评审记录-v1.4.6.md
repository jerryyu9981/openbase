## 3. 评审意见与决策

### 3.1 第一轮（日志中心）

| 意见 | 决策 |
|------|------|
| 三源中 `/audit/records`（内存态）是否纳入？ | **不纳入**（保持现状），登记为排除项 #1 |
| 分类维度如何定？ | **采纳四维**；module/operation 由 path+method **后端派生**（AC-146-02-1） |
| 检索能力范围？ | **采纳四项**：关键字+多条件、时间窗+分页、测试三元组、导出 CSV/JSON |
| 三源如何统一？ | **采纳方案 A**：单接口 + 三适配器 + 统一 `LogEntry` |
| 权限口径？ | **采纳**：`log:read`（仅管理员）+ **跨租户可见**（决议 1） |
| 导出是否留痕？ | **采纳留痕**（决议 2，AC-146-06-4） |
| `/system/audit` mock 页处置？ | **采纳下线重定向**（决议 3；目标随第二轮新 IA 调整） |
| L1 无索引导致大时间窗可能不完整？ | **不算缺陷**：扫描上限 + `truncated` 显式提示（AC-146-04-3）；索引化列为排除项 #7 |
| doc/version 是否存在（我此前误判） | **已纠正**：目录体系完整；需求文档 §1 已修正并留痕 |

### 3.2 第二轮（统一前端功能布局重构，VC-013）

| 意见 | 决策 |
|------|------|
| 目标顶层导航骨架 | **采纳三分**（决议 5）：仪表盘 / 业务模块 / 平台管理（+ 个人与帮助）；`gateway` 迁出业务模块区 |
| 统一哪些"全局性/系统性"域 | **采纳四域全选**（决议 6）：身份与权限 / 平台配置与密钥 / 可观测与审计 / 开发者资源 |
| 四模块内部如何处置 | **采纳"上收系统性能力、模块只留特色"**（决议 7）；判定口径契约化：业务专有→留模块，跨模块通用→上收；**特色页零删减** |
| 是否改视觉规范？ | **不改**：本轮只做 IA 与归属治理（排除项 #10） |
| 是否改四模块业务逻辑？ | **不改**：只做搬迁与入口归位（排除项 #11） |
| 版本归属 | **并入 v1.4.6 并回溯**（决议 8）；不新开版本、不并入 v1.5；周期 2 → 4.5 周 |
| **6 项争议页归属** | **全部按建议裁定（决议 9）**：`DpsMonitorView`·`knowledge/Settings`·`knowledge/Users`·`gateway 模块` → **上收**；`ToolCallMonitorView`·`Routing` → **留模块** |
| **模块开关管理页是否纳入** | **纳入本版本（决议 10，P0）**：否则「平台配置与密钥」域**名不副实**；新增 BL-146-15（含权限码 `module:manage`、`module.switch` 留痕、后端状态写接口） |
| 通用限流配额页是否纳入 | **不纳入**：现仅 DPS 侧 `DpsRateLimitView` 属业务侧保留；如需另立需求（排除项 #13 收敛） |
| 回溯范围与代价 | **接受并显式登记**：Step 1 需求基线 + 追溯矩阵 + **前端类设计文档**（UI/前端架构/系统架构/原型/设计评审）+ 覆盖率核对 + Stage1/Stage2 审计结论均需升版重出；后端类设计（API/非功能/部署）经评估基本不受影响 |
| 迁移期双入口 | **采用"新增即隐藏旧入口 + 保留路径重定向"**，迁移完成即下线旧入口（风险 10 应对） |

### 3.3 第三轮（四仓日志接入，VC-014）

| 意见 | 决策 |
|------|------|
| 日志域工作是否归并到一个版本 | **采纳 A：全部并入 v1.4.6**（决议 11）；备选 B"剥离为日志专项版本"、C"并入但分两批（跨版本）"未采纳；理由见 VC-014 |
| 四仓日志接入是否拆批 | **拆为两批（同版本内）**（决议 12）：批 A = BL-146-16（D-6 接线，价值自足）；批 B = BL-146-17~20；**建议 G1（JSONL）与 D-6 合并同批**以省一轮跨仓流程（≈8h） |
| 跨仓边界与流程 | **采纳**（决议 13）：**本仓不代改四仓代码**；四仓各自评审/提交/发布；**接受"收口绑定四仓排期"**（风险 12，高/高），以"两批推进 + 交付说明显式标注覆盖范围"缓解 |
| 四仓日志原为排除项，是否解禁 | **解禁**：§12 排除项 #6 状态变更为"移出排除项、纳入本版本"；新增 6b（四仓日志清理/轮转仍排除，沿用各仓既有策略） |
| 是否要求四仓一次性输出 JSONL | **要求**（BL-146-17 纳入同版本）；理由：仅接线不结构化则接入后只能关键字检索、无法按模块/结果过滤（风险 14），从根因消除 |
| `source` 枚举如何扩展 | **新增 `repo_log`**（四仓统一走该源，以 `module` 维度区分 dps/rag/memory/llm）；前端数据源下拉增加四仓选项（`module` 枚举已含四值，无需扩展） |
| 适配器是否支持纯文本 | **支持**（JSONL 优先 + 纯文本回退）；作为某仓未结构化时的过渡，但**必须在交付说明中显式标注覆盖范围**（禁止静默降级） |
| 采集命名是否必须按日切分 | **必须**（BL-146-18）：对齐 L1 的 `-YYYYMMDD.jsonl` 口径，以复用既有"分片倒序扫描 + 上限截断"逻辑；**且不删历史、重启不覆盖** |
| 四仓日志含敏感字段如何处置 | **服务端统一脱敏**（复用既有口径，**不得因新源放宽**）；四仓既有脱敏逻辑保留 |

## 4. 评审结论

**✅ 批准** —— v1.4.6 需求（日志中心 + 统一前端功能布局重构 + **四仓日志接入**）通过评审：

- **20 项功能需求、67 条 AC、追溯率 100%**；排除项 **14 条**（原 13 条 + 新增 6b「四仓日志清理/轮转」），无隐式扩项（其中四仓日志由 #6 **移出排除项并纳入本版本**，状态变更已留痕）；
- 功能归属矩阵覆盖全部现有页面，判定口径明确；6 项争议页已裁定；模块开关管理页已纳入；
- **跨仓契约完整**（§11.1：8 项强制契约 + 4 场景失败处理），跨仓改动清单已量化（4 仓 / 7 文件 / +38~+67 行）；**四仓负责人已登记为干系人**；
- **待确认项 13 项全部落定，残留待确认项 = 无**；
- 需求基线可用于 Step 2 设计移交；后续变更须走范围变更流程（提出→分析→更新→评审→批准）并回写候选需求池与 VC 记录；
- **风险提示**：**风险 12（跨仓排期不可控，高/高）为本版本最大单点风险** —— Phase 6 开工前必须完成 6.0 三项前置核实（OpenMemory 启动路径 / OpenRAG 日志栈统一 / 四仓受信口径）。
