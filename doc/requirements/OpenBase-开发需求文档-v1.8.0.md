## 3. 功能需求（用户故事 ＋ 验收标准）

### FR-180-01 模板服务端筛选（RT-180-001/002/003）
> 作为模板管理员，我希望关键字/分类/模板类型筛选由服务端执行，结果不受已加载集合限制。

- 验收：`GET /templates` 支持 `keyword/category_id/template_kind`；keyword 对 name/code 大小写不敏感且通配符转义；非法 `template_kind` → 400；前端 `load()` 传参且无本地过滤。

### FR-180-02 队列聚合统计（RT-180-004/005/006）
> 作为审核管理员，我希望按模板/状态/级数/审核人查看队列计数。

- 验收：`GET /annotations/stats` 支持 4 分组；非法分组 400；`stats` 不被 `{annotation_id}` 吞掉；工作台队列展示状态 KPI。

### FR-180-03 审核人视角（RT-180-007/008）
> 作为审核员，我希望只查看分配给我或未领取的任务，并按级数筛选。

- 验收：`reviewer=me` 解析当前身份（无身份 401）；`level` 0~5；列表返回 `reviewer_id`；前端「只看我的」与级数筛选回写 URL。

### FR-180-04 任务领取（RT-180-009/010/011）
> 作为审核员，我希望领取待审核任务，避免与他人重复处理。

- 验收：领取成功/本人幂等返回不同 `already`；他人已领/非 pending → 409；不存在 → 404；权限动作为 `update`；前端领取后刷新队列与统计。

### FR-180-05 A5/A8/A13 验证闭环（RT-180-012/013）
> 作为项目负责人，我希望确认草稿、模板健康度、模板包预览已有实现并留存证据。

- 验收：源码核对（草稿键/Ctrl+S、health.ts、dry-run 预检）＋既有用例全绿；设计总文档回填。

## 4. 业务流程

```text
模板中心：输入/分类/类型 → load(params) → DPS 服务端过滤 → items
审核收件箱：只看我的/级数 → GET /annotations?reviewer=me&level= →
  行内归属 → 领取 POST /claim → 条件 UPDATE → 刷新队列/KPI → 开始审核
```

## 5. 数据模型与接口

| 接口 | 方法 | 说明 |
|---|---|---|
| `/api/v2/portrait/templates` | GET | 新增 keyword/category_id/template_kind |
| `/api/v2/portrait/annotations/stats` | GET | 4 分组聚合；静态段先注册 |
| `/api/v2/portrait/annotations` | GET | 新增 reviewer/level；行内 reviewer_id |
| `/api/v2/portrait/annotations/{id}/claim` | POST | 幂等领取 |

错误码沿用 DPS `{code,message,data}`；OpenBase 代理统一 `{code,message,data,timestamp}`。无数据库迁移。

| 编号 | 类别 | 指标 |
