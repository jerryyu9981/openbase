## 4. 给 Step 2 的设计约束

| # | 约束 |
|---|------|
| 1 | 前端架构沿用 openbase-ui（Vue3 + Element Plus + ECharts + D3），新页面复用公共组件库 |
| 2 | 请求层统一封装 `/api/v1/proxy/{system}/{path}` 代理基址，SSE 透传支持 |
| 3 | 后端仅涉及代理层增强（RT-328 402 错误码），不新增四系统后端功能 |
| 4 | 页面交互能力 ≥ 独立前端基线（逐页对照） |
| 5 | 破坏性操作二次确认、密钥脱敏、日志不落敏感信息（RT-N303） |
| 6 | 高耦合 P1 4 项（RT-329~332）随对应系统模块设计，复用 P0 组件 |
| 7 | **分层复用（G3 实现方式，决策记录）**：OpenLLM 组件/图表/请求层直接拷贝（技术栈 100% 一致）；OpenRAG/OpenMemory/DPS 交互级参照重写为 Vue；仅改造请求层基址/路由注册/布局壳 |
| 8 | **D3 依赖决策**：openbase-ui 未装 D3，RT-320 图谱在 Step 2 定引入 D3 或 ECharts graph |
| 9 | **基座调试（VC-005）**：基座功能（登录/鉴权/RBAC/动态模块/公共页面）本次必须与 OpenBase 后端调试完整（AC-327-2） |
| 10 | **四系统对接挂起（VC-005）**：OpenMemory/OpenRAG/OpenLLM/DPS 对接调试挂起，前端按契约 mock 先行（AC-327-5），后续按需分批 |
