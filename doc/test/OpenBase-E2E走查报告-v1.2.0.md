## 1. 走查概述

### 1.1 目的

在 Step 4 测试阶段批准后，对 v1.2.0 统一前端执行一次**完整的端到端页面走查**：前后端服务全量运行，逐页验证所有页面功能（含真实表单交互与数据变更），补充自动化巡检未覆盖的交互层验证，发现并闭环交互缺陷。

### 1.2 范围与排除

| 维度 | 说明 |
|------|------|
| 覆盖范围 | 公共页（登录/仪表盘）+ 四模块（OpenLLM/OpenRAG/OpenMemory/DPS）全部路由页面与核心交互功能 |
| 走查页面点 | 22 个（19 个功能页 + 3 个规划占位页） |
| 交互验证 | 表单填写/提交、按钮点击、下拉状态流转、批量删除、标签增删、检索、对话发送、导出下载 |
| 排除范围 | 四系统真实 API 深度联调（依赖代理与后端实例，登记环境遗留清单，见主测试报告 §5）；占位页（17 页 v1.2.0 已规划，深度对接依赖四系统 API） |
| 数据说明 | 模块页面为前端 mock 数据阶段，跨页持久化依赖后端 API 接入（v1.2.0 规划占位页已标注） |

### 1.3 执行方法

1. 确认前后端服务运行状态（后端 :8000 / 前端 :5173 监听正常）。
2. 浏览器自动化：登录态（token 注入 `ob_access_token`）→ 逐页导航 → DOM 快照断言页面渲染 → 执行表单/按钮交互 → 验证数据变更结果。
3. 对发现缺陷：定位源码 → 修复 → 浏览器复测 → 补充 vitest 回归测试 → 全量回归。
4. 走查证据：每页快照（URL/标题/节点/交互元素）+ 交互结果断言记录。
