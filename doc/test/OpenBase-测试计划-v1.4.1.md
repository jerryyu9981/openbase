## 2. 测试策略（T1-T4 四层）

| 层级 | 本版本内容 | 通过标准 |
|:----:|-----------|---------|
| T1 契约层 | API 契约校验（routes/请求响应结构一致性，Schemathesis 按需） | P0/P1 路由契约一致 |
| T2 接口层 | 后端 API 三要素校验（状态码 + 响应结构 + 边界参数） | P0/P1 API 全通过 |
| T3 集成层 | 服务 Key 认证链路（签发→认证→越权拒绝）+ 网关回归 | 无阻塞性问题 |
| T4 验收层 | API 调用序列走查（服务 Key 全生命周期） | 核心业务流通过 |

> 说明：v1.4.1 为纯后端能力补足，无新增前端页面，T3 采用"服务间集成巡检"模式（替代全页面巡检），T4 采用"API/CLI 调用序列"走查模式。

## 3. 测试环境

| 项 | 配置 |
|----|------|
| 后端服务 | FastAPI uvicorn，端口 8000（Dev 实例） |
| 前端服务 | Vite，端口 5173（走查备用，本版本不涉及） |
| 数据库 | SQLite（Dev 内存/文件库） |
| 四系统实例 | 未启动（8001/8010/8020/8030） |
| 测试框架 | pytest + fastapi.testclient |
| 静态检查 | ruff（`ruff check openbase tests`） |
| 覆盖率 | pytest-cov（目标 ≥80%） |

### 环境注意

- 全量 pytest 在本机存在既有崩溃（TD-新增-009），回归按文件隔离执行。
- 服务 Key 为内存存储（P2 债务），测试用唯一名称隔离避免状态污染。

## 6. 准入准出标准

### 准入（进入测试）

1. DevLogReport 已更新（含 TD-141-01~08）
2. code-logic-review 通过，无未解决 P0/P1
3. 开发审计通过
4. ruff 检查 0 错误
5. 自测证据抽查通过

### 准出（进入 Step 5）

1. 测试矩阵全部执行，P0/P1 问题全部关闭
2. 全量回归通过率 ≥95%（目标 100%）
3. 修改文件覆盖率 ≥80%
4. UAT 通过或有明确人工审批结论
5. 测试报告、测试用例、测试回溯对比审计报告、阶段审计报告齐备
6. 测试回溯审计允许进入 Step 5
