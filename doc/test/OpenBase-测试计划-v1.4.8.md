## 5. T1-T4 四层架构适配

| 层级 | 本项目适配 | 说明 |
|:----:|-----------|------|
| T1 契约层 | 编排请求契约（`OpenLLMChatRequest.session_id` 可选）+ 两个新增查询端点 + conversations 端点 `session_id` 参数；前端 `llm.ts` 请求体字段 | 本项目**无 OpenAPI 快照自动 diff** 条件时，以「前端调用字段 ↔ 后端请求模型字段」的**双向核对表**替代 |
| T2 接口层 | 三要素校验（状态码 + 响应结构 + 边界参数）：`/chat`、`/chat/stream`、`/trace/metrics/export`、`/writeback/receipts`、`/monitoring/traces/{id}`、conversations 系列 | 含鉴权与错误码 |
| T3 页面/集成 | **双模**：T3a 前端全页面巡检（全栈部分，强制）+ T3a 服务间集成巡检（跨仓后端链路，强制）；T3b 深度用例（会话编排链路的 CRUD 类比：触发→观测→查询） | 前端 E2E 用例位于 `openbase-ui/tests/e2e/` |
| T4 验收层 | API/CLI 调用序列走查（无独立 UI 业务流）：发消息→观测回执→查 trace→重启→再发消息→核对无丢写 | 见 §8 |

**层间追溯要求**：T1 定义的每个契约点须在 T2 有 API 用例、在 T3 有巡检/集成覆盖、在 T4 有走查项（P0/P1 100%）。

## 8. T4 验收走查清单（API 调用序列，纯后端模式）

| 序号 | 业务流 | 步骤（API 调用序列） | 预期结果 | 通过 |
|:----:|--------|----------------------|----------|:----:|
| 1 | 会话轴 + 三路回写闭环 | `POST /openllm/v1/chat`（带 `session_id`，pipeline 含 memory/rag/llm）→ `GET /openllm/v1/writeback/receipts?session_id=...` | LLM 有响应；三路回写受理状态可见（accepted/duplicated）；`routing_trace` 含计量回执 | ⬜ |
| 2 | 流式路径等价 | `POST /openllm/v1/chat/stream`（同一输入）→ 对照用例 1 的注入片段集合 | 历史/记忆/知识库/画像四类素材注入集合与同步路径一致 | ⬜ |
| 3 | **重启不丢写（硬判据）** | 发 N 次带回写的消息 → 重启服务 → 再发 1 次 → `GET /openllm/v1/writeback/receipts` 与 `writeback.db` 行数核对 | **重启后回写丢失数 = 0**，序号续接历史最大值 | ⬜ |
| 4 | 会话标识与落库对齐 | `POST /api/.../conversations/{id}/messages?session_id=...` → `GET .../messages?session_id=...` | 消息元数据含 `session_id` 与记账口径；按会话筛选命中 | ⬜ |
| 5 | 计量导出 | `GET /openllm/v1/trace/metrics/export?session_id=...` | 返回回执行（含 token 分项、WCR 相关字段），不含片段/回答正文 | ⬜ |
| 6 | 前端会话标识 | 前端发消息（`npm run dev`）→ 后端日志/trace 核对请求体 | 请求体含 `session_id`，同标签页多轮复用同一标识 | ⬜ |

## 11. 通过标准（Step 4 退出条件）

1. 测试矩阵 14 类全部执行，或「不适用」有明确原因、影响与补救说明。

3. 改动文件行覆盖率 ≥ 80% 或有逐文件不适用说明。
4. **重启不丢写 = 0** 与 **两路径一致性** 两项硬判据有可复现证据。
5. UAT 走查清单全部通过或有明确审批结论。
6. 产出物存在性验证通过（LS/Glob 逐项核对，记录在审计文档）。
7. 测试回溯审计允许进入 Step 5。
