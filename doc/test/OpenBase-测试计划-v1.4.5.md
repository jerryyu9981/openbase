## 3. 测试矩阵（计划）

| 测试类别 | T 层 | 用例数 | 方式 | 通过标准 |
|----------|:---:|:---:|------|----------|
| API 测试（dps-proxy） | T1+T2 | 15（pytest）+ 8 端点三要素 | pytest + 真实链路 | P0/P1 全通过，无非预期 5xx |
| 集成测试（双系统链路） | T2 | 4 | 真实链路（登录→画像→详情→502 归一化） | 关键链路有效执行 |
| T3a 全页面巡检 | T3a | 3 页（画像列表/详情/仪表盘） | 浏览器巡检 | 无代码类 HTTP≥500 / requestfailed / console error |

| 回归测试（后端全量） | - | 全量 | `python -m pytest tests` | ≥95% 通过，P0/P1 闭环 |
| 覆盖率（dps_proxy 模块） | - | - | `pytest --cov=openbase` | 新代码 ≥80% |

## 4. 执行顺序

```
环境验证 → 自测证据抽查 → API 测试（4.3a）→ 集成测试（4.4a）→ T3a 巡检（4.3b'）
→ E2E（4.5）→ 全量回归 + 覆盖率（4.6）→ 安全快检（4.7）→ UAT（4.8）
→ 缺陷闭环（4.9）→ 报告（4.10）→ 测试回溯审计（4.11）
```

## 5. 已知限制与跳过项（测试前声明）

| 跳过项 | 原因 | 影响 | 补救 |
|--------|------|------|------|
| DPS 真实业务数据联调（画像真实返回） | DPS 侧 config.settings 缺陷（M4，第三方）启动受阻 | dps-proxy 转发真实数据无法验证 | 验证 502 归一化符合契约（H 类）；M4 修复后 Step 5 补测 |
| 画像计算/批量任务真实执行 | 依赖 DPS 服务 + AI 模型服务（OQ-145-2） | 计算链路降级 | 单测 mock 覆盖 + M4/M2 修复后补测 |
| 组织/租户映射实际值 | 联调确认（OQ-145-1） | 四头注入实际值待确认 | 映射逻辑单测覆盖（default/映射/直传），Step 5 联调确认 |
