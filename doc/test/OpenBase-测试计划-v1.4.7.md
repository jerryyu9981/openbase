### 2.2 判据口径（人工裁定，2026-09-19，**必须先读**）

> 目标 3 的「100% 合法 JSON」**适用面限定为四仓输出的应用日志行**（行首 `{`）；`uvicorn.access` 等**框架/服务器进程自身的输出行不纳入该判据**（该类行由日志适配器「纯文本回退」解析，能力受限已在《覆盖状态说明》§5 显式声明）。目标 1 的串联比对**同样以应用日志行为对象**（应用日志行必须携带 `request_id`；框架访问行天然无此字段，不参与比对）。
>
> 裁定记录：《OpenBase-DevLogReport-v1.4.7》§5.1。被否选项（四仓统一 uvicorn JSON formatter / 关闭 access log）登记为后续版本候选（《OpenBase-候选需求池》§1.15）。

### 2.4 取证口径补充：HTTP 错误响应体（PS 5.1，**必须先读**）

> **背景（DEF-BE-147-005 假阳性事故，2026-09-20 复盘）**：Windows PowerShell 5.1 下 `Invoke-WebRequest` 在非 2xx 时抛异常，此时读取 `$_.Exception.Response.GetResponseStream()` 得到 **0 字节**；而**同一响应体早已被 PS 内部消费并缓存在 `$_.ErrorDetails.Message`**。据此得出的「400 响应体为空」曾被写入定位证据（并据此派生「可排障性缺陷」判断），后经四口径交叉验证判定为**测量假阳性**——服务端声明 `content-length: 381`，线上实发 381 字节完整 envelope。

| # | 取证口径 | 可靠性 | 说明 |
|:-:|---------|:------:|------|
| 1 | 原始 socket 抓取（status line + 原始头 + 原始体字节） | **最高** | 线上字节级事实源；「是否空体」存在争议时以本口径为准 |
| 2 | .NET `HttpClient`（`UseProxy=$false`、`AllowAutoRedirect=$false`） | 高 | 独立 HTTP 栈，非 2xx 同样返回全部字节 |
| 3 | `$_.ErrorDetails.Message` | 高 | PS 原生惯用错误体口径，与线上字节一致性已实测 |
| 4 | `$_.Exception.Response.GetResponseStream()` | **禁止单独采信** | 读错误体恒为 0 字节（流已被 PS 内部消费），**不得**据此判定「响应体为空」 |

**强制规则**：

1. 判定「响应体为空/丢失」类缺陷，**至少需两条口径（其中一条为原始 socket）结论一致**方可成立。
2. 统一使用取证件 `scripts/probe_http_response.ps1`（`-Raw`=原始 socket；`-ViaInvokeWebRequest`=PS 原生对照，内建 PS 陷阱自检告警）；含中文的 `.ps1` 必须保存为 **UTF-8 BOM**（PS 5 解析要求，见 CR-147-003）。
3. 「服务端丢失响应体」与「客户端读不到响应体」必须分别举证，不得混同归因。
4. 该类判据的取证结论须同时记录**四口径取值**（或注明未采口径及原因），保证可复核。

## 5. 通过标准

| # | 标准 | 阈值 |
|:-:|------|------|
| 1 | 串联一致性抽样 | ≥20 次，**100%** 命中且取值一致 |
| 2 | 四仓可检索 | 四仓各 ≥1 命中（合计 ≥4） |
| 3 | 应用日志行 JSON 合法率 | **100%**（抽样行；框架自身输出行不纳入，见 §2.2） |
| 4 | 本仓回归 | 无**新增**失败（环境性失败须逐项归因） |
| 5 | 四仓专项回归 | 复跑通过 |
| 6 | 证据完整性 | 环境/抽样/比对/检索证据齐备并可复算 |

**不通过判定**：任一 P0 判据未达 → 记录缺陷 → 回退 Step 3 修复 → 更新 DevLogReport → 重跑相关用例（必要时全量）。
