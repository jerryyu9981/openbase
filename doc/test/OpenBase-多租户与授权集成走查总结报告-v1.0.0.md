## 1. 概述与范围

本次走查覆盖「多租户与授权集成」（MTAUTH）的两条主线，跨越 **5 个系统 / 4 个下游仓**（OpenBase 本仓 + OpenLLM / OpenRAG / OpenMemory / DPS）：

| 主线 | 范围 | 基线口径 |
|------|------|---------|
| **① 权限管理与多租户授权** | 四角色（admin / org_admin / org_member / viewer）× 关键端点准入判定；错误码规范性；JWT 租户声明；身份头受信判定；前端页面级守卫与菜单同源 | `config/role_tier_anchors.json`（五码标准角色集）；架构/UI 设计文档 v1.4.2 |
| **② 跨仓数据面租户隔离** | 下游四仓数据面：① 只返回该租户数据；② 拒绝未授权/未登记租户；③ 不因缺失租户标识而放行全量 | 《联调窗口真实面执行单》；`docs` 隔离口径「空或 403、无 500」 |

**不在本次范围**：各下游仓自身业务功能走查；不在授权链路内的性能/容量专项。

## 2. 走查方法与口径

- **后端矩阵**：四身份登录 → 对关键端点逐一只读探测，记录 HTTP 状态与业务错误码；补充角色分配枚举、JWT 声明解码、身份头受信判定、负控（无令牌 / 篡改令牌）。
- **跨仓闸门矩阵**：下游三系统直连「身份闸门四态矩阵」（无身份头 / 非受信来源+身份头 / 受信来源+保留码 / 受信来源+未登记租户[+已登记租户]）。
- **前端逐页**：四身份分别登录 → 遍历全部业务路由，记录 `/forbidden` 拦截、渲染态、控制台报错、4xx/5xx 失败请求。
- **真实面执行**：原子窗口探针（同命令内「起→探→停」）验证 OIDC/Redis 吊销面、委托跨界、agent key 面、fail-closed 故障注入与冒烟 S0–S6。
- **纪律**：TDD（先 RED 后 GREEN）；最小侵入；不翻转既有默认（需翻转者改等价开关并登记「需裁定」）；每仓留痕 + 本地提交 + 推送三远程并核验 HEAD 一致。
