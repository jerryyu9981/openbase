## 1. 口径纠错声明（v1.1.0，2026-09-20）

> 原 v1.0.0 §1 表中「400 响应体：**空（0 字节）**」系 Windows PowerShell 5.1 取证件缺陷所致：`Invoke-WebRequest` 在非 2xx 时抛异常，此时读 `$_.Exception.Response.GetResponseStream()` **恒为 0 字节**（响应体已被 PS 内部消费并缓存于 `$_.ErrorDetails.Message`）。
>
> 按《OpenBase-测试计划-v1.4.7》§2.4「取证口径补充」的强制规则（判定「响应体为空/丢失」须≥2 条口径且其中一条为**原始 socket**；`GetResponseStream()` **禁止单独采信**），本轮以原始 socket + httpx 双口径复核，**推翻该结论**并作下述纠正。纠正全程留痕：

| # | 原记录（v1.0.0，已纠正） | 复核结论（v1.1.0） | 复核口径 |
|:-:|------------------------|-------------------|---------|
| 1 | 经网关 `GET /api/v1/rag-proxy/collections` → 400，响应体「空（0 字节）」 | 上游 400 实发 **385 字节完整 envelope**（`code=BIZ_RESERVED_TENANT_CODE_COLLISION` + `detail` + `request_id` + `trace_id`）；网关侧 4xx 响应体亦非空（实测 190 字节 envelope，见 `def005-gateway-retest-20260920.json`） | 原始 socket（最高）+ httpx（独立 HTTP 栈） |
| 2 | 派生次级发现「拒绝响应无 body → 可排障性缺陷」 | **撤回**：拒绝响应携带完整错误 envelope，且 `detail` 已给出 `tenant_code` 与 `reserved_codes`，可排障性成立 | 同上 |

> 保留但不作为缺陷的部分：OpenRAG `request_completed` 应用日志行仅记状态码、未记拒绝原因，**日志可观测性**仍有改进空间（已随之登记为跨仓建议，见 §5）。

## 2. 多口径复核结果（2026-09-20 13:06）

请求：`GET http://127.0.0.1:8010/api/v1/collections`（直连 OpenRAG），基线头 `X-API-Key` + `X-Proxy-Source: openbase-rag-proxy` + `X-Request-Id`。

| 用例 | 附加身份头 | 状态 | `content-length` | 原始 socket 体字节 | httpx 体字节 | 响应体摘要 |
|------|-----------|:----:|:----------------:|:-----------------:|:-----------:|-----------|
| B0 基线（仅来源 + 请求 id） | — | **200** | 5386 | 5386 | 5386 | `code=0`，`items` 12 条（租户 `default` 数据可见） |
| R1 重现（保留租户码） | 四头 + `X-Tenant-ID: default` | **400** | 385 | **385** | **385** | `code=BIZ_RESERVED_TENANT_CODE_COLLISION`；`detail.reserved_codes=[default, openrag-local]`；`request_id` 回显网关值 |
| A1 方案 A（非保留码） | 四头 + `X-Tenant-ID: openbase` | 200 | 228 | 228 | 228 | `code=0`，但 **`data.items=[]`、`total=0`**（租户隔离生效 → 既有知识库不可见） |
| A2 方案 A'（非保留码） | 四头 + `X-Tenant-ID: openbase-demo` | 200 | 228 | 228 | 228 | 同 A1（空数据） |
| B1 方案 B（不注入身份头） | — | **200** | 5386 | 5386 | 5386 | `code=0`，`items` 12 条数据完整可见 |

**判读**：

1. **R1 证明根因成立**：受信来源（M2）下只要带任一身份头即 400 —— 因缺省 `X-Tenant-ID` 即被填为保留码 `default`；
2. **方案 A 不可行（新证据）**：改为非保留租户码后状态码恢复 200，但租户隔离使**既有知识库不可见**（`items=[]`）→ 只是把「400 报错」换成「200 空数据」，联调演示与检索功能实质退化；
3. **方案 B 同时满足功能与串联**：不注入身份头时 OpenRAG 走「受信来源 + 自身 API Key」路径（本地 `default` 域），数据完整可见，且 `request_id` 仍复用网关出站值。

## 3. 根因（源码定位，结论不变）

OpenRAG `src/openrag/api/middleware/identity_gate.py` `_handle_trusted_identity()`（L224–239）：

```python
values = validation["values"]
tenant_code = values.get(HEADER_TENANT_ID) or LOCAL_DEFAULT_TENANT_CODE   # ← 缺省即 "default"
if is_reserved_tenant_code(tenant_code):                                   # B2 碰撞防护
    return self._reject(code=BIZ_RESERVED_TENANT_CODE_COLLISION, ..., status_code=400)
```

- M2（受信）路径下，未显式给出 `X-Tenant-ID` 时**缺省取 `LOCAL_DEFAULT_TENANT_CODE` = `default`**；
- `default` 与 `openrag-local` 是 OpenRAG 的**本地保留租户码**（禁止出现在受信入站，防采集侧伪装本地租户）；
- 本仓网关 `build_outbound_headers` 注入的 `X-Tenant-ID` 取自统一主体 `tenant_code`，联调主体为 `default` → 命中该防护 → 400。

## 4. 处置裁定与落地（2026-09-20）

| 方案 | 做法 | 实测结果 | 采纳 |
|:----:|------|---------|:----:|
| A | rag-proxy 使用**非保留真实租户码** | 200 但 `items=[]`（隔离致数据不可见）；且牵动全局租户码语义与四仓一致性 | ✗ 不采纳（本轮） |
| **B** | **rag-proxy 对 OpenRAG 不注入身份头**（仅 `X-API-Key` + `X-Proxy-Source` + `X-Request-Id`） | **200 且数据完整（items 12）**，串联 `request_id` 一致 | **✓ 采纳** |
| C | OpenRAG 侧为联调放行/映射保留码 | 削弱其保留码防护语义；需跨仓评审，本仓沙箱无该仓写权限 | ✗ 不采纳（登记为跨仓议题） |

**落地实现（本仓单点，未改他仓代码）**：

| 变更 | 位置 | 说明 |
|------|------|------|
| 新增显式开关 | `openbase/settings.py` → `rag_inject_identity_headers: bool = True` | 默认 True 保持既有四维身份透传语义；关闭即「不注入身份头」 |
| 策略消费 | `openbase/modules/rag_proxy/__init__.py::_build_upstream_headers` | 关闭时以 `user_ctx=None` 走**同一装配点**产出 `X-Proxy-Source` + `X-Request-Id`（不另起旁路，避免口径分叉） |
| 联调口径声明 | `scripts/service-orchestrator.ps1`（openbase `Env`） | `OPENBASE_RAG_INJECT_IDENTITY_HEADERS = 'false'`（**显式声明，非静默降级**） |
| 护栏用例 | `tests/test_bl147_trust_env_wiring.py`（+1 例）、`tests/test_rag_proxy_identity_policy.py`（新增 3 例） | 防口径被无意改回；覆盖「默认注入 / 关闭不注入 / 关闭仍携带 request_id」 |

## 5. 后续议题登记

| # | 议题 | 归属 | 建议 |
|:-:|------|------|------|
| 1 | **租户码语义对齐**：OpenBase 联调租户码 `default` 与 OpenRAG 本地保留码同名，导致「受信入站必 400 / 非保留码则数据不可见」二难 | 跨仓 + 设计层 | 由设计确认「跨域租户码是否需映射/前缀化」（如 `ob-<code>`）后，再决定是否把 rag-proxy 恢复为注入模式（开关置 true 即可，护栏用例同步提醒） |
| 2 | OpenRAG 拒绝路径日志可观测性：`request_completed` 仅记 `status_code`，未记拒绝原因（`identity_rejected` 类审计日志缺失） | OpenRAG 仓 | 建议其 `_reject` 补结构化拒绝日志（本轮**不再**作为「响应体为空」缺陷登记） |
