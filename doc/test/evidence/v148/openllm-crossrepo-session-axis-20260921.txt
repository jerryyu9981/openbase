==================== 三、实现要点 ====================

1) 请求契约（AC-148-04-2）
   OpenLLMChatRequest 新增 `session_id: str | None = Field(None, ...)`（可选，缺省 None）。
   缺省时不改变既有调用方行为；显式传入时原样保留。

2) 会话轴历史素材（AD-02 / AD-03）
   - 新增 history.build_history_ctx(messages, max_tokens, count_tokens)：
     排除当前 query（最后一条 user 消息）→ 取此前全部轮次 → 按「role: content」逐行渲染；
     超预算时**丢最旧保最近**；无历史返回 None。
   - 网关新增 _history_budget_tokens / _build_history_for_request：
     预算 = (模型窗口 − 输出预留) × 安全余量（0.2）；模型窗口取 F-02 修正后的
     resolve_model_context_key（日期化模型名可正确取窗）；计数器用 ContextManager.count_tokens。
   - _normalize_request 返回值由 4 元组扩为 5 元组（新增 history_ctx），三条返回路径
     （openai / explicit / auto）均已同步；两处调用点同步解包。

3) 组装器历史槽位（AC-148-04-4）
   PromptAssembler.DEFAULT_TEMPLATE 新增 `[会话历史]` 段，位置固定为
   System + 画像 + 记忆 + 知识库 + **[历史]** + Query；render 新增 history_ctx 入参；
   历史为空时不注入，输出与 v1.4.7 完全一致（用例 test_empty_history_not_injected 断言）。

4) 回写会话标识（AC-148-06-1）
   _build_writeback_callback(identity, request_id, session_id=None)：
   base_kwargs["session_id"] = session_id or identity.user_id；编排侧调用点传入
   `chat_req.session_id` → 传入真实会话标识时不再以 user_id 顶替；缺省仍退化为按用户记账。

==================== 五、环境缺陷修复（tests/unit/conftest.py） ====================

现象：所有经网关 / 编排链路导入的单测在**收集期**报
      ImportError: DLL load failed while importing _rust（cryptography 原生扩展）
根因：conftest 将 pgAdmin site-packages 与 backend/.pylib 以 insert(0)/insert(1) 置于
      sys.path **首位/次位**，二者自带与本机解释器 ABI 不匹配的 cryptography，
      遮蔽了虚拟环境中可用且正常的 cryptography / jwt / sqlalchemy。
证据：python -B -c "import jwt, cryptography, sqlalchemy" → 三者在虚拟环境均正常导入；
      tests/unit/test_openllm_gateway.py 修复前 28 errors（全部 DLL 失败）。
处置：两处均改为 `sys.path.append(...)`（末位兜底）：保留「本机缺包时补缺」能力，
      不再遮蔽可用实现。
效果：test_openllm_gateway.py 由 **28 errors（收集期 DLL 失败）** → 仅剩
      `fixture 'client' not found`（因 `--confcutdir=tests/unit` 未加载父级 conftest）
      → 本次会话轴 20 例与回写/F-02 共 39 例可**真实运行并全部通过**。
范围声明：仅改 tests/unit/conftest.py；**未**改 tests/conftest.py（其 .pylib 本就为末位，
      仅 pgAdmin 为首位注入；改动会影响全仓导入解析，风险超出本次范围，遗留待评估）。
