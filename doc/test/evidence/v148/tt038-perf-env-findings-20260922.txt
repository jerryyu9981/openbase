> 供《OpenBase-性能测试记录-v1.4.8》§3 / §4 / §6 引用。命令均在 `OpenLLM/backend` 下执行。

## 2. C-1：网关全局限流（并发 8 档位不可达成）

并发 8 突发 250 次 `GET /openllm/v1/writeback/receipts`：

```
status 分布: {200: 67, 429: 183}
首个非 200: (index=64, 429, 600.4ms,
             '{"code":1003,"message":"请求过于频繁，请稍后再试","error":"rate_limit_exceeded","retry_after":1}')
200 的时延: n=67 min=78ms max=1697ms
```

限流实现（源码实证）：`app/middleware/rate_limit.py` 每请求重读环境变量
（`RATE_LIMIT_PER_SECOND` 默认 `1.0`、`RATE_LIMIT_BURST` 默认 `60`；另有 user 20/s burst 200、
route 50/s burst 100）→ **全局桶 1 req/s 是实际约束**；环境变量属**进程内**读取，
**运行中不可从外部修改**，故本轮以客户端节流 `--rate 0.75` 执行。

## 3. C-2：语义缓存干扰（已规避）

同一 prompt 连续两次 `/openllm/v1/chat`：

```
[2nd] status=200 wall=123.6ms  timeline=[]            # 命中缓存：直接返回、无步骤计时
```

源码实证：`openllm_gateway.py:1900-1918` 命中时 `_save_trace(..., pipeline_names, [], cache_trace)`
（timeline 传空数组）且 `routing_trace.cache_hit=True`；缓存键为 `(user_id, query)`，阈值 `0.92`
（`app/core/semantic_cache.py:33`）。**规避方式**：每次采样在 query 注入唯一 nonce；
加 nonce 后实测 `cache_hit=None` 且 `timeline=[{'step':'auth','ms':0},{'step':'llm','ms':891}]`。

## 4. C-3：DPS 不可用 → 同步对话未计量差额

```
同步 /chat 单样本：墙钟 3308.0ms = llm 步骤 766ms + （墙钟 − Σ步骤）2542.0ms
步骤集合 = ['auth', 'llm']          # 画像拉取 / 回写派发 未进入 timeline
```
与 `dps` 健康探针 `latency_ms=2046`（连接等待）量级一致 → 该差额**主体为 DPS 连接等待**，
因其未进 timeline，**本仓开销与外部等待无法逐样本分离**（记录为口径缺口）。

## 5. C-4：成本优先路由选中不可用模型（错误率根因）

流式失败样本的 `routing` 事件（原始）：

```
... "rag_source": "skipped"}, "model": {"selected": "qwen3:0.6b", "reason": "cost"}, "parallel": false}
event: error
data: {"code": 5001, "message": "内部错误，请稍后再试"}
```

定点探测（同一实例、同一账号）：

```
[model=qwen3:0.6b]        status=500 wall=4713ms code={'code':5001,'message':'LLM 组件调用失败'}
[model=deepseek-v4-flash] status=200 wall=3237ms code={'code':0,'message':'success'}
```

→ **`qwen3:0.6b` 在本环境不可用，但仍在候选池并被「成本优先」选中**；同步对话与流式均因此
出现偶发失败（同步 8/60 = 13.3%；流式 2/30 = 6.7%）。与既有 **P3「偶发 500（未复现）」**
疑同源，本轮提供了可复现判定路径。
