==================== 三、实现要点 ====================

1) 工装 5 归因 B 工具（`attribution_b.py`）
   - `JUDGE_PROMPT_VERSION = "ab-judge-v1"`：**固定判定 prompt 版本**（同输入同种子下 prompt 逐字一致，
     用例断言）；模型名由调用方固定注入并回填结果（`judge_model`）；
   - `anonymize_fragments`：手机号 / ≥12 位长数字 / UUID / 邮箱 → 占位符（**去标识**）；
   - `shuffle_with_mapping`：按种子打乱并返回**还原映射**；`judge_fragments` 判定后
     **还原为原始片段顺序**（用例断言）；
   - `parse_judge_output`：仅接受 `used` / `unused` / `uncertain`，非法或缺失一律降级 `uncertain`；
   - `sample_records`：每轮 ≥30 条（不足则全取，样本量不足由工装 7 记为「不可判定」）；
   - `calibrate_miss_rate`：以 B 校准 A 的漏检率（保守口径，uncertain 不计入分子）；
   - **不含任何裁剪 / 改写对话输出逻辑**，不落存片段与回答正文。

2) 工装 6 固定集与评分表（`golden_set.py` + `data/golden_set_v1.json`）
   - 7 场景矩阵：S1 多轮指代 / S2 记忆召回 / S3 知识库检索 / S4 画像适配 /
     S5 跨源综合 / **S6 纯闲聊（负例）** / **S7 无历史单轮（负例）**；
   - 固定集实测 35 条、每场景 5 条、负例 10 条（2 组负例场景）；
   - `validate_golden_set` 校验规模与结构（场景缺失 / 条目不足 / 负例不足均给出 issues）；
   - 四维 1~5 分量表 + 记录模板（评分人 / 日期 / 模型版本 / 问题集版本 / `temperature=0`
     / 复评比例 20% 与间隔 24h）。

3) 工装 7 汇总脚本（`baseline_report.py`）
   - `summarize_baseline`：记录点位 / 方法 / 样本量 / **WCR 三分比例（含 sum）** /
     **漏检率区间** / `judgeable` 与 `notes`；
   - `render_baseline_report`：输出 Markdown 骨架，含要素「方法 / 样本量 / 漏检率 /
     硬浪费 / 软占用 / 必要占用 / 判定三要素（A 引用检测、B LLM 归因、C 消融）」；
   - 样本不足（<30）或 WCR 口径缺失 → 显式记「**不可判定**」，不得以缺失数据充当结论。

4) 与派单契约的对应
   | 契约项 | 落点 | 用例 |
   |--------|------|:----:|
   | 每轮抽样 ≥30 条 | `sample_records` | ✅ |
   | 固定判定 prompt / 版本 | `JUDGE_PROMPT_VERSION` + 稳定性断言 | ✅ |
   | 片段去标识 + 打乱可还原 | `anonymize_fragments` / `shuffle_with_mapping` / 还原断言 | ✅ |
   | used / unused / uncertain | `parse_judge_output`（非法降级） | ✅ |
   | 7 场景 ≥5 条共 ≥35 含 2 负例 | 固定集数据 + `validate_golden_set` | ✅ |
   | 四维 1~5 分量表 + 记录模板 | `SCORE_DIMENSIONS` / `build_score_record_template` | ✅ |
   | 报告含方法/样本量/漏检率区间/WCR 三分/判定三要素 | `render_baseline_report` | ✅ |
