==================== 三、实现要点 ====================

1) 共用组装步骤（TD-148-03 核心）
   build_prompt(query, system_prompt, memory_ctx, rag_ctx, profile_ctx, history_ctx,
                count_tokens=None, assembler=None) -> (prompt, PromptComposition)
   - 同步路径：PipelineExecutor.execute → build_prompt(..., assembler=self.assembler)
   - 流式路径：网关流式端点 → build_prompt(...)（**删除**原 PromptAssembler().render 自建副本）
   → 两条路径现在使用**同一个实现**组装 Prompt（F-01 的组装分叉已消除）

2) 第零段计量（工装 1：Prompt 组成计量；工装 2 的检索快照未含）
   PromptComposition:
     - prompt_total_tokens            最终 Prompt 总 token
     - segment_tokens                 六段分项（system/profile/memory/rag/history/query）
     - contexts_tokens                分母口径 = 四类素材之和（不含 query 与输出预留）
     - counted                        是否已计量（未传计数器为 False）
   设计取舍：计数器由调用方注入（缺省不计量），避免在本模块内耦合 tiktoken；
   网关侧已有 _history_budget_tokens 的取窗与 ContextManager.count_tokens 能力，
   在下一批「回执落库」时统一注入并写入 routing_trace。

3) 只观测硬约束的**可验证化**
   共用步骤用例直接断言「输出与既有组装器逐字一致」与「超长素材原样保留」，
   使「第零段不得含裁剪/改写/截断」从人工审查项变为**回归可证**项。

4) 双路径护栏（防复发）
   源码级 AST 护栏三项：两路径均调用 build_prompt；素材参数齐备；网关内无直接 render 调用。
