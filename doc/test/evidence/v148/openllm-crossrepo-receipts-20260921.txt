==================== 三、实现要点 ====================

1) 同步路径逐路回执（AC-148-05-2）
   - 执行器新增 `ExecuteResult.writeback_receipt`，由异步回写任务在完成时填充：
     True→accepted / False→duplicated / 其他→submitted / 最终失败→failed(+reason)；
   - 三路（memory / rag / profile）**统一经 `_schedule_writeback`** 调度
     （原 rag 走内联任务，现与 memory/profile 同入口，保证回执一致采集）；
   - 编排助手 `_run_orchestrated_chat` 把回执带回网关，同步路径写入
     `routing_trace["writeback"]`。

2) 回执查询接口（AC-148-05-2「可查」）
   - `WritebackStore.list_rows(session_id=, request_id=, target=, limit=)`：
     **参数化**查询队列表（status + seq + retry_count + 时间），不返回 payload 正文；
   - 端点 `GET /openllm/v1/writeback/receipts`：按会话 / 请求 / 通道查询，
     三路均在同一队列留痕 → 回执覆盖率对三路成立；队列不可用时返回
     `{"items": [], "total": 0, "note": "writeback_queue_unavailable"}`（降级不报错）。

3) 权威状态口径（重要）
   - **权威来源**＝回写队列表（`writeback_queue.status/seq`），经查询接口读取；
   - `routing_trace["writeback"]` 为**尽力而为**快照：同步路径的填充依赖异步任务完成时机，
     流式路径为逐路实时记录。二者互补，判定以队列表为准。

4) 过程偏差（如实登记）
   本批中途一次编辑误删 `max_seq` 的 docstring 首行，在下一处编辑前发现并立即修正
   （未进入测试环节；py_compile 与用例均通过）。
