## 7. 发现与建议

| # | 发现 | 级别 | 建议 |
|:-:|------|:----:|------|
| 1 | 需求 §5.3 "三源只读"与导出留痕写入存在表述张力 | **已闭环** | 需求文档 v1.1.0 已精确表述为"只读，唯一例外是导出留痕"（§5.3 规则 1）；设计侧 ADR-146-04 + API §3.3 补"留痕失败不阻断导出"降级语义 |
| 2 | `total` 在 `truncated=true` 时语义易被误读为"全量命中数" | 提示 | 已在 API §3.1/§6 明确 `total` 为"扫描上限内命中数"并要求与 `truncated` 同读；建议 Step 3 在代码注释与前端提示文案中保持一致表述 |
| 3 | 测试记录的 `result`（`PASS/FAIL/BLOCKED/SKIPPED`）映射到三源统一 `result` 枚举时存在语义损耗（`BLOCKED`/`SKIPPED` 归入 `client_error` 略显粗糙） | 提示（口径） | 已在 API §4.3 显式标注"按记录语义映射（可人工复核）"；建议 Step 4 以抽样人工核对（AC-146-02-2）确认可接受，必要时在后续版本细化枚举 |
| 4 | `log:read` 为数据（授权）变更，若遗漏授权步骤将导致"功能上线但无人可见" | 提示（可操作） | 已在部署 §4 给出幂等落地方式与三态验证（401/403/200），并纳入发布后验证清单第 ② 项 |
| 5 | 深分页（如 `page=50`）在 L1 源会放大扫描成本 | 低 | 已用 `page_size ≤100` + 扫描上限双限幅约束；如需深分页优化，列入后续索引化需求 |
| **6** | **路径级归属矩阵尚未生成**（UI §9.4 标注"待补全"）；重定向映射表为**设计基线**而非脚本产物 | 提示（已给方法） | 已在 UI §9.1 定义**脚本化生成法**（禁止人工转写）并要求 Step 3 施工前生成全量四列并替换基线表；**不构成设计缺口**（方法已定、载体已定） |
| **7** | `gateway` 模块**注册身份处置**与模块注册表**持久化形态**两项决策未定 | 提示（已登记） | 已列为 3 项决策点（系统架构 §2.2、前端架构 §3.4）；**Step 3 施工前必须确认**（否则模块开关页范围与 `repo_log`/导航归位实现会漂移） |
| **8** | 跨仓契约的**实际符合性无法在本仓验证** | 中（边界） | 属审计边界（见 §8 新增边界声明）；须在 Phase 6 以各仓评审记录 + 端到端串联证据（AC-146-16-1/20-1）验证 |
| **9** | `module.switch` 留痕失败的处置口径未定（"变更失败并回滚" vs "降级告警"） | 中 | 已在 API §3.4「幂等」与部署 §6「回滚风险」中标注**Step 3 定案**；建议采用与导出留痕对称的"**变更失败并回滚**"（避免"状态已改但无留痕"） |

**无 P0/P1 级设计缺口。**

## 8. 审计结论

**✅ 通过** —— v1.4.6 需求架构对比审计通过（**含 VC-013 + VC-014 回溯重出轮**）：

- **RT → 设计覆盖 100%（20/20）**；DT → AC 覆盖 100%（**67/67**）；三项覆盖检查（**后端 5/5、前端 7/7 步 2 页、契约 8/8**）复算与设计评审记录一致；
- **14 条排除项均未被隐性纳入**（**#6「四仓日志」为显式留痕的"移出并纳入"状态变更**，非隐性扩项）；**7 项"不适用"理由正当**；
- Step 1 移交要点 **11/11 + 4/4 待确定项 + §3.4 四仓日志接入线 9 项**均已闭环；**10 项风险**均有设计应对（含 2 项高/高：风险 7 模块瘦身、风险 12 跨仓排期）；
- **新增设计缺口 0**：`repo_log` 适配器 / 模块写路径 / 重定向映射表 / 路径级归属矩阵四项均有明确设计载体（DT-146-12~16）；
- 审计意见：**允许进入 Step 3 开发**（可实现性由物理设计完备性支撑：模块文件清单、端点契约、**svc↔module 映射表**、重定向映射表、配置项、测试预映射齐备）。

**审计边界（本轮新增）**：本结论**不覆盖**四仓施工（属各仓自身流程）；跨仓契约的**实际符合性**须在 Phase 6 由各仓评审记录与端到端串联证据验证（AC-146-16-1/20-1）。
